# KALEIDO · 11 Diegetic UI 教义(2026-07-22 · Kanata 拍板 · 长期铁律)

> **UI 不是元层的界面,是世界内的物件与能力。** 它可以被发现、被获得、被夺走。玩家探索的对象不只是地图,还有**系统本身**。
> 本文件 = 长期设计铁律,**所有未来机制都按此设计**。取代旧「渐进披露 = 系统主动解锁并教学」的范式(05 的 ui_unlocks 是其实现基座,语义按本文件重划)。

## 1. 三条法则

### 法则一 · 功能常在,观测要争取
**机制永远在运行,与玩家是否看见无关。** UI 只是观测窗口,不是功能开关。
- 体力一直在消耗 —— 不管玩家有没有点开那个条。
- 设施损毁度、武器磨损度一直在累积 —— 玩家发现了才有读数,没发现就只能靠感觉。
- **玩家没发现 ≠ 机制不存在**。

### 法则二 · UI 由世界内动作获得,而非系统授予
**不是系统在恰当时机"解锁"给你,是你在世界里做了一个动作,世界因此改变,UI 随之出现。**
- 「开关」范式(Kanata 原例):墙上有个灯泡开关 —— **玩家不按,房间就不亮**;而玩家得**自己想到**去按文字板上那个开关。UI 不是奖励,是**你操作世界的结果**。
- 武器改装 / 模式切换的界面:**默认隐藏**,要玩家自己探索到。
- ⟹ **隐蔽度是设计参数**:提示从「下划线」逐步收到「只靠措辞与位置暗示」。

### 法则三 · UI 可以失去
**UI 是资源,不是成就。** 单调递增是错的。
- 最终 boss 战:**夺走生命条** —— 玩家看不见自己还剩多少(制造压迫与恐惧)。
- 武器**炸膛/损坏** → 对应 UI 消失(后果的可视化)。
- 设施损毁 → 该设施提供的读数失效。
- ⟹ 必须区分三种「没有 UI」:**从未发现** / **曾有·被夺走** / **临时·被遮蔽**。三者的叙事与体验完全不同。

## 2. 叙事兜底(法则一的公平性保障)

**没有 UI 的玩家,靠叙事文字活着。**
- 体力降到 20% → 搜索后追加一行「你感觉有点累了」。**没点开体力条的玩家,只能靠这行字判断状态。**
- ⟹ 叙事在此**不是氛围,是替代仪表盘的信息通道**,承担功能性角色。
- ⟹ 叙事线索**同时是发现的诱饵**:持续暗示「你有个东西可以看」,防止「太隐蔽 = 永远发现不了 = 功能白做」。

**推论(文案口吻铁律)**:nar_line **不得使用「——已开放:XXX」这类系统宣告式**(替玩家宣布获得了功能 = 剧透探索)。改为**只描述世界与动作**,可交互词自然嵌在叙述里(玩家没注意就是普通叙述,注意到才发现能点)。

## 3. 架构冲突 —— 已解(2026-07-22 · 🧭 裁 · 经四轨勘察 + 三镜头对抗验证,44 攻击 / 14 blocker)

### 3.0 病根不是「缺字段」,是「触发到底产出了什么」从没被定义

05 的触发**从来不是「授予 UI」,而是「发出要约」**:世界打印了那一行,那一行里有个可点的词。**「获得」发生在玩家点下去的那一刻。** 这是两个状态迁移,过去被压成了一个 —— 教义法则二与 05 的「冲突」由此而来,而非语义打架。

### 3.1 四态 · 两层持久性

| 状态 | 含义 | 作用域 |
|---|---|---|
| `offered` | 触发已发生,nar_line 已落舞台,可交互词已可点 | **账号级持久 · 单调增** |
| `discovered` | 玩家点过那个词(或该键 `gate:'auto'` 由引擎自置) | **账号级持久 · 单调增** |
| `suppressed` | 已 discovered 但本 run 内被临时遮蔽(boss 夺血条) | **run 级瞬态** |
| `lost` | 已 discovered 但本 run 内被摧毁(武器炸膛) | **run 级瞬态** |

**渲染判据 = `discovered ∧ ¬suppressed ∧ ¬lost`。**

⟹ **§3 原冲突(单调增 ↔ 可失去)靠分层解决,不改单调性**:账号层永远单调增,失去只发生在 run 层。

> **⚠ 致命耦合 —— 两条独立路径撞在同一处(🧭 对抗验证 + 🔧 架构评估)**:`players[uid].uiUnlocks` **同时是 `profiles` 整列覆盖的源**(`gameActions.js:2934→2943→2961`),且该写**静默失败**(try/catch 是死代码 —— supabase-js 返回 `{data,error}` 不 throw;且无 `.select()`,匹配 0 行也算成功)。
> 🧭 从「run 级减法会流向账号列」入口发现;🔧 从「读抖动 → 回落空集 → 覆盖成小集」入口发现 —— **同一处,两条路**。🔧 已修上线(`e053f75`,fail-closed:读失败则本 run 跳过账号列写,房内解锁照常,下个 run 自愈)。
> ⟹ **🔒 守卫救不了这个**:守卫只守「谁写」不守「写成什么」,service_role 写标量 / 写空 / 写缩小集一律通过。**风险全在应用层,不在 DB。**

### 3.1.1 字段编码 —— 采纳 🔧 的「投影模型 + 双集存储」

**单调性不打破,是「移位」。**

| 字段 | 语义 | 作用域 |
|---|---|---|
| `profiles.ui_unlocks` | **上次存档点已提交的发现集**(2026-07-22 Kanata 定,原「曾发现」)—— 仍严格单调 | 账号级。**列 / 类型 / RLS / 🔒 守卫一行不改**(🔒 零介入) |
| `players[uid].uiKnown` | 本 run 曾发现 | run 级 |
| `players[uid].uiHidden` | 遮蔽态(suppressed / lost) | run 级 |
| `players[uid].uiUnlocks` | **此刻可见** = 纯函数「曾发现 ∖ 遮蔽谓词」,每动作重算。**形状不变** | run 级投影 |

> **为什么是这个编码而不是 🧭 原拟的三字段**(`uiUnlocks`=discovered / `uiOffered` / `uiRendered`):🔧 给出的理由 —— 让 `uiUnlocks` **形状不变、语义变成「此刻可见」**,则 🎨 冷开场「直接吃下发集」那行**一个字不用改**。原拟法会逼 🎨 换字段名,白白多一处改动面。**🧭 已按此改写(2026-07-22)。**

> **判定层的 `already` 必须换源为「曾发现」,不能喂可见集** —— 注册表里 `hp_bar`/`log_panel`/`level_header` 等是**恒真条件**,若让可见集喂 `already`,剥夺后下一个同类动作立刻复活。**两轨独立推出同一结论**(🔧 从注册表恒真条件;🧭 从契约 §1.2「每键至多一次」)。注册表与 `evaluateUnlocks` **一行不改**。

### 3.1.2 存档点提交 —— Kanata 定(2026-07-22)· 并**顺手解掉「漏点 = 永久缺件」**

> 「重生后,上一次进行程度中出现的 UI 也要**退回原始(存档点时)状态**」

- 走到安全屋(step1 终点)= **提交**,这一程发现的才算数
- **死在半路 = 这一程的发现跟着这个单位一起没了**

**对 §3.1.1 编码的影响 = 改 `when`,不改 `what`。** 账号列的**写入触发点**从「每动作写」改为「**到达存档点那一拍写一次**」;字段形状、类型、RLS、🔒 守卫、单调性论证**全部原样有效**(存档点只前进 ⟹ 提交集只增)。
副作用:BUG-1(读抖动 → 覆盖成小集)的风险面进一步缩小 —— 写次数从「每动作」降到「每存档点」。

> **🔒 硬护栏(🧭 定 · 破「哪个字段负责渲染」的循环讨论)**:🧭 与 🔧 曾各自采纳对方的字段模型、互相谦让一轮。**最终取 🔧 的投影模型**(🎨 冷开场兼容是实打实的收益),但把 🔧 担心的雷用**命名**消掉,而非靠纪律:
> **`profiles` 的写入必须读一个独立命名的变量 `uiCommitted`,严禁读 `uiUnlocks`(渲染集)或 `uiKnown`。** 写入点只有一处(存档点提交),就地留注释写明「此处严禁改读渲染集」。
> **危险的不是哪个字段负责渲染,是那次写读了什么。**

**`offered` 与 `discovered` 同层同作用域**(都随存档点提交 / 回滚)。⟹ §3.1.2 原来那个「offered 落哪一层」的悬案**作废**,不需要单列升形、不需要两个部署周期、不需要双形状分支。

> **🎁 「漏点 = 账号级永久缺件」这个 blocker 被结构解掉了,不是被裁决解掉的:**
> - 看到那一行、没点、死了 ⟹ `offered` 一起回滚 ⟹ **那一行下次会再来**
> - 看到、点了、走到存档点 ⟹ 提交,永久
> - 看到、点了、死在存档点前 ⟹ 回滚,重新来过
>
> 而且理由是**世界内**的:那一行会再来,但你得**重走到那个位置** —— **是情境复现,不是系统重发**。Kanata 原话「当时那个剧情错过可能要等很久才会出现」由此自动成立。
> ⟹ **06 §1.2「每 ui_key 账号生命周期至多一次」改为「每存档点周期至多一次」**(并入已批的 06 §1 解冻)。

### 3.1.3 法则三的第三个形态:**死亡回滚**

除「被夺(suppressed)」「被摧毁(lost)」外,§3.1.2 给了法则三第三条、也是最常发生的一条通路:**死亡会让你失去这一程挣来的观测能力**。这条不需要任何新机制,是存档点语义的自然结果。

### 3.1.4 ⚠ 两条**独立**的持久线 —— 禁止合并

> 「玩家开了灯,死了,**下一次到达这个房间时灯就是开着的**」(Kanata · 2026-07-22)

| 持久线 | 内容 | 死亡时 |
|---|---|---|
| **UI 解锁持久层** | 观测能力(`offered`/`discovered`) | **随存档点回滚** |
| **场景状态持久层** | 世界内改动(灯、开关、被撬开的门……) | **跨单位永不回滚** |

**⟹ UI 退回,世界不退回。单位是消耗品,世界在累积。**

这是「讲的不是一个个体的故事」的**机制形态**,不只是叙事说法;并回答了两个此前挂起的问题:
- **前一个单位的痕迹是否可见** → 是,靠场景改动 —— 而且是**玩家自己造成的**痕迹,比预埋的更有分量
- **新单位继承的世界内锚是什么** → **安全屋**(不是抽象的「系统」)

**给 🔧 的硬约束**:场景状态**不得**挂在 run 上(run 结束即失),也**不得**与 UI 解锁共用字段/表 —— 两条线的回滚语义相反。

### 3.1.5 I9 不变式 —— **禁止剥夺「操作面」ui_key**

> **`search_btn` / `combat_panel` / `move_btn` / `craft_btn` 永不可被剥夺。**

- **硬后果**:`KaleidoAvgView.jsx:530-531` 的战斗按钮是**全仓唯一战斗输入出口** ⟹ boss 关剥夺 `combat_panel` = 玩家无法击杀 = **软锁**。(🔧 评估中三个候选方案都推荐拿它试点,**全错**。)
- **但更根本的理由是教义自洽**:剥夺**读数** = 教义本意(观测要争取);剥夺**操作面** = 剥夺 agency,**与法则一自相矛盾** —— 法则一说功能常在、只是看不见,而剥夺操作面是让功能真的没了。
- 与 §3.3 三条硬约束同源。**底线一句话:藏可以,断不行。**
- **剥夺试点键** = `turn_counter` / `level_header`,且必须在**非末关**。

### 3.2 硬时序法则:**不改法条**,落到 gate 上

05 §1.2「能伤害玩家的机制,其读数 UI 必须先于该机制首次生效」是拍板级铁律。新语义下引擎无法保证「玩家一定会点」,但**不降级法条** —— 改为:

> **凡 `missCost:'fatal'` 的键强制 `gate:'auto'`。** 该集合上旧法条自动满足。

(曾考虑降级为「要约先于伤害 + 叙事兜底」,**已否决**:N7 兜底通道在 `src/` 零实现,且档位分辨率结构性低于读数 —— 不能拿一个不存在的通道去承接公平性。)

### 3.3 门类分级 —— 判据是「诱饵有没有时间」,不是「重不重要」

注册表新增 `gate:'auto'|'click'` + `missCost:'none'|'harder'|'fatal'`。

- **不点 → 卡住**:run 停在原地,诱饵有拍数可以慢慢变明显 → **时间成本,可接受** → `click`
- **不点 → 有时钟在跑向死亡**:诱饵还没升到明示,人已经死了 → **必须 `auto`**

**三条硬约束**(对抗验证产出,缺一即回归):
1. `missCost:'fatal'` 一律不得为 `gate:'click'`
2. **任何被其它 ui_key 的呈现状态所门控的可交互词,其宿主 key 不得为 `click`**(否则点击层自锁)
3. **click 键的上游依赖键不得也是 click**(否则一次漏点滚成多件永久缺失)

**P1 `auto` 集 = `search_btn` / `move_btn` / `combat_panel` / `hp_bar` / `inventory`**;其余 10 项 `click`。

> **`auto` 的语义 = 「UI 不等待点击就渲染,但词仍 underline、仍可点、点击幂等且必须有可见回执」。** 渲染成可点却零反应 ≡ 点不动,同样毁掉可点性的可学习性(N3 §4④)。**此条写进验收。**

> **`hp_bar` 留 auto 是技术前置,不是设计退让**:现编舞里 `statusActionReady = dialogDocked && statusStage==='docked'`(`KaleidoAvgView.jsx:396`),而 `statusStage` 只有 hp_bar 解锁后才离开 `hidden`(`:237`)⟹ hp_bar 若走 click,**舞台上每一个可交互词都渲染成不可点 span**(含开场「翻找」),全链锁死且不报错。
> **待解耦**:把可点门从「全局编舞状态」改为「该行自身落位」。解耦落地后 hp_bar 可回到 click。

> **`inventory` 走 auto 的理由是结构性的**:它是药的载体,若走 click,诱饵曲线就得跑赢它自己所保护的那个掉血时钟 —— **自指,不可能保证**。
> 对抗验证另给出独立算术:inventory 未 discovered ⟹ 所有道具收益(heal/atk/def/maxHp)**只在 `useItem` 兑现** ⟹ 玩家永远停在裸值 10/5/100 ⟹ 对 boss 260/34/8 **胜率 0%**;叠加 **无中途撤离**(`extractPlayer` 对 kaleido throw)⟹ 不是「更难」,是**数学上不可能**。
> ~~且每动作重锁遭遇 ⟹ 锁在必输战里~~ **此支论据作废(🔧 实测更正)**:`releaseEncounter` **无 `isKaleidoRoom` 守卫**且**不在 `TURN_ACTIONS`** ⟹ kaleido 局可**零回合成本**放过遭遇。结论不变(上面两支独立成立),但**不得再依赖「锁死」这一支**。
> ⚠ 该实测另暴露一个内容级问题(已转 ⚙️):**kaleido 局能零成本规避战斗**,在「每搜 -4」曲线下等于一条免费的战斗豁免通道。

### 3.5 尚未实现,别当成已有

### ⚠ H1 · 叙事兜底**没有引擎通道** —— 这是教义的关键路径

🔧 架构评估的最重方向性结论(四个候选方案的**共同盲区**):

> 阈值线索与发现诱饵是**每动作按状态求值的持续输出**,而现有 nar 通道全是**状态转移一次性**的。三条路 🔧 实测全堵:
> ① 走 `unlockEvents` ⟹ 会把**没发现的件点亮**(自相矛盾)
> ② `normalizeLogEntry` **硬裁元数据** ⟹ 诱饵不可能是可点的「墙上开关词」
> ③ `narLog` 结构上**产不出「无解锁的叙事行」**

**⟹ 必须单开一条通道。** 这条现在是整个教义的关键路径 —— 因为另外两轨已经把管子两头都做好了、中间没有管:

- ⚙️ 定了仪表:**「有效剩余拍数 = (hp + 药瓶×30) ÷ 每搜掉血」**,档 ≤20 / ≤10 / ≤4 拍。(换掉血量百分比的理由:「40 血 3 瓶」与「40 血 0 瓶」百分比相同但处境完全不同 —— **百分比是错误的仪表**。这也是「只有余量薄厚不确定」的字面实现。)
- 📖 有全部档位措辞(N7)+ 承重键三档递进(`1b55781`,按合格动作拍数:常规 8→5→3 / 承重 5→3→2)。
- **中间那条「每动作求值 → 产出一行(可能带可点词)」的通道,不存在。**

通道约束(🧭 定,🔧 先出设计再实现):① 与 `unlockEvents` 解耦 ② 能承载可点词 ③ 能产出无解锁的叙事行 ④ 求值输入 = 有效剩余拍数 + 未发现时长。

## 8. 结构重置 + 死区(2026-07-22 Kanata 提 · **待细化,勿实现**)

> 「可以考虑世界观下添加**结构重置**这一事件,反应在**现实时间新的一天**时场景受到的改动会复原变成初始状态;或是一些**特别重要的事件**,我们设置成如果发生了就持续生效,也不会被结构重置掉。」
> 「比如我们之前的**死区机制**,可以设置一个时间段,比如**晚上 12 点到 1 点,杀死当时处于安全区/基地/特殊地区外的玩家,不论是否在线**,逼迫玩家那个时间回到安全区存档 —— 也就解决了我们的单调性问题,也就是**玩家是可以回头的,只是偶尔要回一趟安全区好让我们给他存档**。」

### 8.1 它解决了什么

**两条持久线(§3.1.4)从此共享一个节律 = 一天**:
- **UI 解锁**:死区强制每天至少回一次安全区 ⟹ **每天至少提交一次** ⟹ 回滚损失有界(最多一天)
- **场景改动**:结构重置每天清一次 ⟹ **不无限累积**(存储与设计复杂度都有界)

⟹ 单调性问题被**世界内的理由**解掉,而非靠加规则。

### 8.2 场景状态:**恢复周期是一个参数,不是两个档**(Kanata 定 · 2026-07-22)

> 「灯 = 日常(当天有效,次日复原)→ 跨单位痕迹是『今天的』,**但有的『灯』,比如重大事件玩家拿炸药给一个区块炸毁了,我们可能需要过几天才恢复** …… **这个不是固定的**。」

⟹ **每条场景改动自带自己的恢复周期**,而非归入固定档位:

```
场景改动 = { 改动内容, 恢复周期 }
恢复周期 ∈ { 当天(次日复原) , N 天 , 永不复原 }
```

**结构重置 = 每日跑一次的到期清算**,把恢复周期已到的改动复原,而不是「清空所有日常档」。

**设计含义**:恢复周期**本身就是叙事分量的刻度**。开一盏灯次日复原;炸毁一个区块要几天才恢复;某些事永不恢复。**世界修复自己的速度,正比于你造成的破坏有多大。**

⟹ 对 §3.1.4「开了灯,死了,下次到这个房间灯是开着的」:该句在灯的恢复周期内成立。跨单位痕迹的**存续时长 = 那次改动的分量**。

> **给 🔧 的结构要求**:场景状态持久层须按**到期时间**组织(每条带 `restore_at` 或等价物),重置作业按到期扫描;**不要按「档位枚举」建模** —— 那会把一个连续参数硬编码成两个常量,后面加「三天」「一周」就要改 schema。

**已定的取值**(随设计推进在此累加):

| 场景改动 | 恢复周期 | 理由 |
|---|---|---|
| **安全屋的门(关上)** | **永不** | 存档点锚。随重置复原 ⟹ N8「后面来的找得到这儿」变假陈述,而它正是跨单位持久的世界内解释(`12 §1.2`) |
| 灯(开关类) | 当天(次日复原) | Kanata 原例 |
| 炸毁区块类重大破坏 | 数天 | Kanata 原例:「可能需要过几天才恢复」 |

### 8.3 三处已定(Kanata · 2026-07-22)

1. **恢复周期是参数** —— 见 §8.2(替代原「日常/永久两档」)
2. **离线死亡的损失边界 = 只清未提交的进度,不动已提交的存档点。**
   ⟹ 离线惩罚 = 「**今天白跑了**」,不是「几天的东西没了」。
   **告知设计 = 放在基地的剧情里**(Kanata 定)—— 不做元层弹窗/说明书,由世界内的人告诉你天黑会发生什么。**这本身就是 Diegetic 教义的一致应用**:规则也是世界内的知识,不是 UI 上的提示。⟹ 交 📖。
3. **step1 期间没有安全屋 ⟹ 第一个单位必死于死区 = BUG,要修。**
   ⟹ **step1 期间死区不生效**(或 step1 必须能在一个日循环内完成)。**不采**「第一个单位一定死于死区」那条读法。
   ⟹ 给 🔧 的实现口径:死区判定须能识别「该账号尚未确立任何安全屋」并跳过;给 ⚙️:L 的上限不受死区约束(step1 内没有第二口钟)。
