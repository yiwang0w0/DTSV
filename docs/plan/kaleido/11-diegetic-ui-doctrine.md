# KALEIDO · 11 Diegetic UI 教义(2026-07-22 · Kanata 拍板 · 长期铁律)

> **UI 不是元层的界面,是世界内的物件与能力。** 它可以被发现、被获得、被夺走。玩家探索的对象不只是地图,还有**系统本身**。
> 本文件 = 长期设计铁律,**所有未来机制都按此设计**。取代旧「渐进披露 = 系统主动解锁并教学」的范式(05 的 ui_unlocks 是其实现基座,语义按本文件重划)。

## 1. 三条法则

### 法则一 · 功能常在,观测要争取
**机制永远在运行,与玩家是否看见无关。** UI 只是观测窗口,不是功能开关。
- 体力一直在消耗 —— 不管玩家有没有点开那个条。
- 设施损毁度、武器磨损度一直在累积 —— 玩家发现了才有读数,没发现就只能靠感觉。
- **玩家没发现 ≠ 机制不存在**。

### 法则二 · UI 由世界内动作获得,而非系统授予
**不是系统在恰当时机"解锁"给你,是你在世界里做了一个动作,世界因此改变,UI 随之出现。**
- 「开关」范式(Kanata 原例):墙上有个灯泡开关 —— **玩家不按,房间就不亮**;而玩家得**自己想到**去按文字板上那个开关。UI 不是奖励,是**你操作世界的结果**。
- 武器改装 / 模式切换的界面:**默认隐藏**,要玩家自己探索到。
- ⟹ **隐蔽度是设计参数**:提示从「下划线」逐步收到「只靠措辞与位置暗示」。

### 法则三 · UI 可以失去
**UI 是资源,不是成就。** 单调递增是错的。
- 最终 boss 战:**夺走生命条** —— 玩家看不见自己还剩多少(制造压迫与恐惧)。
- 武器**炸膛/损坏** → 对应 UI 消失(后果的可视化)。
- 设施损毁 → 该设施提供的读数失效。
- ⟹ 必须区分三种「没有 UI」:**从未发现** / **曾有·被夺走** / **临时·被遮蔽**。三者的叙事与体验完全不同。

## 2. 叙事兜底(法则一的公平性保障)

**没有 UI 的玩家,靠叙事文字活着。**
- 体力降到 20% → 搜索后追加一行「你感觉有点累了」。**没点开体力条的玩家,只能靠这行字判断状态。**
- ⟹ 叙事在此**不是氛围,是替代仪表盘的信息通道**,承担功能性角色。
- ⟹ 叙事线索**同时是发现的诱饵**:持续暗示「你有个东西可以看」,防止「太隐蔽 = 永远发现不了 = 功能白做」。

**推论(文案口吻铁律)**:nar_line **不得使用「——已开放:XXX」这类系统宣告式**(替玩家宣布获得了功能 = 剧透探索)。改为**只描述世界与动作**,可交互词自然嵌在叙述里(玩家没注意就是普通叙述,注意到才发现能点)。

## 3. 架构冲突 —— 已解(2026-07-22 · 🧭 裁 · 经四轨勘察 + 三镜头对抗验证,44 攻击 / 14 blocker)

### 3.0 病根不是「缺字段」,是「触发到底产出了什么」从没被定义

05 的触发**从来不是「授予 UI」,而是「发出要约」**:世界打印了那一行,那一行里有个可点的词。**「获得」发生在玩家点下去的那一刻。** 这是两个状态迁移,过去被压成了一个 —— 教义法则二与 05 的「冲突」由此而来,而非语义打架。

### 3.1 四态 · 两层持久性

| 状态 | 含义 | 作用域 |
|---|---|---|
| `offered` | 触发已发生,nar_line 已落舞台,可交互词已可点 | **账号级持久 · 单调增** |
| `discovered` | 玩家点过那个词(或该键 `gate:'auto'` 由引擎自置) | **账号级持久 · 单调增** |
| `suppressed` | 已 discovered 但本 run 内被临时遮蔽(boss 夺血条) | **run 级瞬态** |
| `lost` | 已 discovered 但本 run 内被摧毁(武器炸膛) | **run 级瞬态** |

**渲染判据 = `discovered ∧ ¬suppressed ∧ ¬lost`。**

⟹ **§3 原冲突(单调增 ↔ 可失去)靠分层解决,不改单调性**:账号层永远单调增,失去只发生在 run 层。

> **⚠ 对抗验证抓到的致命耦合(必须写进实现)**:`players[uid].uiUnlocks` **同时是 `profiles` 整列覆盖的源**(`gameActions.js:2934→2943→2961`)。若让它变成可减的渲染集,run 级减法会**永久抹掉账号列**,且该写是**静默失败**的(try/catch 是死代码 —— supabase-js 的 update 不 reject;且无 `.select()`,匹配 0 行也算成功)。
> ⟹ **字段必须拆开**:`uiUnlocks`(账号 discovered,恒数组,profiles 写的唯一源,run 层减法**永不流向**它)/ `uiOffered`(幂等锚)/ `uiRendered`(唯一渲染出口,可增可减)。
> ⟹ **🔒 守卫救不了这个**:守卫只守「谁写」不守「写成什么」,service_role 写标量 / 写空 / 写缩小集一律通过。风险全在应用层,不在 DB。

### 3.2 硬时序法则:**不改法条**,落到 gate 上

05 §1.2「能伤害玩家的机制,其读数 UI 必须先于该机制首次生效」是拍板级铁律。新语义下引擎无法保证「玩家一定会点」,但**不降级法条** —— 改为:

> **凡 `missCost:'fatal'` 的键强制 `gate:'auto'`。** 该集合上旧法条自动满足。

(曾考虑降级为「要约先于伤害 + 叙事兜底」,**已否决**:N7 兜底通道在 `src/` 零实现,且档位分辨率结构性低于读数 —— 不能拿一个不存在的通道去承接公平性。)

### 3.3 门类分级 —— 判据是「诱饵有没有时间」,不是「重不重要」

注册表新增 `gate:'auto'|'click'` + `missCost:'none'|'harder'|'fatal'`。

- **不点 → 卡住**:run 停在原地,诱饵有拍数可以慢慢变明显 → **时间成本,可接受** → `click`
- **不点 → 有时钟在跑向死亡**:诱饵还没升到明示,人已经死了 → **必须 `auto`**

**三条硬约束**(对抗验证产出,缺一即回归):
1. `missCost:'fatal'` 一律不得为 `gate:'click'`
2. **任何被其它 ui_key 的呈现状态所门控的可交互词,其宿主 key 不得为 `click`**(否则点击层自锁)
3. **click 键的上游依赖键不得也是 click**(否则一次漏点滚成多件永久缺失)

**P1 `auto` 集 = `search_btn` / `move_btn` / `combat_panel` / `hp_bar` / `inventory`**;其余 10 项 `click`。

> **`auto` 的语义 = 「UI 不等待点击就渲染,但词仍 underline、仍可点、点击幂等且必须有可见回执」。** 渲染成可点却零反应 ≡ 点不动,同样毁掉可点性的可学习性(N3 §4④)。**此条写进验收。**

> **`hp_bar` 留 auto 是技术前置,不是设计退让**:现编舞里 `statusActionReady = dialogDocked && statusStage==='docked'`(`KaleidoAvgView.jsx:396`),而 `statusStage` 只有 hp_bar 解锁后才离开 `hidden`(`:237`)⟹ hp_bar 若走 click,**舞台上每一个可交互词都渲染成不可点 span**(含开场「翻找」),全链锁死且不报错。
> **待解耦**:把可点门从「全局编舞状态」改为「该行自身落位」。解耦落地后 hp_bar 可回到 click。

> **`inventory` 走 auto 的理由是结构性的**:它是药的载体,若走 click,诱饵曲线就得跑赢它自己所保护的那个掉血时钟 —— **自指,不可能保证**。对抗验证另给出算术:inventory 未 discovered ⟹ 所有道具收益(heal/atk/def/maxHp)**只在 `useItem` 兑现**、玩家永远停在裸值 10/5/100 ⟹ 对 boss 260/34/8 **胜率 0%**,且无中途撤离 + 每动作重锁遭遇 ⟹ 锁在必输战里。不是「更难」,是数学上不可能。

### 3.4 点击的回程

新增轻动词 `discoverUi{ui_key}`:**不消耗回合、不推进 run、不进结算链、幂等**。
区分 `actionKind`:`'notice'`(注意到,零代价)vs `'operate'`(世界内操作,如按开关 —— 世界要变)。

> **登记**:P1 若 15 项全 `notice`,则法则二的实际落地物是「UI 靠仔细阅读获得」,而 Kanata 的原例是「玩家不按,房间就不亮」。**是否落一个 `operate` 样板 = 待 Kanata 拍板(§7 项 2)。**

### 3.5 尚未实现,别当成已有

- **N7 兜底通道在 `src/` 全仓零命中** —— 法则一的公平性目前**没有任何实现**在支撑。
- 客户端 `REVEAL_ORDER` 只有 11 键、服务端注册表 14 键 ⟹ `loadout_panel`/`prep_readout`/`convergence_preview` 三条事件被 filter **静默吞掉**(存量 bug,与本方案无关但会放大)。
- 现网**没有一条 nar_line 含它被指定的可交互词**(13 条仍是旧宣告式)⟹ 不先换字,整条链空转。

## 4. 前置缺口(机制层现状)

法则一要求「数据常在」,但 kaleido 引擎侧**目前缺这些数据机制**:
- **体力**:`staminaDelta` 被 `!isKaleidoRoom` 明确排除 —— **kaleido 现无体力经济**(Kanata 举的 20% 例子需先补此机制)。
- **设施损毁度 / 武器磨损度 / 武器改装与模式切换**:均**未实现**。
⟹ 这些是法则一的载体,需 ⚙️(数值/内容设计)+ 🔧(机制实现)排期。

## 6. 与既有决策的关系

- **B1(UI 即进度 = 一次性开场)仍成立**,但被本教义扩展:一次性的是「首次发现的惊艳」,而**探索系统本身**是长期玩法(法则二三让后续 run 仍有可发现物)。
- **B3(边界 = 仅现有循环)暂不变**:损毁/磨损/改装属新机制,排在现有循环全量之后。
- **05 §1.3 的 12 项 ui_key** 语义按本教义重划(从「系统解锁」→「玩家发现」)。

> **⚠ 未登记的隐性裁决(交 Kanata,§7 项 3)**:§3.1 的「账号级单调 + offer 一次性」事实上让 **B1 赢过本节那句「后续 run 仍有可发现物」** —— 账号跑完首个 run 后 15 项全 offered+discovered,注册表再无未发现项,**法则二退化为账号生命周期里的一次性教程**。B3 解冻后(磨损/损毁/改装 = 法则二的**原例**,天然是 carrier 级可发现物:每把武器各有未发现的改装口),持久化形状里没有 scope 位就得改列。
> **🧭 已裁的零成本对冲**:注册表现在就付 `scope:'account'|'carrier'|'run'` 字段 + 持久化版本位 `{v:2,...}` 的预留成本(P1 全填 `'account'`),**B3 解冻时不必再动列**。取向本身挂起待裁。

### 7.2 🧭 已裁(工程判断,不占 Kanata 注意力)
