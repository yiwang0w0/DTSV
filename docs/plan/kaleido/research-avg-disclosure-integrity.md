# KALEIDO · 研究:AVG 渐进披露下的游戏性完整性(⚙️ · 研究不实现)

> 2026-07-08 · ⚙️ 游戏性轨 · 应 🧭 命题(Kanata 愿景:文字 AVG·登录即进 run·初始只有搜索按钮·整套搜打撤随点击渐进浮现)。
> **方法**:3 grounded lens(loop-integrity / cadence-fit / risk-gap·各读 00/02/05/06/07/09)+ 对抗 critic 压测。全体裁决 = **holds-with-gaps**。

## 0. 结论速览

**成立,但有一个必须纠正的框架错位 + 一处结构性缺口。**

- **✅ 底层循环成立**:"搜刮 vs 战斗 vs 赶路"的回合预算 → 准备度 → boss 闸门,是一个**定量解出、调好的**预备型 roguelite 循环(09 §6.2:pStat=0.30 → balanced 83% / rush 5% / hoarder 污染自限)。这套**是真引擎**。
- **⚠ 框架错位**:"UI 即进度 / A Dark Room" **不是引擎,是一层皮**——它是**账号级、一次性、约 10 分钟的首个 run 教程**(05 §1.1·veteran 一进局满 UI)。第 2 个 run 起它贡献**零**。把一次性教程当作撑全程的引擎 = 过度承诺。
- **🔴 核心结构缺口 = 倒挂的投入曲线**:游戏**最新鲜时机制最薄**(seq1 = 三次点同一个按钮·零战斗),**机制最厚时新鲜感已耗尽**(seq3-5 的准备度数学)。披露预算 seq3(40%)就花光,seq4-5(40% 行程)零新 UI。两个趣味源(披露在前段 / 循环在后段)**时间上错开**,接缝在中段——首玩家最可能在此感到"地板"。

**一句话给 Kanata**:愿景的**手感与调性**对(ADR 式冷峻描述制真的贴),**底层循环**也对;要纠的是**别让"UI 即进度"独自扛全程**——把一部分披露挪到后段、绑到准备度兑现上,让"UI 长出来"的感觉延续到真正有深度的地方。

## 1. 两个断言,分开判

Kanata 的愿景含两个断言,必须分开:

| 断言 | 判定 | 依据 |
|---|---|---|
| **A. 搜打撤循环撑得起一局** | ✅ 成立 | 3 固定动词(R5)+ move → 准备度闸门 boss;09 §6.2 定量解出平滑曲线;污染贪婪税自限囤货 = 真长期决策压力 |
| **B. "UI 即进度"是撑趣味的引擎** | ⚠ 过度承诺 | 披露是**有限、前置、首 run 唯一**;10/12 ui_key 在 seq1-2 触发,末个机制披露(stance_ui)在 seq3;之后 60% 行程无新 UI |

**ADR 为何成立、我们的复刻缺口**:ADR 每次点击同时给三样——①发现 ②常带新机制 ③**喂养一个活经济的资源分配决策**(火要柴→人口要食→工作抢人口→地图打开…系统层层叠、始终活)。KALEIDO:
- **①发现 + 调性**:真复刻(nar_line 逐解锁 + 05 §0.4 描述制"那东西/那家伙/黑里的那个" = 真 ADR 对齐,非贴皮)。
- **②新机制**:只在有限窗口复刻。
- **③每次披露带分配决策**:**早期几乎没复刻**——seq1 无分配张力(搜→进背包→无稀缺物竞争);更糟:craft_btn 在 seq1 就浮现(背包有材料),但**首次真能合成要到 seq4**(配方需 2 件·seq1 只保底 1 件;且 6 种散件凑成对更难)→ **浮现一个 ~3 关内失效的按钮 = ADR 失败模式的倒版**(ADR 里浮现的机制立刻可用且有后果)。

## 2. 核心结构发现(3 lens + critic 收敛)

1. **🔴 倒挂投入曲线 + 后半新鲜感崩塌**:seq1 最新鲜(3 次同点击)最薄;seq4-5 最厚(准备度数学)却零新 UI。"UI 即进度"支柱 60% 处停产。**无任何闸门测到这个断层**(P1 闸门 §6 只看开局"到第二个 UI 的时间")。
2. **🔴 冷开局无钩子(critic 的 fatal-flaw 候选)**:首次点击**前**的屏幕 = 一个裸按钮·零叙事框——log_panel 与"觉醒"nar_line 都在**首搜之后**才浮现。ADR 先给你点击的理由("火灭了,屋里在结冰"),KALEIDO 给的是**对着裸按钮的信仰之点**。真实的 10 秒跳出风险。
3. **末关手感扁平**:seq4+seq5 都是 mode=standard;boss(260/34/8)是**纯拼数值的伤害交换**,非机制独特战。只有 seq2(gauntlet)+ seq3(stance_duel)有战斗质感 → run 的**高潮时刻靠一场平庸的对攻**。
4. **回放现实 vs roguelite 野心**:披露账号级一次性 → run 2+ 贡献零。P1 闸门时变体近乎无(seq1-2 固定 onboarding·seq3-5 用 `.find` 首匹配无 seed 洗牌·AI 生成 P2+)。**在"无 AI 纯随机版可玩且成立"这个可终止项目的 P1 闸门(00 §8),披露已耗尽 + 回放很薄 + 裸循环欠建**。
5. **载重功能警告**:今日 build 里 ADR 开局是**惰性**的——event_deck 零运行时读者(07 §0.4)、seq1-2 SQL enabled=false。整个"搜索长出一切 + 安全首战"**已规约+已验证但未接线**(待 🔧 hook ①②④)。**拿惰性 build 去评 P1 = 验错了工件。**

**强项(值得保留)**:①调性/描述制 ADR 对齐是真的 ②准备度决策轴定量解出调好 ③污染贪婪税自限囤货(优雅)④硬时序法则严谨(hp_bar 挂首搜·覆盖污染/Ω/收缩全死亡向量·20000 seed 证首战安全)⑤**团队自省强**(缺口多在文档里自己标了,非盲区)。

## 3. 我的 D6/09 在这个 AVG 形态下的适配度(cadence-fit)

**纸面 = 对得上;live = 当前是断的(卡在 hook①)。**

- **纸面顺序对**:注册表序(05 §1.3 / 06 §2)= search_btn→log_panel→inventory→hp_bar→combat_panel→move_btn,映射 Kanata 的 搜索→(日志)→物品栏→血量→战斗→移动。inventory(pos3)在 hp_bar(pos4)前,06 §1.2 定 unlockEvents 序=注册表序 → 首搜出物时 inventory 动效先于血量 = 匹配"物品栏→血量"。
- **🔴 live 顺序当前是断的**:06 §7.1 的 E2E 实测解锁序 = [log_panel, hp_bar, combat_panel, …, **inventory 第 8**]——inventory 落在 hp_bar/combat_panel **之后**,反了 Kanata 的"物品栏先于血量""物品先于战斗"。**根因**:hook①(非 boss 内容注入)未接 + seq1-2 enabled=false → 首搜不出物 → inventory_gained 假。
- **接线后自愈**:hook①(内容注入)+ hook④(seq1 零战斗)+ enabled=true 后,cadence 干净解出:search1 得 id27(front-load guaranteed)→ unlockEvents=[log_panel, inventory, hp_bar](物品栏先于血量);search2 得材料 → craft_btn;seq1 无遭遇 → combat_panel 首现于 seq2 → **首物(seq1)先于首遇(seq2)、hp_bar(seq1)先于 combat_panel(seq2)**。
- **一处有意偏离**:硬时序法则把 hp_bar 钉在首搜(覆盖非战斗死亡向量),故血量**与 inventory 同一动作共现**,而非作为稍后"危险逼近"的独立披露——偏离 Kanata 的分段 搜→拾→血 爬升。06 §5.3 已标给 📖 改 nar_line(措辞改"首次行动时身体的受伤感上线")。防御性正确,但是有意识的偏离。
- **需调的 seq1-2 投放**(具体):①保持 seq1 event_deck 消耗品 id27 **列在**材料前(保 inventory 先于 craft);②hook④ 强制 seq1 chamber max_npcs=0(防随机遭遇在 seq1 抢先 combat_panel);③材料 id 从占位 id13 改指 kaleido 新散件(碎块等·09 已建·避 canon);④修 07 §1 表里陈旧的 hp_bar=seq2 行(应 seq1 首搜·与 §9 一致)。

## 4. 最高杠杆修法 + 优先建议

**🥇 最高杠杆(critic + risk-gap 收敛)= 把披露预算重分配到后半,且每个后段披露绑到准备度兑现**:
- seq4 crafting 首次兑现时浮现一个"整备/合成产出"面板;seq5 浮现 boss 准备度读数;收敛预览。
- **一改同治两大结构缺口**:①后半新鲜感崩塌(seq4-5 现零新 UI)②倒挂曲线(把披露挪到真决策轴所在处 → 新鲜感与机制深度不再时间错开)。"UI 即进度"支柱撑过 60% 而非 seq3 死。
- **不可谈判的前置**:先落 hook①(非 boss 内容注入)+ seq1-2 enabled=true。否则 onboarding 全惰性、每条 pacing 断言不可测,拿当前 build 评 P1 = 验错工件。

**其余优先建议**:
1. **冷开局种一行静态"觉醒"提示**(首搜前可见·先于 log_panel)→ 裸按钮不再是信仰之点。低成本、治 fatal-flaw 候选。
2. **修 craft_btn 死窗口**:要么推迟其浮现到第 2 件配对材料落袋(显得可用),要么给个更早的低成本兑现。注:6 种散件权重抽 → 凑成对(碎块×2)比"seq4 可用"更难(critic 指出各 lens 都**低估**了这个死窗口)。
3. **给高潮加战斗质感**:seq5 boss 改非 standard 模式(阶段化 / gauntlet-stance 混合);优先填战斗模板库(规格目标 5-8·00 §3)再靠它撑中后期深度——现 5 关里 2 关 standard。
4. **P1 前落最小 seed 洗牌(hook②·mulberry32 已在)**,让 run 2 不同。披露 run1 后耗尽 + 生成 P2+,近乎相同的回放是 P1 闸门(可终止项目)对 roguelite 前提的最大威胁。
5. **解决 over-search 机制悬案(09 §6.0)**:critic 指出 seq4 搜索空转严重性(~29% 空搜)**预设玩家能超 survive_turns 多搜**——而这是未决机制。若关卡 survive_turns 达标即自动清,hoarder 画像不成立、空转问题大幅蒸发。**这个机制答案定了才能定死经济**。(注:🔧 三问回执其实已答"达标能留关囤货·上限开放"——故 over-search 可行,空转问题成立,须治;critic 用的是旧口径,以 🔧 回执为准。)
6. **诚实重定框架**:文档里把"UI 即进度"明确标为**首 run onboarding 皮**(非 loop),让 P1 评审判**裸循环**而非披露(披露 run2 起就没了)。
7. **文档卫生**:修 07 §1 表 hp_bar=seq2 陈旧行;📖 改 hp_bar nar_line。

## 5. 给 Kanata 的诚实底线

- **愿景值得做**——手感、调性、底层循环都成立,团队自省强(缺口多已自标)。
- **但别让"UI 即进度"独扛**:它是一层漂亮的一次性 onboarding 皮,不是撑重复游玩的引擎。撑重复的是**准备度 vs 贪婪的回合预算循环**(这套是真的好)。
- **三件事决定它成不成**(按优先):①先接线(hook①)让 onboarding 真的活,别拿惰性 build 评 P1 ②把披露挪一部分到后半、绑准备度兑现,治倒挂曲线 + 后半崩塌 ③P1 前给最小回放变体(seed 洗牌),否则 run2 = run1。
- **风险不是"不好玩",是"趣味源时间错开 + 后半无新意 + 回放薄",且当前未接线**。这些**都是已知、可修、低-中成本**的——不是设计死局。
