## 1. step 是什么

> 「我们设置的 step 检测,是比如玩家**第一次到达某个安全区/基地**来给他的账户从 step0 标记改为 step1;另外比如是他**杀死了某个特定敌人**、**第一次获得了某个特定物品**、**做了某个特定操作**,给他推进 step。」(Kanata)

**step = 账号级里程碑标记,由具名世界事件推进。**

- **不是**「阶段」——不按时长、不按关数、不按进度百分比
- **不是**存档系统 —— 见 §3
- 触发面 = 四类具名事件:**到达某地 / 杀死某敌 / 获得某物 / 做某操作**
- **一次性**:每个 step 只推进一次,幂等

### 1.1 已定内容

| step | 达成条件 | 备注 |
|---|---|---|
| **step0** | 注册 → 登录 → **首次搜索** | 账号首次只一次。觉醒行「很久没有回音了」**只播这一次**;再进走「延续」分支 |
| **step1** | **把安全屋的门「关上」**(2026-07-22 改:里程碑是**动作**不是位移,见 §1.2) | **首次搜索起**(含 step0 那一搜)**每次搜索同步掉 HP**(负伤 buff),首要目标活下来 · 找药;由此引出物品栏 + 详细状态 UI |
| step2+ | 未定 | **不必是「安全屋→安全屋」** —— 可以是「杀掉墙后面那个东西」「第一次拿到某个物件」。里程碑形状跟着剧情走,不被地理结构绑死 |

### 1.2 step1 里程碑 = 把门「关上」(📖 C 案 · 🧭 批 · 2026-07-22)

**不是「走到」安全屋,是玩家亲手把那扇门关上。** 抓手是 Kanata 自己给的:step 可由「**做了某个特定操作**」推进 ⟹ 里程碑不必是位移。

四条同时对上:
1. **N8 说安全屋是「整个游戏第一个『我留下了什么』的时刻」—— 只有那个动作是玩家做的,这句才为真。** 「走到」的写法里玩家只是碰到了它。
2. **它是 `11` 法则二(世界内动作 → 世界改变)最干净的一次示范**,且是进度关键件、天然走点击。
3. 「关上」是天然的 `action.word`:世界内动作、删除测试过、与现有 14 词零撞。
4. **它解释了后来的单位为什么回得来 —— 门是关着的,是上一台关的。** 跨单位持久由此得到世界内理由,**不用多写一个字**。

> ### 🎁 连带:**这就是 `11 §7.3` 项 2 要的 `operate` 样板**
> Kanata 对 operate 的要求是「玩家对场景的交互要**确实给场景添加改动**」「可以是**永久性改动**」。「关上门」逐条命中:世界内动作 ✓ 真的改变场景状态 ✓ 跨单位持久 ✓ 走点击 ✓。
> ⟹ **教义里第一个真正的 `operate` 实例,落在 step1 的最高点上。**
> (开场「翻找」点下去=直接执行一次搜索,是**另一个**位置的候选,与本条不冲突,仍未定。)

**门的恢复周期 = 「永不」(🧭 裁)**:门是**存档点锚**。若它随结构重置复原(`11 §8.2`),存档点的世界内理由当场蒸发 —— N8 那句「后面来的找得到这儿」变成假陈述,而它正是跨单位持久的解释。⟹ 「又回来了」分支里「**还关着**」为真。

**载体口径**:seq2 那场安全首战**保留为「路上的东西」**(非门槛)—— combat 解锁点与已入库数值不浪费。

### 1.3 掉血起点 = **首次搜索(含 step0 那一搜)**(🧭 裁 · 2026-07-22)

📖 抓到一处跨文档矛盾:本文原写「step0→1 期间掉血」(可读成 step0 首搜不掉),而 N3 的 `hp_bar` nar_line 挂在**首次 search**、内容是「损耗**从这一下开始算**」⟹ **那一拍上这句是假的**。

**裁「甲」:step0 首搜就掉血,`hp_bar` 挂载点不动、文案一字不改。** 两条理由:
1. **Kanata 原话含首搜**:「打算制作成玩家**从第一次开始搜索后**,每次搜索都会同步失去 HP」。原文的「step0→1 期间」是 🧭 措辞造成的歧义,已订正。
2. **更硬:挪走会破硬时序法则。** `06 §1.3` 记明**污染熔毁 / Ω 超时 / 收缩**等非战斗死亡向量**在任意动作上结算,含首搜**(引擎当初正是为它们才把 hp_bar 从 fight_start 提前到首次 search)。`hp_bar` 若挪到「进入 step1」,step0 那一搜就成了**能死人但没有读数要约**的窗口 —— 拍板级铁律不为文案让路。

(否决的乙案 = 把 `hp_bar` 挂载点移到「进入 step1」。📖 的设计理由「让负伤成为 step1 的开幕事实而非开局杂音」成立,但敌不过时序法则;且 100 血扣 4 点读起来不是杂音,是**世界的第一句话**。)
**⟹ 费率 = 全程同率(🧭 裁 · 2026-07-23)。** 原写「step0 那一搜扣多少是 ⚙️ 的旋钮」,现收回 —— 📖 给了一条技术理由,它比设计口味硬:

> **N7 的余量锚点公式假设单一费率。** 「有效剩余拍数 =(hp + 药瓶×30)÷ d」在 d 分段时会**在跨段那一拍跳变**,而那个数是四档阈值的**唯一依据**。

⟹ 两段费率会让阈值线索在段边界上错档。加上「你做的第一件事就要付代价」会被减免打折 —— **两条都指向同率**。⚙️ 的旋钮收回,`d` 全程单值(方差另算)。

### 1.4 死亡语义

- **死亡从当前 step 的开头重开**,且**换视角** —— 「讲的不是一个个体的故事」:上一个单位死了,下一个被派出,叙事交代「离上一个人出发过去了多久」。
- **死亡 = 时间推进,不是回档。**
- ⟹ **`step` 不随死亡回滚**(故事进度)。

## 2. 🎁 step 与 `ui_unlocks` 是同一台机器

| | `ui_unlocks` | `step` |
|---|---|---|
| 判据 | 路由边界 `beforeMe`/`afterMe` 前后态 diff | **同** |
| 存储 | 账号级 | **同** |
| 幂等 | 每键至多一次(`already.has` 早退) | **同** |
| 注册表 | `KALEIDO_UI_UNLOCKS` 15 条 `{verb, condition}` | **第二张表** |

⟹ `evaluateUnlocks` + `applyKaleidoPostAction` + 账号持久 + 幂等**整套可复用**。机制部分几乎不用新建,**成本主要在注册表内容**。

> **但不为复用而复用**:若共用 evaluator 会把 `ui_unlocks` 已稳住的逻辑搅浑,就分开写。以 🔧 实测为准。

**分工**:机制与形状 = 🔧;里程碑**语义** = 📖;**具体实体**(哪个敌人 / 哪个物品 / 哪个操作)= ⚙️。

## 3. ⚠ step 推进 ≠ 存档点提交 —— 三条独立的作用域

「首次到达安全区」那一拍是**多件事同时发生**,但它们频率与回滚语义都不同:

| 概念 | 触发 | 频率 | 死亡时 | 载体 |
|---|---|---|---|---|
| **step 推进** | 首次达成条件 | **一次性**(里程碑) | **不回滚** | 账号级 step 标记 |
| **存档点提交** | **每次**回到安全区 | **反复**(死区逼玩家每天回) | 提交点不回滚;**未提交的进度回滚** | `uiCommitted` → `profiles.ui_unlocks` |
| **场景状态** | 玩家操作场景(`operate`) | 每次 | **不回滚** | 独立持久层;日常档每日结构重置,永久白名单不重置 |

**第二次之后到达安全区,只有存档点提交,step 不动。**

### 3.1 由此得出的一条自洽性

> **玩家可能是 step3,却顶着 step1 的 UI 集。这不是 bug。**

- `step` = **故事走到哪儿了**
- UI 解锁 = **这个单位知道什么**

⟹ 「故事在前进,人换了一茬」的机制表达。**实现里不得把这两者对齐**,它们本来就该错位。

### 3.2 回滚语义相反的东西不得共用字段

`step`(永不回滚)与 `ui_unlocks`(随存档点回滚)**必须分开存**。同 `11 §3.1.4` 的教训(UI 解锁持久层 vs 场景状态持久层)。
