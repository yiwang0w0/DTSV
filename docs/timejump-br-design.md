## 1. 关键工程判断（决定整个技术路线）

**结论：时间跳跃BR 是"慢节拍策略大逃杀"，不是 twitch FPS。可在现有 Next.js + Supabase 栈上以"事件溯源 + 服务器权威"重建，不需要从零写实时网络引擎、也不需要迁 Unreal。**

依据（全部来自规则书自身）：
- **节拍 = 15 分钟一个阶段**（RULEBOOK §2）。这不是 60fps 同步，是分钟级战略推进。
- **警报 = 3 分钟逃离窗口**（§8）。玩家占据房间位置、以分钟尺度移动/逃离，不是像素级走位。
- **§11 工程备忘直接点名事件溯源**："服务器权威 / 所有动作发往服务器按 tick 排全局唯一先后 / 不切实例（单服务器单时钟）/ 预测+回滚（仅为手感，以服务器为准）"。

这正是现有 DTSV 的动作分发模型（`gameActions.js`：search/attack/move/extract 都是离散的、服务器校验的动作写进 `gamevars`）。**重建 = 把"单人生成 chamber 路径"换成"多人共享的 100 房世界 + 大时钟 + 深度/有效阶段 + 双属性状态 + 事件日志 + 可见性过滤 + 播报"，动作模型本身基本复用。**

> ⚠️ 前提假设：moment-to-moment 玩法是**动作级**（点击移动/搜索/炸毁/跳跃），不是连续位移。
> 若用户真要 twitch 级走位射击，则需要独立实时服务器（或 NIGHTFALL/UE track）——本文档按动作级设计，
> 如需改向请在 Phase 31 走查时提出。

## 3. 目标架构：数据模型（双属性 → 表映射）

验毒针矩阵直接决定建表。**结构上让"按深度分版本 + 可写"那一格无法存在**，悖论从根上消失。

| | 全局·一份 | 按深度·分版本 |
|---|---|---|
| **可写** | ✅ `br_match_events` + `br_match_room_state`（物理/物资/尸体） | 🚫 **结构性禁止**（不建任何这样的表） |
| **只读** | ✅ `br_rooms`（静态拓扑） | ✅ `br_zone_tables`（禁区表 + 物资档位） |

### 新增表（Phase 30 加性部署，不动现有 live game）

| 表 | 属性归属 | 职责 |
|---|---|---|
| `br_rooms` | 静态·只读·全局 | 100 房拓扑（room_id / label / region / neighbor_ids）。虚拟空间术语命名（扇区/节点），不用伊甸港/Ω-段。 |
| `br_zone_tables` | **属性②** 只读·按深度 | `(phase, room_id) → is_forbidden, loot_tier`。预设菜单。深度只是读哪一行的镜片。缩圈 = forbidden 集合随 phase 单调增长（100→80→60→40→20 开放）。 |
| `br_matches` | 大时钟锚点 | 一行 = 一场 BR。`started_at + phase_seconds` 计算当前真实阶段（不存，按 wall-clock 算 → 崩溃安全）。 |
| `br_match_events` | **属性①** 可写·全局 | 追加式事件日志。`id BIGSERIAL` = 全局唯一定序（§11）。`clock_phase` = 事件时钟戳。bomb/repair/loot/death/extract/move/jump。**唯一可改写世界的层。** |
| `br_match_players` | 玩家态 | `(match_id,user_id) → room_id, depth, hp, alive, gear, inventory`。`有效阶段 = 当前真实阶段 + depth`（封顶 max_phase）。 |
| `br_match_room_state` | 属性① 派生缓存 | 由事件折叠出的房间现状（physical_state / loot_remaining / state_clock）。`state_clock` 实现"后写覆盖前写"。读快用，真相仍是事件日志。 |

复用现有表：`player_points` / `shop_catalog` / `shop_exchange_rates` / `classes` / `equipment_*` / `item_pool`（局间经济 + 入场装配，见 §5）；`fragment_pool` / `player_fragments`（深层叙事，见 §6）。

### 三条派生公式（应用层计算，不落库）

```
当前真实阶段(match)  = min(max_phase, floor((now - started_at) / phase_seconds))
有效阶段(player)     = min(max_phase, 真实阶段 + player.depth)
可见(viewer, event)  ⟺ event.clock_phase <= 有效阶段(viewer)        // §5 唯一判据
```

### 物理状态折叠（last-write-wins）

`br_match_room_state` 由 `br_match_events` 按 `clock_phase` 升序、同戳按 `id` 升序折叠：后写覆盖前写。
物资守恒：loot 事件只减不增、原子先到先锁（§7）。修复事件把 physical_state 设回 intact（§8），但**绝不改动 `br_zone_tables` 的 20 系统禁区**——修复只作用于属性①。

## 4. §10 设计旋钮的决定（拍板）

规则书 §10 留了四个旋钮。本宪法的初版默认值（Phase 33+ 实现，可在 admin 调）：

1. **深度如何获得/消耗** → **消耗"跳跃"道具/资源 + 冷却，单向阶梯**（不能回头）。`br_match_events` 记 `type='jump'`。稀有豪赌而非常规操作，保护"跳=赌"的张力。
2. **情报是否收费** → **收费**（耗道具 / 暴露位置 / 有延迟）。否则信息过载、张力消失（§8 建议）。
3. **"解除禁区"是否向前传染** → **否，初版**。修复只改属性①物理状态，不改属性②的 20 系统禁区（与 §8 一致）。"主动改写下游玩家生死"作为后续高级旋钮，默认关闭。
4. **平衡校准** → 交给 Phase 35+ 真实对局 + healthcheck 数据驱动。确保跳跃者回报（早期代差 + 看清未来禁区图）压得过代价（即死风险 + 世界变窄 + 成为猎物），否则无人敢跳、机制空转。

## 6. 虚拟空间叙事重构宪法（弱化远星表层）

### 6.1 硬边界（与 `narrative-vision.md §6.1 Additive Evergreen` 的强制和解）

> **"弱化远星表层符号" ≠ 删除远星。** 它指：降低前台权重 + 不在新手引导里前置六纪元谜题。
> 残片 F01-F15 **仍永久可发现**（`narrative-vision §6.1.1`），不删、不 retire、不 vault、不限时。违反即违宪。

具体落地：
- **前台（80% 虚拟空间）**：大厅 / 入场 / 对局内 HUD / 播报 一律用**中性虚拟空间术语**——扇区、节点、深度、阶段、禁区表、物资档位、跳跃、撤离。机制频道 100% 清晰（守 `narrative-vision §6.4`）。
- **深层（20% 远星）**：六纪元 / 泡泡 / Ω-段 / PI 引导者 / 函馆 退入 **archive / codex / 隐藏终端**。玩家可挖，但不强推。新玩家可以完全不碰也能玩懂 BR。
- **桥接叙事（可选，最连续的解释）**：虚拟空间"是什么"留白即可；若需一句话，可暗示"这片可被跳跃、可被缩圈、物资按档解锁的空间，本身就是某台仍在运行的计算"——顺着现有 lore（Ω物质="被重排的数据"、"环在做计算"、函馆=泡泡），但**前台不展开**。

### 6.2 命名速查（BR 前台 vs 远星深层）

| 概念 | 前台（虚拟空间·中性） | 深层（远星·彩蛋） |
|---|---|---|
| 战场 | 虚拟空间 / 竞技场 / 实例 | 远星函馆 / 17号异常段 |
| 房间 | 扇区 / 节点 / 区块 | （不在前台用伊甸港等） |
| 跳深度 | 跳跃 / 深度 / 向后跳 | （新机制，无远星包袱） |
| 禁区 | 禁区表 / 收缩边界 | （前台即用禁区，远星侧另说） |
| 物资档 | T1-T5 物资档位 | 结构碎片/环段部件/Ω物质（退深层 item flavor） |
| 玩家 | 玩家 / 跳跃者 / 书写者 | PI 引导者（深层身份） |

### 6.3 监测
- 任何修改 `fragment_pool` / 残片可发现性的 PR 仍受 `narrative-vision §6.1.6` 全量首达率红线约束。
- "弱化"只允许调**前台呈现/引导顺序**，不允许调"是否可发现"。
