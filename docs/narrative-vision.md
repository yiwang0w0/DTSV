# 远星函馆 — 叙事愿景与六纪元宪法

> 本文档定义六纪元(最深层 lore 时间轴)的官方分期与情感主题。
> 所有残片文案、合成配方叙事、新系统命名、新地图氛围词,凡涉及"过去"或"现在"的相对位置,都必须能对到本文档的某一纪元。
> 与 [lore-minimum-viable.md](./lore-minimum-viable.md) 互补:前者讲玩家看见什么("泡泡 / 异常段"),本文档讲玩家看见的东西**属于什么时间层**。

## 一、为什么要写这份文档

六纪元在游戏内**不直接出现**(玩家不会读到"现在是第 6 纪元"这种话),但它是 lore 作者、SQL migration、系统命名的**对照基准**:

- 残片文案里"当前纪元""早于当前纪元"——"当前"指哪个纪元?必须是确定的(且**按产品线分锚**,见 §二)。
- 新增任何残片 / 地图 / 职业 / 关卡文案,都要先回答:它属于哪个纪元?情感主题对得上吗?
- 没有对照表,lore 会内部失序(Destiny / Halo / Mass Effect 全踩过的坑:时间轴失序 → 资深玩家弃坑)。

## 三、每纪元情感主题速览(lore 作者抓手)

### 起源(序章)
- 关键词:拾遗、死者低语、余响域、"不是创造,而是拾遗"。
- 绝不出现:任何函馆内部系统名(都还没建立)。

### 第 1 纪元 — 监听时代
- 关键词:采样、背景噪声、失稳模板、"文明的灭亡是一次高密度信息爆发"。
- 氛围:冷静到近乎虔诚的倾听;结尾的厌倦("越来越整齐的旧答案")。
- 绝不出现:泡层/泡泡(还没造)、Ω、PI。

### 第 2 纪元 — 构造时代
- 关键词:泡层、时间压缩、初始变量包、投放、熵终、视界线回收、"残响与封闭性原则"。
- 氛围:实验室的冷酷好奇("我们只是想看,压力最大的时候,会不会出现意料之外的结构")。
- 情感台词基准:"他们花了一百万年,只是在一个封闭盒子里,把每一寸墙壁都摸了一遍。"

### 第 3 纪元 — 失衡时代(KALEIDO 在此)
- 关键词:那十秒、3 号干道、主锚未响应、溢出、"错误的位置包裹住错误的东西"、临时编号、冻结、封锁、低频、挂起、收缩。
- 氛围:事故后的静默。没人欢呼,没人解释;系统没宣布紧急状态,但一切行为都收缩了。"我们不知道它是什么,所以我们先不动它。"
- **KALEIDO 写作口径**:玩家看到的一切黑暗、断电、无图、权限一格格下放,都是"收缩"的具象;系统自己也没有内部的完整图——这不是玩家的无知,是世界的实况。
- 绝不出现:PI/引导者(第 4 纪元才有)、共构(第 5 纪元概念)、深界(第 6)。

### 第 4 纪元 — 拓荒时代
- 关键词:模拟回包、伪装缺席、PI-1、六十周期、"它还在发生中"、"每次回应的排列都不一样"。
- 氛围:对外死寂,对内全部注意力聚焦在一个不理解的结构上。
- (生成式内容的正史执照在此:永不重复的排列。)

### 第 5 纪元 — 逃逸时代
- 关键词:D-8821、Anchor-β、伊甸港-3 号旧通道、误接、共构、结构污染源、"不是泡层突破了系统,而是系统接住了泡层"。
- 氛围:恐惧的性质变了——从"外面"变成"里面"。

### 第 6 纪元 — 深界时代(多人线"当前")
- 关键词:伪造编号、闯入、往深处走、阻断、熔断、"我们已经不再封闭"。
- 氛围:对峙与未完待续。四结局(崩解/清算/合流/探索)在此待决——游戏内多人线结局即此。
- 注:ver2「终末」篇给出另一组结局表述(崩解/转化/失败/探索),**游戏现行四结局按根目录深界版**;两版归一待 Kanata 钦定(登记于修订影响清单)。

## 六、宪法条款(治理规则 · 2026-07-07 修订中逐条保留)

### 6.1 Additive Evergreen 条款(research-2026-05-28-C P0)

> **宪法级别条款。** 本节是 DTSV 叙事系统的不可妥协承诺,PR review 时对照执行。
> 直接对 Destiny 2 内容 vaulting 灾难的预防性回应,参考 Marathon(Bungie)"additive evergreen" 与 Warframe 反 FOMO 哲学。

#### 6.1.1 永久可发现承诺

- **F01-F15 是永久可发现的**。任何注册账号、任何赛季、任何时间加入 DTSV 的玩家,都能在游戏内通过常规玩法(raid 拾取 + 三链合成 + 解码)触达全部 15 个残片。
- 这是**对玩家的承诺**,不是"目前的默认行为"。`fragment_pool` 表里的 F01-F15 行不得被删、不得被打标为"已 retire"、不得被赛季配置覆盖为不可拾取。
- 老残片("结构稳定性年报-第 5 纪元"等历史文本资产)同样适用:写出来过的 lore 永不撤回。

#### 6.1.2 仅可加不可减(additive only)

- 任何叙事新增内容(F16+ 残片 / 新纪元 / 新合成图谱 / 音频日志)**只能扩张总集合**,不得替换或移除已有元素。
- 残片合成图谱(discoverFragment 三链)的边只能加,不能删。若某条三链设计失败,**修文案 / 调权重**,不删边。
- 新增内容不得通过改写老残片文本"挪用"已有 F01-F15 编号。新内容用新编号。

#### 6.1.3 反 FOMO 红线

- **禁止"限时残片"**:不允许"本周末前才能拾取的残片"、"赛季独占叙事章节"、"raid race 限定 lore drop"等任何带 deadline 的叙事资产。
- **禁止 fragment cadence 倒计时 UI**:大厅 / chamber 内不得出现"距离 F0X 下架还剩 N 天"或同类倒计时元素。
- **赛季回归玩家不补偿叙事进度**:残片解码进度不参与 wipe;回归玩家的叙事进度本来就在。
- **限时活动不得绑残片解锁**:活动可以**增加**相遇概率,不得将任何残片首发设为"仅活动期间可发现"。

#### 6.1.4 与经济边界的关系

- 残片 = 持久层资产(economy-canon §3.1):永不 wipe + 永不 vault + 永不 FOMO。
- 即使未来引入"赛季 wipe",残片进度、解码等级、揭示状态**绝对不重置**。
- 跨季奖励不得包含"独占残片";赛季回归叙事化用结构性身份("重返函馆者"),不用内容独占。

#### 6.1.5 例外与变更治理

- **唯一例外**:残片文本有事实性 lore 矛盾、违反纪元一览表定义、或含敏感内容时,可以**修文不删片**。编号、解码等级、玩家记录保留,仅替换文本字段。修订 commit 标 `lore-revision` 并记录于剧情轨 log。
- 本条款任何放宽必须:单开 issue @narrative owner / 同步修改本节 / 同步修改 economy-canon §8 / 公开 changelog。
- **未走流程的任何"事实上 vault"**(如悄悄把权重设 0)= 违宪,PR 必须 block。

#### 6.1.6 监测与执行

- healthcheck 残片健康度含 F01-F15 全量首达率监测,任何残片连续 14 日 0 首达触发 🟡(信号是"调权重/三链",不是"下架")。
- F01 首达率红线:新玩家首周触达 ≥80%,低于 70% 触发 🔴。
- PR 审查清单:改 `fragment_pool` / `fragment_recipes` / `discoverFragment` / `loreInjections` 的 PR 须勾选"未删任何 F01-F15 行 / 未减合成边 / 未引入限时机制"。

### 6.2 经济与持久边界(research-2026-05-28-B P0)

权威机制见 [docs/economy-canon.md](./economy-canon.md)。对叙事的反向约束:

- **残片解码进度 / chamber 访问历史 / 职业池解锁 / 死亡日志 = 持久层**:赛季 wipe 不得抹除;任何文案不得暗示"赛季结束你的发现会消失"。**KALEIDO 的 UI 解锁集(渐进披露)同属持久层**——已点亮的界面是玩家的认知资产,permadeath 与收敛不回收(05-progressive-disclosure §1.1)。
- **点数余额 / 装备实例 / stash = 可重置层**:叙事可用"补给周期/物资循环"包装,不得叙述为"玩家的记忆或功绩"。
- **赛季奖励不得提供战斗优势**;回归玩家称呼用结构性身份,不写数值优越。
- **跨季残片不得 FOMO 化**(与 6.1 同源)。

### 6.3 未来纪元(第 7 纪元)触发条件

由四种结局(崩解 / 清算 / 合流 / 探索)决定——多人线(深界时代)机制。游戏内任何提及"下一纪元"或"未来"的文案,需回到结局触发设计核对,避免泄露玩家未达成的结局。(ver2「终末」的结局变体归一待 Kanata 钦定。)

### 6.4 机制/叙事双频道隔离(research-2026-05-29-C P1)

> **宪法级别条款。** 硬规则一句话:**叙事可晦涩、机制必清晰**。

#### 6.4.1 两个频道的定义

- **叙事频道(可晦涩)**:残片正文、loreInjection 短句、chamber/关卡环境描述、KALEIDO nar_line 与题记。只**描述世界**,允许留白、悬疑、不解释。
- **机制频道(必清晰)**:玩家"该怎么玩"的全部信息——目标 / 门槛 / 威胁 / 数值,一律走**结构化 UI**。

#### 6.4.2 硬规则

- **lore 文本禁止承载机制指令**:任何叙事文本不得写"往左走 / 先用 X / 你的目标是 Y"式操作指令。
- **机制引导必须有独立于 lore 的清晰频道**:操作提示由结构化 UI(按钮/数值/标签)承载。
- **禁止"解析 lore 文本 → 驱动机制"的代码路径**:机制值只能来自结构化字段。
- **KALEIDO 渐进披露的延伸**(2026-07-07):UI 可以晚到,但**不能晚于需要它的机制**——任何能伤害玩家的机制,其读数 UI 必须先于首次伤害解锁(05 §1.2 硬时序法则);"还没解锁所以看不懂怎么玩"与"还没解码所以看不懂故事"是两回事,前者违宪。

#### 6.4.3 为什么晦涩留在叙事侧

- 叙事晦涩是留存资产(渐进揭示、"不解释只描述");机制晦涩是纯流失。频道焊死隔离 = 保住前者优势 + 后者风险归零。

#### 6.4.4 与既有条款的关系

- 渐进揭示只作用于**叙事频道**;任何阶段玩家的**机制频道始终全清晰**。困惑可以指向"故事还没拼齐",绝不能指向"我不知道这个按钮干什么"。

#### 6.4.5 监测与执行
