**两处对齐**:

### 1.1 ✅ 已裁「甲」:step0 首搜就掉血,`hp_bar` 挂载点不动(🧭 · 2026-07-22)

**原矛盾**:12 §1.1 写「step0→1 期间掉血」⟹ 读起来 step0 首搜不掉血;但 N3 `hp_bar` 挂在「首次 search/before」、说「**损耗从这一下开始算**」——**那句在它自己触发的那一拍上是假的**。

**裁定 = 甲**(掉血含首搜),两条理由:
1. Kanata 原话本就含首搜:「**从第一次开始搜索后**,每次搜索都会同步失去 HP」。12 §1.1 的措辞是笔误,🧭 改文档。
2. **更硬**:`06 §1.3` 硬时序法则 —— 污染熔毁 / Ω 超时 / 收缩等**非战斗死亡向量在任意动作上结算,含首搜**(引擎当初正是为它们才把 `hp_bar` 从 `fight_start` 提前到首次 search)。挪走 ⟹ step0 那一搜成为**能死人但没有读数要约**的窗口。拍板级铁律,不为文案让路。

⟹ **`hp_bar` nar_line 一字不改**,「损耗从这一下开始算」在甲下为真。

### 1.2 🔴 裁甲带出的连锁:step1 入场行第二句变假了(📖 自查)

裁甲 ⟹ 代价**从 step0 首搜就开始**。那么 §3.1 原写的「**从这儿起**，每翻一下都得付点什么」在进入 step1 那一拍是**假的**——不是"从这儿"起的。
(我原先那条「裁甲则此句保留」的条件注记**写错了**:我当时按"甲 = 两句各管一段"推,实际甲让两句**抢同一个开始**,而后发的那句必假。)

⟹ **§3.1 第二句删**。step1 入场在机制上**没有新东西开始**,不该宣布任何"从此刻起"。

**✅ ⚙️ 已定:同率 `d=4` 贯穿 step0/step1**(2026-07-23)⟹ **第二句永久删除**,入场只留场景行。

> ⚙️ 采纳的是第二条理由,因为它指向他们自己的公式:**余量锚点 `beats =(hp + 药瓶数×30)/ 每搜掉血` 假设单一费率**,两段费率会让"还能撑几拍"在跨段时**跳变**,而那个数是四档阈值的**唯一依据** ⟹ 分段费率直接把仪表打坏。
> (另一条也认:🧭 说甲的意义是"**你做的第一件事就要付代价**",step0 减免正好把这句话打折。)

> step0 内 **N7 阈值线索仍不发**:首搜之后余量 ≈ 满,不到任何一档。

## 2. step1 载体形态 —— ✅ **已批准 C 案**(🧭 · 2026-07-22;A/B 存档备查)

> **批准附带一条我没意识到的定性**:C 案不只是载体方案,**它是整个 Diegetic 教义里第一个真正的 `operate` 实例**。Kanata 定 operate 时的原话是「玩家对场景的交互要**确实给场景添加改动**」「可以是**永久性改动**,比如玩家开了灯,死了,下一次到达这个房间时灯就是开着的」——「关上」逐条命中:世界内动作 ✓ 真改场景状态 ✓ 跨单位持久 ✓ 进度关键件 ✓ 走点击 ✓。
> **保留 seq2 安全首战作为"路上的东西"(非门槛)一并批准。**

**共同前提**:step1 = 探索求生 + **每搜 −4 HP** + 找药(⚙️ 曲线);**L 推荐 30 搜、硬上限 ≈40**;载体内**必须有那个能当安全区的地方**。

| 案 | 形态 | 优 | 劣 |
|---|---|---|---|
| **A · 纯探索求生** | 移除全部战斗;唯一压力源 = 掉血时钟 | 最贴 step1 核心;⚙️ 曲线不必重算;最省 | `combat_panel`/`stance_ui` 无处解锁;30 搜可能单调 |
| **B · 弱遭遇非门槛** | 探索为主,偶发弱敌(可打可绕),战斗**不是**通关条件 | 保住 combat 解锁点 + 变化 | 战斗叠加掉血,⚙️ 需重算曲线 |
| **C · 关门即里程碑** ★**推荐** | 探索求生 + **保留一次安全上演的弱遭遇(非门槛)** + 终点是**一个能关上的地方**;**step1 达成 = 玩家把它关上**(不是"走到") | 见下 | 需 🔧 支持「操作」类 step 触发 |

### 2.1 为什么推荐 C

1. **Kanata 已给了这条路**:12 §1 明写 step 可由「**做了某个特定操作**」推进 —— 里程碑不必是位移。
2. **它让"留下了什么"成立**:安全屋不是玩家**碰到**的,是玩家**关上的**。N8 §6 说这是"整个游戏第一个我留下了什么的时刻" —— 只有当那个动作是**玩家做的**,这句话才为真。
3. **与 diegetic 教义同构**(11 法则二):**你在世界里做了一个动作,世界因此改变** —— 关门是这条法则最干净的一次示范,而且是**进度关键件**,天然走点击。
4. **文案已经在那儿了**:我 N8 §6 写的「**这地方能关上。记下了。**」——「能关上」原本是描述,在 C 案里它**变成了那个动作**。
5. **`关上` 是天然的 `action.word`**:世界内动作、删除测试通过、与现有 14 词零撞。
6. **它解释了后来者为什么回得来**:门是关着的,**是上一台关的**(N8 §5 遗留层的最强形态)。
7. **保留 seq2 的安全首战资产**:那场弱遭遇(算术保证必胜)作为"路上的东西"仍在,只是**不再是门槛** —— combat 解锁点保住,seq2 已入库数值不浪费。

### 2.2 C 案的判定链(给 🔧/⚙️)

```
探索(每搜 −4 HP,找药)→ 发现「能关上的地方」(可交互词:关上)→ 玩家点「关上」→ step0→step1 推进(一次性)
                                                              ↘ 同拍:存档点首次提交
```
- **step 推进** = 一次性、不回滚;**存档点提交** = 此后每次回来都提交(12 §3)。两者在这一拍**同时发生但语义不同**,文案分两套(§4)。
- 「发现那个地方」与「关上它」是**两拍**:前者是诱饵/发现(可能被错过 ⟹ 走 N7 §2.4 承重诱饵),后者是里程碑。

## 3. step1 文案(按 C 案 · 改案则调整)

### 3.1 进入 step1(step0 首次搜索之后)

> 供电只够这些。往里的路还通着，风是从那边来的。

- ⚠ **首句原写「往里的门开着」,已改「路还通着」**:step1 的终点是**那扇能关上的门**(§3.3),开场就出现另一扇"门"会让玩家把两者认成一个,还可能对着它找点击。**「门」这个物件在 step1 里只归安全屋一处**——它出现即意味着终点到了。
- ⚠ **原第二句「从这儿起，每翻一下都得付点什么。」已删** —— 裁甲后代价从 step0 首搜就开始,这句在此刻为假(§1.2)。掉血的世界内交代**已由 `hp_bar` 的 nar_line 在首搜那一拍完成**,此处不得重复宣布。
- ⟹ **step1 入场只有场景行,不宣布任何"从此刻起"。**(若 ⚙️ 定 step0 更轻,按 §1.2 复活为「往里的每一下，比外头沉。」)

### 3.2 探索求生期

- **阈值线索**走 N7 §3.1(状况四档 × 四态,锚点 = 有效剩余拍数)。
- **找药**:修补剂拾得走 N5 道具文案 + `inventory` auto 浮现(N3 §1)。
- **氛围行**:复用 N4 seq1-2 `ambient` 池(去撞行后)。

### 3.3 发现「能关上的地方」(诱饵拍 · 可被错过)

**首现**(发现那一拍):

> 前面有扇门。完好的，能关上。

**复现诱饵**——本条是**承重 key**(不关门 = step1 永不达成 + 持续掉血),按 N7 §2.4 承重档 M 5→(16 拍)3→(32 拍)2,**并需两组平行措辞**(同 move_btn,见 N7 §2.4 会签):

| 档 | 曝光驱动(看见了但一直没关) | 余量驱动(才发现没多久但快没了) |
|---|---|---|
| 1 | 「那扇门还开着。」 | (同) |
| 2 | 「门在那儿，一直没合上。」 | 「那扇门还开着。外头耗不起了。」 |
| 3 | 「门一直开着。你就在它边上。」 | 「门还开着。你耗在外头了。」 |

- 全部四句 + 首现均含**「关上」/「开着」/「合上」**的同一物件,可交互词恒为**「关上」**。
- ⚠ **档3 曝光组用「你就在它边上」而不是再报一次血**:≤4 拍时 hp 档3「撑不住几下了。」同拍齐发,两条都喊濒死是浪费(同 N7 move_btn 的处置)。余量组则明写「耗在外头」,因为它的触发因就是余量。
- ⚠ **叙述里一律用「合上」,可点的只有「关上」**:两词分工是**故意的**——`一词一key` 要求可交互词词面唯一,所以描述门的动作时避开「关上」,否则玩家会对着不可点的字去点。

### 3.4 关上它 = step1 达成(里程碑拍)

> 门合上了。外面的声音停在门外。
> 这地方能关上。记下了。

- 保持 N8 §6 的「只登记不承诺」口径(真承诺版等安全屋跨 run 持久落地,🧭 §6.1)。
- **不煽情**:重量靠「外面的声音停在门外」这个可验证事实。
- **不得暗示存档/补给**(🧭 明禁)——尽管这一拍机制上确实同时提交存档点(§4)。
- ⚠ **「能关上」的时态是故意的,别当 bug 改**:门此刻已经合上了,按现场写该是"关上了"。但这一句不是描述现场,是**往登记里记一条这个地点的持久属性**——"此处可闭合"。记的是**给后面的单位看的**,不是给此刻的自己看的。这正是值班的该做的事,也是它能在 N8 §5 遗留层里被下一台读到的原因。

## 4. 「第一次关上」vs「又回来了」——两套文本

12 §3 明确:**第二次之后到达,只有存档点提交,step 不动**。二者频率与语义完全不同:

| | 触发 | 频率 | 文案 |
|---|---|---|---|
| **第一次关上** | step1 达成 | **一次性** | §3.4(里程碑) |
| **又回来了** | 此后**每次**回安全区(死区逼玩家每天回) | **高频** | **本批不写**,结构预留(下) |

**「又回来了」的结构预留**(高频 ⟹ 必须能重复读不腻,同 N8 按拍分池思路):
- 三拍:**门的状态** + **这一趟带回什么** + **外面的变化**。
- 变化来自**世界事实**(N8 C 加法轴),不来自口吻递减。

### 4.1 ✅ 已裁:**门永不复原**(🧭 · 2026-07-22)

不是白名单选择题,是结构必需:**门是存档点锚**。若它随结构重置复原,存档点的世界内理由当场蒸发 —— N8 那句「后面来的找得到这儿」变成假陈述,而 §2 刚用"门是上一台关的"解释了跨单位持久。

⟹ 在 `11 §8.2` 的模型里,**安全屋的门 = 恢复周期「永不」**。
⟹ **「还关着」是真的,可以放心写。**

> **恢复周期本身就是分量刻度**(Kanata 已定):开盏灯**次日**复原 · 炸毁区块**几天**复原 · **门永不**。⟹ 📖 记一条通用写法:**一个改动的恢复周期越长,叙述越该少形容多登记** —— 越持久的东西越不需要修饰来证明它重要。

## 7. `loadout_panel` 改余量框架(⚙️ 提案 · **待 🧭 批准重锚,未批不落 N3 表**)

**⚙️ 给的理由比我的硬**:我原本只说"若扩容变成主要升级路径就该改";⚙️ 指出 **step1 里它本来就是唯一碰得到那口钟的升级** ——

⟹ **「结实 / 耐打」在 step1 是错误的仪表** —— 与"血量百分比是错误的仪表"同一个道理:它描述**抗打击**,而玩家实际买到的是**时间**。

| | 现行(冻结中) | **提案** |
|---|---|---|
| nar_line | 「这一件算在身上了。**比刚进来时结实了一点。**」 | 「这一件算在身上了。**翻出来的，换成了往后多撑的几下。**」 |

- 可交互词仍是**「身上」**,首句不动(注册表已冻结的部分零改)。

- **「换成了」写的是转化(材料 → 时间),不是牺牲** —— 故它**无论有没有机会成本都成立**(见下)。
