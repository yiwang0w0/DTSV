## 1. seq1 · search(觉醒关 · 纯搜索零战斗)

**结构摘要**(D6 §2):archetype=search · mode=standard · exit=survive_turns=3 · combatSetup=null · pollution 0(chamber id1)。保底掉 恢复品(id27)+ 配方材料(id13)+ 随机补给(id22)。**这是玩家第一次「搜索→日志醒来→拿到东西」的地方**——首次搜索即点亮 `hp_bar`(首搜前·契约改挂)+ `log_panel`(首搜后)+ `inventory`/`craft_btn`(吃到掉落),清关后 `move_btn` 亮起。
**chamber legacy 名**「外环-巡查节点」= DB 旧多人标签,**不采**;kaleido 命名如下。

| 文案槽 | 供稿 |
|---|---|
| `name` | **外圈 · 停摆段** |
| `description` | 平台最外的一圈。事故之后,这里先停下来。<br>灯还亮着,别的都停了。<br>能翻的东西不少,没人清点过。 |
| `enter_text` | 灯先亮,然后是你。<br>这里是外圈,停摆的一段——事故之后最先安静下来的地方。<br>东西散了一地,没人收。<br>能做的只有一件:翻找。 |
| `ambient`(搜索时随机·值班的) | ①「翻找完毕。找到一件还能用的东西。」<br>②「这一格空了。换一处。」<br>③「有东西卡在缝里。抠出来了。」 |

| 敌人命名 | **无**(零战斗)。若引擎随机刷怪,须按 ⚙️ §8 hook④ 压制;文案侧不提供敌名。 |

**与解锁链/N3 的咬合**:
- `enter_text` 的最后一句「能做的只有一件:翻找」= 把玩家推向**唯一可用 UI(搜索钮)**;紧接 N3 `search_btn` 开场行「供电恢复。可用功能:一项。」落日志(两者同刻·不同挂载:enter_text=场景板,nar_line=日志行,**已去重不重述"供电恢复"**)。
- **首次搜索前** `hp_bar` 上线(06 契约改挂 `search`/before,§1.3)→ N3「你动起来了。往后有损耗,得盯着了。——已开放:状况读数。」;理由:污染熔毁/Ω 超时/收缩等**非战斗死亡向量**可在任意动作(含首搜)结算,状况读数须在**第一次搜索**就位、而非等到 seq2 战斗。seq1 首关 `pollution=0`(非即死),满足契约内容不变量。
- 首次搜索后 `log_panel` 亮 → N3「开始记录。——从你翻找的这一下算起。」;`ambient①` 即那一下的搜索结果。
- 保底吃到 id27 → `inventory` 亮(N3「你需要地方放它。——已开放:随身储物。」);吃到 id13(结构碎片=配方材料)→ `craft_btn` 亮(N3「这两样,拼得到一起。——已开放:动手做。」)。
- 清关(survive_turns=3 达成)→ `move_btn` 亮(N3「这一段的事,办完了。——已开放:前进。」)。

## 2. seq2 · encounter(首次战斗 · gauntlet 2 波 · 安全上演)

**结构摘要**(D6 §3):archetype=encounter · mode=gauntlet(waves=2, waveHeal=15) · exit=survive_turns=4 · pollution 35(chamber id5)。敌 = id8 手写弱化值(hp18/atk6/def2),**算术保证必胜**(死亡下界 hp92,20000 seed 零非胜)。点亮 `combat_panel`(遭遇时)/ `rules_card`(入关前);**`hp_bar` 已在 seq1 首搜上线**(06 契约改挂,见 §1),此处不重复解锁。
**chamber legacy 名**「锚点-残响游走区」= DB 旧多人标签,含禁用词「残响」,**不采**;kaleido 命名如下。

| 文案槽 | 供稿 |
|---|---|
| `name` | **往里 · 承重段** |
| `description` | 往里的第一段。这里在承重。<br>空气不干净了,读数开始跳。<br>有东西在动,不止你一个。 |
| `enter_text` | 你往里走了一段。外圈的安静,到这儿没了。<br>脚下开始承重。你踩的这层,扛着上面。<br>读数不稳,盯着它。前面有动静。<br>这一段的规矩和外圈不一样,已经写在门口了。 |
| `ambient`(战斗区·值班的) | ①「读数在跳。别信它跳的那一下,信它停的那一下。」<br>②「它先看见了你。这里往后都这样。」<br>③「打完这一波,还有一波。」 |
| `ambient`(稀有残页·留下的字) | ④「前面那段,昨天还不在这里。」<br>⑤「别站在承重的缝上打。我站过。」 |
| `combatSetup.enemy.name` | **「那东西」**(指示代词式裸描述·占位防回落·见下 §3);**严禁**填 id8 legacy 名「残响低语」。 |

**硬时序法则咬合(D6 §3.1 / 05 §1.2 / 06 契约 §1.3)**:
- **hp_bar 已在 seq1 首搜上线**(契约改挂 `search`/before,早于一切伤害/死亡向量);seq2 `enter_text`「读数不稳,盯着它」是**引用已开的状况读数**,非在此开启。
- seq2 的 before-解锁 = `rules_card`(`move`/before):「规矩……写在门口」引出 N3「这一段,规矩不一样。——已张贴在门口。」入关前展示。
- 「前面有动静」= 前瞻(遭遇尚未建立)→ 遭遇建立时 `combat_panel`(`fight_start`/after)上线(N3「有东西在动。它先看见了你。——已开放:自卫。」)。
- 次序:(seq1 首搜 → hp_bar)→ 入关 seq2 → rules_card(before)→ 遭遇 → combat_panel。首害之前 hp_bar 早已就位,硬时序法则满足。
- gauntlet 两波:`ambient③`「打完这一波,还有一波」为波次体感,与 rules_card 波次规则同频。
- `waveHeal=15` 的波间回复:可不配文案(纯机制),或值班的一行「一波结束。下一波在等。」(备选,🎨 取舍)。

## 3. 敌人命名规约(名随物后 · 本批适用 + 未来 payoff 登记)

- **seq2 首遇 = 描述制,无正式名**(N1 §3.2 名随物后 + §5 敌对物前期只有描述)。玩家看到的是行为(「有东西在动」「它先看见了你」),不是名字。`combatSetup.enemy.name` 填 **「那东西」**——它是**指示代词式裸描述,不是专名**(反复出现仍读作"那个东西",不会固化成名字),作用是**占位防回落**:若留空,现引擎(D6 SQL 注)会回落 `npc_pool.name`=「残响低语」,而「残响」是禁用词,反而漏名。**故本批一律填「那东西」**;**仅当 🔧 确认 combat 面不回落 npc_pool.name 之后**,方可改留空、让指称完全走 combat_panel nar_line。此为本字段唯一口径(§2 表 / §4 入库映射同此)。
- **禁用**:id8 的 npc_pool legacy 名「残响低语」——「残响」是 N1/N3 §4 禁用词,须**见过 3 次后**才可命名。实现侧注意:kaleido combat 面显示 `combatSetup.enemy.name`(=「那东西」),**不得**回落 `npc_pool.name`(=「残响低语」)。
- **未来命名 payoff 登记**(不占本批):玩家在多关/多 run 中第 3 次遭遇此类活动体后,某个中期节点第一次让系统写下它的名字——**那一刻本身是奖励**(N1 §3.2)。名字(以及是否就叫「残响」/另起 kaleido 专名)留给 seq3+ 结构与 Kanata 命名拍板;在此之前一律描述制。
