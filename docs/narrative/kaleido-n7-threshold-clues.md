# KALEIDO · N7 阈值叙事线索 + 发现诱饵体系(叙事兜底 · Diegetic UI 教义 §2)

> 2026-07-22 · 📖 剧情轨 · 依据 `11-diegetic-ui-doctrine.md`(Kanata 长期铁律)。
> **定位升级**:叙事**不是氛围,是替代仪表盘的信息通道**——没有 UI 的玩家靠这些字活着(法则一:功能常在,观测要争取);同时是**发现的诱饵**,防止"太隐蔽 = 永远发现不了 = 功能白做"。
> **范围**:体系设计 + 可落地首批(状况 / 污染);体力·损毁度·磨损度**机制未实现**(教义 §4),只出骨架与措辞方向。
> **共同口径**:值班的主声线 / 全角标点 / 少专名 / **只写可验证的行为或状态事实**(不推测、不预测、不揣测玩家内心)/ **绝不点名 UI**(不出现"面板/血条/读数/打开")。
> **拟人化边界(与 N3 共享)**:工程体是**机械自感**——接缝、发涩、发沉、在响、渗、舱、缝;**不写**呼吸、咳嗽、口袋、心跳。

---

## 1. 三种「没有 UI」——叙事完全不同(教义法则三)

| 态 | 玩家处境 | 叙事职责 | 措辞法 |
|---|---|---|---|
| **从未发现** | 不知道有这东西 | **诱饵**:让"能不能确认一下"的念头生出,并**给出可点的词** | 悬念 + **嵌 N3 §1 的可交互词**(如「状况」)——线索本身即发现路径 |
| **曾有·被夺走** | 曾看得见,现在瞎了 | **压迫**:点出落差 + 把判断权交回玩家 | 明写"看不见了",后接**状态事实**;⚠ **不得写成祈使**(「自己数」是命令,违双频道) |
| **临时·被遮蔽** | 暂时不准/闪 | **干扰**:不稳 + 会回来(不制造永久绝望) | 写"跳/信不过",**仍按档给信息**(见 §3.1) |

- **三态不可用同一句**。诱饵型说"没了"会凭空制造从未存在的落差;失落型说"你不太确定"太轻,浪费掉夺走的压迫。
- **⚠ 遮蔽态不得比被夺走态信息更少**:它是较轻的状态,却最容易被写成一句通用行——那会让玩家在遮蔽期完全无法判断恶化还是好转。故遮蔽态**也分档**。

## 2. 体系设计

### 2.1 覆盖对象(两类)

| 类 | 对象 | 为什么要 |
|---|---|---|
| **A 状态阈值线索** | 状况(hp)✅ / 污染 ✅ / 体力·损毁·磨损(待机制) | 观测层缺位时的**信息通道** |
| **B 未发现 UI 的复现诱饵** | N3 §1 的 14 个 ui_key | 首现 nar_line 是**一次性**的;错过即永久发现不了 ⟹ 法则二退化成运气检定。教义 §2 要求**持续暗示** |

### 2.2 状态阈值:分档与触发

- **每状态 3 档 + 1 恢复档**:档1(注意到)/ 档2(明显·开始影响)/ 档3(危急)/ 恢复(回升一档)。
- **跨档边沿必发**:信息通道的可靠性底线。
- **档内稀发**:停留同档时每 N 次**合格动作** ≤1 条(建议 **N=5**)。
- **恢复也发**:双向,否则玩家只知恶化不知好转。
- **⚠ 合格动作定义(给 🔧)**:`search` / `move` / **战斗中的一次己方行动**(非一个回合内的每次结算)/ `craft` / `item_use` **各计 1 次**;**打开面板不计**。此定义不明确会让密度差 3-5 倍。
- **⚠ 并发与不丢弃(修正旧稿冲突)**:「每动作 ≤1 条」**只约束档内稀发线索**;**跨档边沿触发不受此限**。同一动作多状态同时跨档时按 **状况 > 污染** 排序,首条本拍发出,**其余顺延至下一个合格动作(入队,不丢弃)**;任一状态**跨入档3** 时允许同拍并发,不入队。
  - (旧稿「每动作 ≤1 条 + 边沿只触发一次」会让污染的跨档信息**永久丢失**——污染无 UI,丢一条即丢一整档可观测性。)
- **⚠ 队列不得发过期档**:入队项须带「状态 + 入队时档位」,**发出前重校验当前档** —— 不符则丢弃或换成当前档文案。**发一个过期档位比丢一条更坏**:玩家会据此做致命决策(读到「动作慢下来了」而实际已濒死)。同一状态队内**只保留最新一条**;恢复边沿与恶化边沿**不得倒序发出**。
- **诱饵让位**:§2.4 复现诱饵**优先级低于**阈值线索,二者共享每拍预算——同拍冲突时先发阈值线索。
- **⚠ 与既有事件行同拍**:阈值线索**不与叙述同一事实的事件行同拍**(如 hp 跨档1 与 N2 受伤行「你受伤了。不重。」)——同拍时**优先事件行,阈值线索顺延**,避免两行说同一件事、稀释信号。

### 2.3 措辞四法

1. **给感受,不给数字**。数字归机制频道。
2. **绝不点名 UI**(含"读数"这类 UI 名)。
3. **未发现态必须嵌可交互词**——诱饵与发现路径合一;词用 N3 §1 的那一个,**四态同词**。
4. **越危急越短**。紧迫靠句长,不靠形容词。

### 2.4 未发现 UI 的复现诱饵(新 · 补法则二的兜底)

- **⚠ 前置条件**:仅对「**首现 nar_line 已发出、但其可交互词未被点击**」的 ui_key 发诱饵。**首现尚未触发的 key 不发** —— 否则会在玩家手里还没材料时就播「这几样摆在一块儿…」、还没进规则关就播「门口那张告示，还没读。」,既是**假陈述**(违可验证事实)又**提前剧透后面的关**。
- **规则**:对符合上条的 ui_key,在**其相关动作**发生后按 **每 M 次 ≤1 条** 补一句复现诱饵;**M 随未发现时长递减**(隐蔽度随时间自动衰减 —— 这是"太隐蔽 = 功能白做"的兜底闸)。
- **⚠ M 的递减单位 = 合格动作拍数,不是关数**(⚙️ 2026-07-22 会签抓出):step1 载体只有 1-2 关,按关计的档位**永远不会触发**,M 恒为初值,兜底闸不转。
  - 常规 key:**初 8 → 未发现满 16 拍降 5 → 满 32 拍降 3**。
  - 承重 key:见下(更陡)。
- **措辞**:比首现句**更直白但仍不点名 UI**,且**必须含该 key 的可交互词**。
- **首批(高风险 key —— 首现最易错过的几个)**:

| ui_key | 可交互词 | 复现诱饵句 |
|---|---|---|
| `move_btn` ⚠**承重** | 出口 | 「出口还开着。这一段没别的事了。」 |
| `hp_bar` ⚠**承重** | 状况 | 「自己的状况，一直没细看过。」 |
| `craft_btn` | 拼起来 | 「这几样摆在一块儿，拼起来该是个东西。」 |
| `rules_card` | 告示 | 「门口那张告示，还没读。」 |
| `stance_ui` | 架势 | 「它换了几回架势，你都没跟上。」 |
| `loadout_panel` | 身上 | 「身上装了几件，说不清具体几件。」 |
| `prep_readout` | 掂量 | 「够不够，一直没掂量过。」 |

| `convergence_preview` | 合账 | 「这一趟的账，还没合。」(收敛页前复发) |

- ⚠ **`convergence_preview` 必须配**:它是全表**最一次性**的一条——只在 boss_kill/死亡那一拍浮现、相关动作**不复发**,错过即整个 run 无第二次(§5 注记还规定首次解锁只由 boss_kill 授予)。旧稿把它划进"高频豁免"是错的。
- ⚠ `turn_counter` 与 `level_header` 原定**同拍**浮现(一拍两个新词,结构上最易漏其一)——已在 N3 §1 改为**隔一次 move 再发 turn_counter**,消除该风险,故二者暂不配诱饵。
- 其余 key(search_btn 恒最低隐蔽度不需诱饵;log_panel/combat_panel 相关动作高频、首现难错过)**暂不配**,按实测补。
- ⚠ **`inventory` 已移出诱饵池**(Kanata 定:**物品栏走 auto,不需要点** —— 全表唯一例外)。理由自洽:它是**药的载体**,若走点击,诱饵曲线就得跑赢它自己所保护的那个掉血时钟,**自指**。⟹ inventory **不需要"未发现态"兜底线索**,该档砍掉;N3 §1 其 `action.word` 同步标 auto。

> ### ⚠ 诱饵 = 承重结构,不是锦上添花
> Kanata 定「**进度关键件全走点击**」⟹ **`move_btn` 的「出口」玩家不点就真的过不去**。首现那一行若被错过,**只有复现诱饵能把他救出来** —— 诱饵在这里不是氛围补充,是**卡关的唯一出路**。
> ⟹ 承重 key(现为 `move_btn` / `hp_bar` / **`关上`〔step1 安全屋 · N9 §3.3〕**)的诱饵:**M 递减更陡且按拍计** —— **初 5 → 满 16 拍降 3 → 满 32 拍降 2**;且**不受 §2.2「诱饵让位于阈值线索」的让位规则约束**——承重诱饵与阈值线索同拍时**并发**,不顺延(承重的东西不能排队)。

> **⚙️ 会签补充的实现口径(2026-07-22 · 采纳)**:余量 ≤4 拍时 hp 档3 与承重诱饵档3 **两条都要发,不得互相抑制、不得合并** —— 它们是**互补的两个信息:一条报身体,一条指出路**。
> ⚠ 我先前说的"浪费一拍"指的是**别让两条都去报身体**,不是"只发一条";⚙️ 的理解正确,此处定死免得 🔧 误读成二选一。
> ⚠ **并发时的顺序 = 先身体、后出路**(与 §2.2「状况 > 污染」同一排序原则)。反过来会读成:游戏先回答一个你没问的问题,再告诉你要死了。
>
> ### `move_btn` 的三档递进措辞(⚙️ 会签定:措辞也升级,不只频率变密)
> 旧稿只让 **频率变密**(M 递减),**措辞恒定**——对"卡住即掉血"的键不够。`move_btn` 配三档,**按曝光次数升档**(曝光 1-2 = 档1,3-4 = 档2,5+ = 档3):
>
> **⚠ 两组平行措辞(⚙️/🧭 会签:档位可被"余量驱动"提前跳档)**
> 🧭 指出 M&lt;N 是**静态**不等式(N 从满血算),而卡住可发生在**任何血量**:玩家 35 血 0 药卡在「出口」上只剩 ~9 拍,而按曝光算的档3 要第 21 拍才到 ⟹ **这一局跑不赢**。
> 裁定:**承重 key 的诱饵档 = max(按曝光次数的档, 按余量拍数反推的档)**(余量 ≤10 拍直接给档2、≤4 拍直接给档3)。
> ⟹ **📖 核过:原三档扛不住被提前跳档** —— 档2「**这一段翻遍了**」与档3「**再翻也还是这些**」都对**搜索次数**做了事实断言;才翻 5 拍就跳档时它们是**假陈述**(违"只写可验证事实")。故按**触发因**分两组:

> | 档 | **曝光驱动**(翻了很久还没走) | **余量驱动**(没翻几下但快没了) |
> |---|---|---|
> | 1 | 「出口还开着。这一段没别的事了。」 | 「出口还开着。这一段没别的事了。」(同) |
> | 2 | 「这一段翻遍了。出口一直在那儿。」 | 「出口还开着。这一段耗不起了。」 |
> | 3 | 「再翻也还是这些。出口，一直开着。」 | 「出口一直开着。你耗在这儿了。」 |
>
> - **余量组刻意不复述濒死**:≤4 拍时 hp 档3「撑不住几下了。」会**同拍齐发**,两条都喊"你要死了"是浪费;余量组的职责是**把出口指成出路**,不是再报一次血。
> - 两组同档位、同可交互词「出口」,只换语境;均为可验证事实、非命令。
>
> **⚠ 余量跨档时绕过 M 间隔,强制发一条**(⚙️ 加,📖 认):诱饵仍按每 M 拍一条,而玩家掉到 ≤4 拍时只剩 4 次搜索,下一次发射可能要等 5 拍 ⟹ **他到死都没看到档3**。这正是本文 §2.2 已立的「**跨档边沿必发**」原理,搬到承重 key 的诱饵上。
>
> - 三档都是**可验证事实**(搜索无新物 / 出口开着),**不是命令** —— 越到后面越直白,但始终不越双频道、不点名 UI。
> - **到最直白档(档3)≈ 第 21-24 拍**(M=5 曝光 3 次至拍 15,M=3 后拍 18/21 达曝光 5)—— 远早于 ⚙️ 实测的"卡住不动约第 144 搜才死",**余量 ~6×**。
> - `hp_bar` **不配递进措辞**:它有**双通道**(§3.1 未发现态四档阈值线索已逐档嵌「状况」+ 本节诱饵),不像 `move_btn` 只有诱饵这一条命。

## 3. 首批文案(可落地 · 状况 / 污染)

> 档位阈值由 ⚙️ 定(下列百分比为 📖 建议锚点)。**四态同词 = 「状况」**。

### 3.1 状况(hp)

> **⚠ 阈值锚点已定 = 有效剩余拍数,不是血量百分比**(⚙️ 2026-07-22 会签定案):
> ```
> beats = (当前 hp + 药瓶数 × 30) / 每搜掉血
> ```
> **为什么不用百分比**:它分不出「40 血 + 3 瓶 = 安全」与「40 血 + 0 瓶 = 要命」——而这两种处境该说的话**完全不同**。余量拍数是"**余量薄厚**"的字面实现,且 runtime 可精确算。
> **实测(⚙️ harness,曲线 -4HP/搜 · 每 16 搜保底 1 瓶)**:正常游玩前 30 搜触发率 **档1 91% / 档2 56% / 档3 18%** —— 档1 几乎每局都尝到,档2 过半真紧张过,档3 偶发但真吓一跳;**正常推进仍不死**。旧的百分比锚点下这三档在常规游玩里是 **0% / 0% / 0%**(= 该通道等于不存在)。

| 档 | 阈值(**有效剩余拍数**) | 常态(已发现) | 未发现(嵌词·兼诱饵) | 被夺走 | 临时遮蔽 |
|---|---|---|---|---|---|
| 档1 | **≤ 20 拍** | 「有几处发涩。还不碍事。」 | 「有几处发涩。自己的状况，说不好。」 | —(夺走多发生在危急段) | 「状况在跳，信不过。刚才那下不算重。」 |
| 档2 | **≤ 10 拍** | 「动作慢下来了。接缝在响。」 | 「动作慢下来了。状况到底还剩多少，你没看过。」 | 「看不见状况。只知道比刚才慢。」 | 「状况在跳。响声是真的。」 |
| 档3 | **≤ 4 拍** | 「撑不住几下了。」 | 「撑不住几下了。状况看不出。」 | 「撑不住了。看不见还剩多少。」 | 「状况跳得读不出。响声压过了别的。」 |
| 恢复·**修好了** | 回升一档(hp 升) | 「响声轻了些。」 | 「响声轻了些。状况缓过来一点。」 | 「沉的感觉退了一点。」 | 「跳得慢了些。响声也轻了。」 |
| 恢复·**多了瓶药** | 回升一档(**药瓶数升·hp 未变**) | 「手里多了一瓶。撑得久一点了。」 | 「手里多了一瓶。能撑多久，还是没数。」 | 「手里多了一瓶。剩多少还是看不见。」 | 「手里多了一瓶。跳的还在跳。」 |

- **⚠ 恢复档必须分两因**(📖 核公式时发现):新锚点把 `hp` 与 `药瓶数` 一起算进余量 ⟹ **捡到一瓶药也会让档位回升**,但**身体一点没好**。此时若发「响声轻了些」是**假陈述**(违"只写可验证事实",玩家会发现自己没被治疗)。故拆两支:**修好了**(hp 实升)/ **多了瓶药**(余量升、hp 未变)。

- **档1/档2 刻意换感官**(发涩=摩擦 / 慢下来+在响=速度与声音),避免「发涩/发沉」同构词法在日志流里被读成同一条。
- **档3 全态最短**(法4);未发现态额外给一句"看不出还剩多少"作最后诱饵。

### 3.2 污染(环境 · 当前无 UI = 纯法则一样板)

| 档 | 线索 | 备注 |
|---|---|---|
| 档1 | 「空气开始不干净。」 | 承接 N4 seq2「空气不干净了」 |
| 档2 | 「缝里进了东西。擦不掉。」 | 机械自感,不写呼吸 |
| 档3 | 「这儿待不长。它已经往里渗了。」 | 最短 |
| 恢复 | 「往里渗的慢下来了。」 | 双向 |

- 污染**当前无任何 UI**:玩家只能靠这四行判断"该不该继续待"。若 ⚙️/🔧 日后加污染观测物,它应是**可发现 UI**,届时档1 改嵌其可交互词作诱饵(同 §2.3 法3)。

## 4. 待机制批(设计先行 · 措辞方向)

> 教义 §4 三项机制未实现。**下列只是方向,不是成品文案**;正式批等 🔧 落机制后出,须逐条过"可验证事实"检验。

| 状态 | 档骨架 | 措辞方向(**只写已发生的可验证事实**) |
|---|---|---|
| **体力** | 3 档 + 恢复 | 档1「抬手比刚才慢」/ 档2「每做一下都要停一停」/ 档3「抬不起来了」——教义原例「有点累了」属档1 |
| **设施损毁度** | 3 档 + 修复 | 档1「这处的声音变了」/ 档2「它在漏」/ 档3「它停了」;停摆 = 该设施给的观测失效(接法则三) |
| **武器磨损度** | 3 档 + 炸膛 | 档1「握着发松」/ 档2「每打一下都掉渣」/ 档3「裂口到根上了」 |
