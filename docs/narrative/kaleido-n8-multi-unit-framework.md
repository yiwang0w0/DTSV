# KALEIDO · N8 多单位叙事框架(「讲的不是一个个体的故事」)

> 2026-07-22 · 📖 剧情轨 · 依据 Kanata 拍板的世界观支点(经 🧭 转达)。**本文 = 框架设计,不落全量文案**;§8 只给样例示范语感。
> **支点原话**:「因为讲述的不是一个个体的故事……玩家 step1 死后,下次再开,会用另一个视角讲述,**离上一个人出发已经过去多久了**……然后讲故事。」
> ⟹ **死亡不是回档,是时间推进。** 上一台死了,下一台被派出来;世界在你死的时候继续走。
> **本稿为对抗验证后重写版**:两镜头查出 7 处 blocking(通关路径未覆盖 / 第三拍是祈使 / 三轴全减法 / 自限被自己违反 / 安全屋承诺无法兑现 / 分档惩罚新手 / 可理解性押在一次性事件),已逐条重做,见 §10。

---

## 1. 三层模型(骨架)

| 层 | 是什么 | 连续性 | 叙事职责 |
|---|---|---|---|
| **系统** | 平台的登记与观测能力 | **连续**(跨所有单位) | 讲述者(值班的);**记忆的持有者** |
| **单位** | 你操作的这一台维护单位 | **可替换**(死了就是死了) | 视角;每台是一个"人" |
| **世界** | 函馆内部构造 | **继续走** | 时间感的载体 |

### 1.1 回溯性解释了三件既有设计(白捡的自洽)

1. **UI 解锁为什么账号级、死了不丢** —— **记住东西的不是那个人,是系统**。新单位继承的是**系统的观测能力**,不是前一台的记忆。
2. **觉醒行为什么只播一次** —— 第一台是**醒来**,后来的是**被派出**。
3. **「留下的字」终于有了作者** —— N2 声线3 的"前人"现在有身份:**前面某一台**。声线3 由氛围素材升级为叙事结构的一部分。

### 1.2 与 N1 咬合

N1 定「玩家 = 结构工程体(维护单位)」——**维护单位本就是可替换的备件**,系统派下一台是这个身份的自然推论。

## 2. 三种开场(⚠ 不是两种)

**上一 run 的终态决定走哪支**——这是本框架最关键的分支,漏掉任何一支都会与既有 canon 打架。

| 支 | 触发条件 | 单位身份 | 语感 | 现有资产 |
|---|---|---|---|---|
| **① 醒来** | 账号首次(step 0) | 第一台 | 被动、茫然;系统自己也没底 | 「很久没有回音了」+ 冷开局觉醒行 |
| **② 又是你** | 上一 run **存活**(通关 / abandon) | **同一台**再出发 | 熟稔、省话;个体连续 | N3 §2「又是你。灯还亮着。」**(此支专用)** |
| **③ 派出** | 上一 run **死亡** | **新一台** | 指派;系统更疲惫 | **全新(本文设计)** |

- ⚠ **②支必须保留**:N1 双层制 = 死亡丢远征、**不丢认知**;通关的单位是**活着回驻点**的(N2 收敛行「你回来了。走过的路,已经存进图里。门还在老地方。」)。它下次出发仍是同一台,走"派出登记"会当场拆掉多单位设定。
- ⚠ **给 🔧**:N3 §2「后续 run 开场行」须**限定为②支**(加注记),不得对③支复用——否则第二台开场播「又是你」,设定自毁。
- ⚠ **待 Kanata**:若要让通关也算"这一台任务结束、下一台接班",则 ②支取消、N2 收敛行须同步改写(「你回来了」不再成立)。**两边并存会矛盾,必须二选一。**

### 2.1 ③「派出」的三拍(全登记式)

1. **派出登记**:第 N 台。
2. **前情两句**:上一台的终局(必给)+ **世界现状**(优先取安全屋,见 §3 加法轴)。
3. **派出事由(登记,非交代)**:「本次派出：找药。」

> ⚠ **第三拍不得写成祈使或鼓励**。「撑住。」是鼓励(值班的不鼓励)、「出去。」是命令——两者都违 N1 §3.5 双频道与 N3 §4「去宣告化 ≠ 换成命令」。用**登记体**承载同样的信息:事由是簿子上的一行,不是对玩家喊话。

## 3. 递进设计(减法轴 + **加法轴**,总字量守恒)

**⚠ 旧稿三轴全是减法** —— 序号只是数字、口吻疲惫单调递减且一次性耗尽、世界荒度也是减法且无数据 owner。结果是玩家越往后读到的字越少,曝光最高的档反而最薄(违 N6 §5 红线①:触发越频繁的池必须越大)。**现改为一减一加、总量守恒**:

| 轴 | 方向 | 内容 |
|---|---|---|
| **A · 序号** | 中性 | 第 N 台(载体,不产内容) |
| **B · 口吻密度** | **减** | 修辞越来越省(**只减修辞,不减信息**) |
| **C · 世界事实** | **加** | B 每减一分,C 补一分**具体的世界事实**:上一台留下的东西 / 安全屋现状 / 某一处比上次更暗 |

### 3.1 信息恒给(硬约束)

**三项信息 —— 序号 / 前情 / 事由 —— 在所有档恒给**,档位只改句式密度。旧稿"交代压成半句→不再交代""前情可缺"是**删信息**,不是省修辞,已废。

同信息量的三档示范(以事由项为例):

| 档 | 事由项写法 |
|---|---|
| 早 | 「本次派出：找药。带回来。」 |
| 中 | 「本次派出：找药。」 |
| 晚 | 「派出：找药。」 |

字变少、三项俱全。**晚档仍是三行,不是两行**(两行会被读成"前情加载失败 = bug")。

### 3.2 分档 = 二维取小(⚠ 防惩罚新手)

**档位 = min( f(第 N 台) , f(历史最深进度) )**

- 只挂死亡计数会产生**惩罚性螺旋**:卡在开头反复暴毙的新手,10 次内被推进"近乎无话"档——而那些字正是他唯一的信息通道(N7:叙事=替代仪表盘)。**系统对越不会玩的玩家说越少的话**,是设计事故。
- 取小后,"疲惫"获得正确的世界内含义:系统对**反复损耗在同一处**麻木,不是对新手麻木。
- **护栏**:任一档下**连续 3 次死在同一段**,强制回落一档(系统重新交代)。
- **回归护栏**:距上次派出**超过阈值时长**(见 §7.2)时强制回落早档一次——世界内理由也成立(隔太久,得重新说一遍),同时解决玩家自己忘了规则的再上手问题。

### 3.3 池量下限(参照 N6 §3.2 自纠)

| 档 | N 范围 | 池量下限 |
|---|---|---|
| 早 | 2-3 | ≥8 |
| 中 | 4-8 | ≥8 |
| 晚 | 9-20 / 21+(**再分两段**) | **≥15**(曝光最高,池必须最大) |

旧稿"每档 1 条样例、不规定池量"会让玩家连续十余次读同一句式。

## 4. 死亡叙述(交接,不是终结)

- 死亡当拍**只登记、不预告**「你会再来」(那是元层,破沉浸):「信号中断。单位登记为：失联。/ 登记保留。」
  - ⚠ 「记录保留」已按 N3 §6.2 改为「**登记保留**」——「记录」是 `log_panel` 的可交互词,不得在死亡屏以不可点身份出现(§4 选词法④)。
- 「登记保留」保留给谁?**给下一台**。这句现有资产在新框架下自动获得意义。
- **接口在下一次开场**:玩家读到「上一台：失联于第三段」时自己意识到"上次那个是我"。**这个认知落在玩家身上,比系统说出来重得多。**
- **中间还有一屏在替我们铺路**:N3 §2 死亡收敛页题记「如果有人读到这行字——把灯留着。」(留下的字)本就预设了**一个未来的另一个读者**。死亡末行 → 该题记 → 下次开场,三拍天然成链。

### 4.1 ⚠ 认知安装的护栏(整套设定的可理解性押在这里)

这个认知**只有一次安装机会**(第 2 台的开场,玩家刚死、位置对得上)。必须护住:
1. **N≤3 的派出必须给完整前情**,§5 缺失层不得命中。
2. **缺失层 ≠ 数据兜底**:数据拿不到时**不得复用**缺失层文案(否则设计噪声与工程故障同串,玩家无法区分)。「前情数据不可用」是 🔧 的**阻塞项**,不是可接受降级。
3. **前情逐字取上一 run 真实终局**(段位/原因),不得抽样、不得近似——位置对不上,推理就不成立。

## 5. 前一台如何被后来者遇见(三层)

| 层 | 内容 | 必要性 | 依赖 |
|---|---|---|---|
| **① 登记层** | 前情两句:终局 + **世界现状** | **必有** | 上一 run 终态 + 位置 + 安全屋状态 |
| **② 遗留层** | 前一台死处留下的东西(装备 / 一行字) | 高价值(C 轴主要内容来源) | 需机制 |
| **③ 缺失层** | 系统不给前情(信号没回来) | 调味 · **≤1/5 且不得命中 N≤3** | 无 |

- **② 是「留下的字」的兑现**:玩家捡到的残页可能是上一台留下的;远期若能让**玩家自己上一趟写的字**被下一台捡到,这条线闭环。
- **⚠ 四种「没有前情」必须各配不同措辞**,禁止复用同一句(否则玩家分不清"系统麻木/系统不知道/那家伙是逃兵/游戏坏了"):晚档口吻 / 缺失层 / abandon 不留档(「上一台：未回报。」)/ 数据故障(不应出现在玩家面)。

## 6. 安全屋 = 叙事里程碑(⚠ 归属未裁前不得承诺持久)

**它是整个游戏第一个「我留下了什么」的时刻**,分量最重的一拍——正因为重,**不能承诺兑现不了的事**。

### 6.1 ⚠ 必须先裁的两件(交 Kanata/🧭)

1. **安全屋 vs 驻点**:N1 §2/§5 已定「驻点」= 外层持久层。安全屋与它是什么关系?**三选一**:(a) 安全屋 = 驻点的世界内名字 (b) 安全屋是 step1 内的段内锚点,驻点在其外 (c) 两者合一、废掉一个词。**不裁则玩家同时拥有两个"会留下、会回来的地方"。**
2. **跨 run 持久**:N1 明写内层远征**每次 run 生成 · permadeath**。若无新增持久机制,下一台进的是**重新生成的关卡,安全屋物理上找不到** ⟹ 旧稿「后面来的,找得到这儿」是以事实句形式说出的**假陈述**(违值班的"只写可验证事实"),玩家去验证会读作 bug。

### 6.2 现阶段文案口径

- **依赖落地前**:「这地方能关上。记下了。」——**只登记,不承诺**。
- **持久机制确认后**再加回世界现状那半句,并由 🔧 按持久标记控制是否可发。
- 守值班的:重量靠**「能关上」这个事实**,不靠形容词;**不得暗示存档/补给**(🧭 明禁)。

## 7. 数据依赖(交 🔧)

### 7.1 硬依赖

| 需要 | 用途 | 现状 |
|---|---|---|
| **上一 run 终态**(clear / death / abandon) | **三支开场分流**(§2) | 待确认 —— **不给就分不了支** |
| **账号级「第 N 台」计数** | 序号 + 分档 | 待确认 |
| **上一台终局**(位置 + 原因) | 前情第一句 | 待确认(多人线有 `player_death_log`) |
| **历史最深进度** | §3.2 二维分档取小 | 待确认 |
| **安全屋状态**(存在 / 位置 / 是否仍可用 · **跨 run 持久**) | §6 承诺兑现 + C 轴内容 | **无机制** —— §6 的重量全压在这上面 |
| **N 值下发给关卡/氛围池** | C 轴世界荒度真的随 N 变 | **无** —— 不给则 C 轴退化成空头 |
| **上一 run 时间戳** | §7.2 回归态 | 无(成本极低) |

### 7.2 计数口径(须明写,否则玩家会撞见算术矛盾)

- **N = 派出计数**(每次进入 step1 递增),**不等于死亡计数**。
- **abandon 是否计入 N**:建议**计入**(序号连续),但**不进前情**——那一台在登记里被跳过,措辞用「上一台：未回报。」与"失联"区分。
- 若不计入,则 run 计数与台号永久脱钩,🔧 需额外维护一套账。
- **回归态**:距上次派出超阈值时,用**真实时长**表达"过去多久"(支点原话正是这个),并强制回落早档一次(§3.2)。
