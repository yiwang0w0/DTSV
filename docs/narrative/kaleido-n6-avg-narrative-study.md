## 0. 一句话结论

**现有 N1-N5 是 AVG 的"骨架"(里程碑文字),不是"血肉"(逐动作叙述),也不含"剧情推进层"(跨遭遇/跨 run 的一次性 beat)。** AVG 主体化后玩家真正**反复读**的是每次搜索/每回合/每次移动的字——当前近乎空白。**结构 = 三层**(骨架 nar_line + 血肉动作变体池 + 剧情推进层进度 beat)+ **驻点持久层**(run 之间的空间)。核心工作 = 血肉池,量级 10-20×↑(且此估**偏低**,见 §3);但 **P1"不哑不重"的池必须 >> cooldown**(每高频桶 ≥15-20 条,不是 6-8),这是最尖锐的自纠。业界成熟解法(Valve 规则表 + shuffle bag + cooldown + 记忆回引)可直接抄,不必重造。

## 1. AVG 叙事弧全景 + 文字量/节奏

### 1.1 一整局的时间线(转场→收敛)

| 阶段 | 玩家动作 | 屏上文字 | 存量 |
|---|---|---|---|
| 转场·开场 | 进入,黑屏一钮 | run 开场旁白 | N3 §2 + N4 seq1 enter_text ✓ |
| 首次搜索 | 点搜索(第 1 次) | hp_bar/log_panel 解锁 + 搜索结果 | nar_line ✓;**搜索结果 ≈ 无** |
| **反复搜索** | 第 2…N 次 | 每次结果/空搜/氛围 | **几乎全缺(最痛)** |
| 首次获得 | 搜出道具 | inventory/craft 解锁 + 获得旁白 | 解锁 ✓;**获得旁白缺** |
| 首次遭遇 | 触发战斗 | combat 解锁 + 逐回合 | 解锁 ✓;**逐回合缺** |
| **战斗过程** | 每回合 | 打中/挨打/反击/换招/波次/濒死/击杀/失手 | **几乎全缺** |
| 关间推进 | 清关→往里走 | move 解锁 + 横幅 + 下关 enter_text | ✓ |
| 整套浮现 | UI 陆续解锁 | 11 ui_key nar_line | ✓(N3 全供) |
| 收敛 | 通关/死亡/放弃 | 题记 + run 末行 + 摘要 | 题记/末行 ✓;**摘要缺·多死因缺** |
| **返回驻点** | run 结束回外层 | 驻点态描述/持久层现状/再出发过场 | **整层缺(见 §2)** |

### 1.2 节奏与读字密度

- **搜索 = 主循环动词**,一局点**数十次**;每次都要有字且不能复读同一句(AVG 大忌)。
- 战斗:gauntlet 2 波 + boss 多回合,**每回合一屏字**,量与搜索比肩。
- **结论**:三声线 + 11 条 nar_line 撑得起**里程碑**(每种第一次),撑不起**一整局**——80% 屏幕时间是"第 2…N 次"重复动作,正是存量空白。**AVG 主体化 = 把叙事从"里程碑"扩到"每一次" + 补齐跨 run 与驻点两条被忽略的轴。**

## 3. 工作量冲击(critic 修正后 · 诚实版)

### 3.1 量级(承认原估偏低)

- 存量可上屏文案 ~100-150 行。
- **原稿估 10-20×(~1000-2500 行)是 undercount**:驻点层 / 跨 run 剧情推进层 / UI 标签 / 多死因死亡 原先未入清单,补入后丰满 surface 高于 2500 行上界。
- **context 桶乘法**:血肉按 `key×voice×关型×污染档×深度×敌档` 分桶,"每桶 N 条"要乘桶数——**P1 真实增量远高于原稿的 150-250 行**。

### 3.2 ⚠ 最尖锐自纠:cooldown 与池大小的数学矛盾

- §1.2:一局搜索**数十次**、不能复读。原稿却给池 6-8 + cooldown=3 → 40 次搜索里每句复现约 5-6 次 = **正是要防的出戏**。
- **修正基线**:高频动作(搜索/常规战斗回合)池必须 **>> cooldown**,起步 **≥15-20 条/桶**;低频/情绪句才用小池 + cooldown 保稀有。
- **重估 P1"不哑不重"**:不是 150-250 行,而是"每高频桶 ≥15 × 桶数 + 中低频池";务实做法见 §3.3。

### 3.3 缓解:归约标签 + 分期 + 生成辅助(带诚实成本)

- **先归约标签再挂规则**(Roadwarden 教训):不为每种状态排列手写,把状态压成少数正交标签(关型×危险档×情绪档),规则挂标签上——压平组合爆炸,避开"数千变量测试噩梦"。
- **分期**:P1 只做**最高频 2-3 个桶**(搜索三态 + 战斗核心回合)到"够一局不复读"的量(≥15/桶),其余桶给最小可玩;丰满留 P2/P3。
- **生成辅助(诚实成本)**:LLM **仅 build-time 扩池**(不进 runtime,见 §4 seed 裁定),📖 定声线锚样 + 铁律约束 + 池骨架,生成补量。**审校不省**:逐行审 1000-2500+ 行守少专名/描述制/不解释/声线一致 = 持续大 QA;禁用词可枚举(好审),**风格漂移是软性、快审会漏**——半自动没那么省,人审是 📖 化后的持续新职责。

## 4. 结构建议:三层 + Valve 规则表(外部最佳实践背书)

### 4.1 三层模型(critic 修正:原双层放不下剧情 beat)

| 层 | 是什么 | 触发 | 状态性 | 存放 | 归属 |
|---|---|---|---|---|---|
| **① 骨架** | ui_key 解锁 nar_line(里程碑) | 首次事件 | 一次性·无状态抽样 | 🔧 uiUnlocks.js 注册表(P1)→ content_pool(P2) | 📖→🧭→🔧 |
| **② 血肉** | 每次动作变体池(搜索/回合/氛围) | 每次动作·加权抽样 | 无记忆(池抽样) | content_pool `entity_type='narration'` | 📖 策展 + 🔧 消费 |
| **③ 剧情推进层** | 进度门控一次性 beat(命名 payoff/π 揭示/跨 run 钩子/首次-ever) | 累积条件达成 | **有状态·触发后永久改文本·不可重抽** | 玩家进度态(profiles/player_events)+ 条件文本行 | 📖 供文 + 🔧 状态机 |
| (跨)**驻点持久层** | run 之间外层空间文字 | 返回驻点 | 持久层现状 | content_pool(驻点态)+ 持久 UI | 📖 供稿 |

- ③ 是原稿最大漏洞:命名 payoff / π 揭示 / 「本次记录多出一行」既非 UI 浮现(非骨架),又有状态、触发后永久改文本(非可重抽血肉)。必须单列一层,挂玩家进度态。

### 4.2 血肉层架构(抄 Valve 动态对白 · GDC2012 Ruskin)

外部研究最值得抄的一套(§5 详):
1. **状态归约成 facts/标签**:`{concept, place_type, danger_tier, hp_tier, phase, weather, has_light?…}`,少而正交。
2. **规则表**:每条叙述挂一组 criteria(如 `concept==search AND hp_tier==low AND danger>=4`),事件来时**满足条件最多(最具体)者胜出**;作者只增规则不碰代码,JSON 存储适配。
3. **每规则一个 shuffle bag**:桶内**无放回**抽取(袋空重装),跨袋接缝禁相邻重复,常见句放多副本、稀有句单副本。
4. **稀有/情绪句加 cooldown**(N 回合不复现,避免被 bag 催出)。
5. **名词槽用受控 Tracery**:只从真实 item_pool/map 数据填槽(不自由生成),承载语气的句子仍走手写规则池。
6. **记忆回引**(Roadwarden):偶尔回指本 run 早前事件(「你又回到那处角落,这次……」)——最廉价的"活着"感 + 天然防重复。
7. **纯装饰层可选 Markov**(墙上残字/广播噪声),**绝不承载掉落真值**。

### 4.3 走数据形状(建议给 🔧/⚙️)

```jsonc
// content_pool 行:entity_type='narration'
{
  "narration_key": "search_result_found",     // 引擎按 outcome 解算的 key(见下·outcome-aware)
  "voice": "duty",                            // duty/wall/leftword
  "criteria": { "archetype":["search"], "hp_tier":"low", "danger_min":4 },  // 规则条件(空=兜底)
  "specificity": 2,                           // = criteria 条数;抽样时最具体者胜出
  "text": "……(📖 供稿)",
  "weight": 3,                                // shuffle bag 内副本数
  "cooldown": 8,                              // run 内 N 次不复现(见作用域)
  "once_per_run": false                       // true=剧情推进层/稀有插入用
}
```

### 4.4 必须补的机制裁定(critic 抓的洞)

- **seed 可复现 vs LLM「每次不一样」**:❗**裁定 = runtime 永远只从固定池 seed 抽样(可复现·护 R1/E2E);LLM 仅 build-time 扩池,产物入库后即固定。** 拓荒纪元「每次排列不一样」= run 间 seed 不同→抽样序列不同,**非运行时现生成**。二者不冲突。
- **空池兜底(防动作变哑)**:context 过滤可能返回空(如资源关/污染 55/深度 4 无匹配)。**兜底链**:精确 criteria 空 → 放宽 criteria → 该 voice 通用池 → 保底默认行。**任何动作都不许没字**(违"不哑")。
- **层间排序 + 去重**:同一拍(首次 search)可能骨架 nar_line(hp_bar before + log_panel after)+ 血肉搜索行同刻。**规则**:骨架先于血肉;血肉抽样须避开与本拍 nar_line 语义撞车(如 nar_line「开始记录…从你翻找的这一下」在场时,搜索血肉不重述「翻找」)——建"本拍已用语义标记"排除。
- **cooldown 作用域**:建议 **run 内**(每 run 重置,shape 简单);跨 run 防复读靠 seed 不同 + 池够大。若要跨 run 记忆(高级),另立持久 cooldown 表(P2+)。
- **稀有插入 per-run 预算**:「墙后的 ≤2/run」「钩子每 run≤1」= per-run 计数器,**weight/cooldown 表达不了**。用 `once_per_run` + run 级预算计数(🔧 状态)。
- **outcome→narration_key 映射**:search 一个动词按结果分岔 found/empty/material 三 key——引擎须 **outcome-aware**(动作解算后按结果定 key),不止 verb-aware。这是给 🔧 的新接口点。

## 5. 外部最佳实践(研究背书 · 可落地技法)

> 三镜头研究(WebSearch 查证)收敛的技法,均带出处。

1. **双重防重复**:不连续重复 ⊕ 全池轮空前不重复;触发越频繁的动作池必须越大。[Narrative Dept / Pixel Crushers]
2. **Shuffle Bag**:无放回抽取 + 加权副本 + 跨袋接缝禁相邻;干净可复现数据结构,状态存进 run seed。[seanmonstar / IndieKlem]
3. **cooldown / 新鲜度重排**:统计随机 ≠ 感知随机(Spotify);稀有/情绪句用 cooldown 保稀有感。[Spotify Eng]
4. **Valve 规则表(最值得抄)**:facts + criteria + 最具体者胜出 + 每组 LRU;同动作随语境自然分化,写作增量扩展不碰代码。[Ruskin GDC2012]
5. **Tracery 槽位**:限量用,只填受控真实数据词表;纯组合会产语义空洞句,**受控 > 海量**。[Compton 2015]
6. **Markov 仅装饰**(Caves of Qud):只做背景噪声,绝不承载可操作信息;**可控语法 > 纯生成**。[Qud GDC2019]
7. **短片段抗重复**(Cultist Simulator):搜索叙述宁短勿长,2-3 句精炼片段重复钝感强;用组合面而非单池巨量撑变体。
8. **记忆回引 + 归约抽象**(Roadwarden):回指最强"活着"感;**先归约标签再挂规则**,否则"数千变量测试噩梦"。

**三条红线**:①最高频动作(搜索)池给最大,否则整池秒循环=出戏第一元凶;②变体多≠好,受控>海量;③别手写状态排列,先归约标签。

## 6. 结论 + 给 🧭/Kanata 的决策点

1. **存量定位**:N1-N5 = 骨架(已就位);血肉(每次动作)+ 剧情推进层(跨 run beat)+ 驻点层(外层空间)= AVG 主体化的真正工作,近乎空白。
2. **量级**:>2500 行级(原估偏低);但 P1 靠"归约标签 + 只做最高频 2-3 桶到 ≥15/桶 + 其余最小 + build-time 生成扩池"控制。
3. **结构**:三层(骨架/血肉/剧情推进)+ 驻点层;血肉抄 Valve 规则表 + shuffle bag + cooldown,走 content_pool `entity_type='narration'`。
4. **📖 职责演变**:手写里程碑 → 声线策展 + 规则表骨架 + 生成 prompt 工程 + **持续 canon 人审**(风格漂移软约束,是新常态负担)。
5. **决策点(交 🧭/Kanata/🔧)**:
   - ① **血肉数据形状 + 三个引擎新钩子**(🔧 定):narration content_pool + Valve 式规则抽样(最具体胜出 + shuffle bag + cooldown)+ **outcome-aware key 解算** + **空池兜底链** + **per-run 预算计数**。
   - ② **seed/LLM 裁定确认**(🧭/🔧):runtime 只 seed 抽固定池、LLM 仅 build-time 扩池——请确认这条(护 R1/E2E)。
   - ③ **P1"不哑不重"量级基线**(Kanata 手感):高频桶 ≥15-20 条?先做哪 2-3 桶?
   - ④ **剧情推进层**(命名 payoff/π 揭示)落点仍等挂起⑥⑦ + ⚙️ 敌变体池结构。
   - ⑤ 落文案(血肉实写)= 下一批,等 ①③ 定形状与基线。
