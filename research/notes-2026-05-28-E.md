## 主题 E — 异步 PvP / 探针（延伸）

### 关键词
- `extraction shooter asynchronous PvP reward economy 2026 attacker defender both sides`
- `asynchronous multiplayer griefing prevention anonymity ghost player invasion design 2026`
- `Hunt Showdown 2 dark sight wraith trail persistent traces game design 2026`

### 关键发现

1. **Hunt: Showdown 1896 Update 2.7 "Devil's Trail" (2026-03-18) 用"世界会记得"重构了异步信息战** — Crytek 把 in-match trace residue 系统全面铺开：
   > "envelopes, ammo crates, and first aid kits now remain open; destroyed barrels leave behind remains; killing animals leaves corpses; doors remain ajar after being opened once; and used Trait Spurs leave scorch marks"
   设计哲学被概括为 *"rewards slow, methodical play—loud, fast teams get tracked while quiet teams that move efficiently can disappear off the map"*。这是 v3 的 probe-as-marker 模型的**超集**：probe 是显式 ghost marker，trace residue 是**隐式**的、衍生于玩家行为的痕迹层。两者并存才完整。
   - 来源: [Update 2.7 — Hunt: Showdown 1896 Wiki](https://huntshowdown.wiki.gg/wiki/Update/2.7)
   - 来源: [Scouting, Tracking and More in Update 2.7 — Crytek 新闻](https://press.crytek.com/scouting-tracking-and-more-in-update-27-devils-trail-bringing-searing-new-content-surprises-and-fresh-ways-to-play-in-hunt-showdown-1896)

2. **Hunt 2.7 路线图：撤离点和高价值 loot 将不再标注在小地图上** — Crytek 进一步把"信息匮乏"作为设计目标：
   > "extraction points and loot won't appear on the map"
   玩家必须通过痕迹 / 探索 / 同队信息共享发现撤离点。这把 trace residue 从"识别敌人路径"升级到"识别玩家目标本身"。对 DTSV 的对照意义：当 chamber 内信息越稀缺，**探针 / 痕迹的价值就越高**，单条探针的留存动机就越强。
   - 来源: [Hunt Showdown 的下一个实验：撤离点和 loot 不再上小地图 — PC Gamer](https://www.pcgamer.com/games/fps/hunt-showdown-keeps-experimenting-with-the-extraction-genre-and-its-next-twist-sounds-irresistible-soon-extraction-points-and-loot-wont-appear-on-the-map/)

3. **Ghost Player Effect 综述明确指出：匿名化本身是 anti-griefing 的设计资产** — 2026-04 综述强调异步交互的张力来源于"对方是不是真人 + 是谁的不确定"。一旦暴露真实 username 就把 indirect communication 退化成 direct contact，攻击的针对性、群体围攻、跨平台骚扰立刻成为可能。Dark Souls 的入侵和 Death Stranding 的点赞机制都对玩家 ID 做了**显示距离化**（玩家名变小 / 玩家头像泛灰 / 跨服 ID 哈希）。
   - 来源: [The Ghost Player Effect — News For You Today](https://www.acidoborico.info/2026/04/16/the-ghost-player-effect-how-seeing-others-indirectly-is-changing-viral-game-design/)

4. **Nemesis / Avenger 系统是异步重复遭遇从噪声变 emergent narrative 的范式** — USPTO 9539518 / 9076292 把 *Middle-earth: Shadow of Mordor* 的 Nemesis 系统泛化为可专利的 social-encouragement 模型。核心思想：同一对玩家重复遭遇后，系统应识别此对关系并升级（记忆对方上次胜负 / 加 banter line / 给特殊重逢奖励）。v3 警告过 8% 平均抽取会让同一对反复遇见 = 烦人；Nemesis 提供了**反向解法**：与其让它消失，不如让它变成有名字的死敌。
   - 来源: [Nemesis and avenger system patent — USPTO 9539518](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/9539518)
   - 来源: [Encouraging player socialization patent — USPTO 9076292](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/9076292)

5. **abuse-pattern 自动分流是 2026 异步多人的合规底线** — USPTO 11400378 "Automatic separation of abusive players from game interactions" 已经把"攻击模式异常 → 静默匹配隔离"作为可专利模型记录。对 DTSV 的现实映射：probe 池里如果某玩家对 >Y% 遭遇都选"袭击" 且其中 >Z% 是 hard-counter 残片，应进入"独立 hot pool"，与同档玩家匹配，不再骚扰 PvE 倾向用户。这与 v3 P1 的 `player_aggression_score` 是同方向，但增加了**主动检测 + 静默分流**的底线条款（非用户感知，避免被反向 exploit）。
   - 来源: [Automatic separation of abusive players patent — USPTO 11400378](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11400378)

6. **Marathon (Bungie, 2026-03 launch) 的 Rook runner shell 是不对称异步的折中范式** — Marathon 把 "scavenger 角色 = 单人 + 随机装备 + 投放进活的战斗" 作为独立模式。映射到 DTSV：除了"留探针 (gear-heavy ghost)"，可加一个 **"scavenger 探针" 子类**（不消耗 platform_part，但只能放过 / 不能攻击，遭遇时给主人 1 个观察 buff）。让低投入玩家也能进入异步层，扩大探针总量基数 → 降低长尾静默率。
   - 来源: [Marathon (2026 video game) — Wikipedia](https://en.wikipedia.org/wiki/Marathon_(2026_video_game))
   - 来源: [March Launch Details, Pricing Unveiled For Marathon — MMORPG.com](https://www.mmorpg.com/news/march-launch-details-pricing-unveiled-for-marathon-bungies-delayed-extraction-shooter-2000136860)

### 对照 DTSV

DTSV Phase 21 探针的现状（v3 引用的 `.claude/worktrees/suspicious-solomon-598909/src/lib/server/probes.js`，主分支仍未合并）：

- chamber 每次 raid 失忆：NPC 重生 / loot 重置 / 战斗残留全清
- 探针抽取按 chamber_template 索引，单条 ghost marker，无衍生残留
- 遭遇时（按 v3 注解推断）显示探针主人 username
- 没有重复遭遇识别，没有 abuse 检测，只有一种探针 SKU（"留 → 8% 被遇到"）

**已对齐**：
- v3 P0 telemetry + 回信闭环若上线，已经把"基础异步信息流"搭起来了，是 trace residue 的前置基础
- 8% 遭遇率方向正确（落在 ghost player effect 的窄区间）
- chamber_template 作为索引维度，给未来加 trace residue 字段提供了天然分桶

**风险 / 缺口**：

1. **chamber 是失忆的，探针是唯一痕迹**。Hunt 2.7 "the world remembers" 是 2026 extraction 标杆设计。DTSV 当前每次 raid 进同 chamber 像第一次进，"上一位玩家曾在这死过 / 摧毁过 NPC / 拿过 loot" 全无可见痕迹。这让探针**孤立**承担了所有"他人存在感"的叙事压力，单一向量很容易扛不住。

2. **probe 主人 username 直接暴露 = 针对性骚扰通道开放**。如果遭遇 UI 显示 "你撞上了 玩家ABC 留的探针"，那么：
   - 玩家可以在大厅 / 外部社群人肉对方
   - 同社群的小团体可以协同"专挑 X 的探针袭击"
   - 跨平台骚扰链路打通（QQ 群报点 → 同时段集中清剿）
   v3 完全没覆盖这个角度。匿名化（pseudonymous handle / 显示 "某位幸存者" + chamber 出勤次数段位）应该在 Phase 21 上线前就锁定，**事后改是 PR 灾难**（"为什么之前能看名字"）。

3. **重复遭遇没有 Nemesis 识别 = 既浪费叙事资产又制造怨气**。v3 P1 的 `player_aggression_score` 是降低重复遭遇概率的路子；但 Shadow of Mordor / USPTO 9539518 给出了**相反路子**：抓住重复，把它做成有名字的死敌。两条路并不互斥：低侵略玩家走 P1 隔离，高侵略玩家走 Nemesis 升级。

4. **没有 abuse-pattern 自动检测**。v3 P1 aggression score 只在匹配权重里用，没有"阈值触发 → 静默分流"。一旦少数高攻击率玩家集中骚扰新人探针，新人探针流入率会迅速崩溃（基础雪球：被打 → 不留 → 池子变小 → 更易被同一批人抽到 → 更被打）。需要 hard cap（如 30 日内 attack_rate > 0.85 且样本 ≥20 → 独立 hot pool）。

5. **只有一种探针 SKU**。"留 → 等被遇到"是唯一模式，参与门槛 = 消耗 1 platform_part + 接受 8% 命中。Marathon Rook scavenger 范式说明：**异步层需要"轻量入场"子类**，让不愿意消耗 platform_part 或不愿意冒"被袭击 / 反过来被人偷残片"风险的玩家也能贡献痕迹。

### Actionable findings (优先级 P0 / P1 / P2)

- **P0** — **探针主人匿名化（上线前必须锁）**：`tryEncounterProbe` / `resolveProbeFight` / UI 遭遇面板 / `player_notifications` 回信文本里全部禁止显示 probe-owner `username` 或 `email`。改为展示稳定 pseudonym（如 `观测者-<probe_id 后 4 位>` 或 `第 N 位幸存者` + 段位 / chamber 出勤次数段）。pseudonym 在 probe 生命周期内稳定，过期后下次留新探针重新生成。
  - 文件：`src/lib/server/probes.js`（owner_pseudonym 字段）、`cross_room_probes` schema、遭遇 UI 模板、回信通知文本
  - 理由：Ghost Player Effect 的核心 anti-griefing 资产 = 匿名性。username 暴露 = 开放跨社群人肉 / 集中骚扰通道，事后改是 PR 灾难。

- **P0** — **chamber 持续痕迹 v1（trace residue）**：探针被遭遇 / chamber 结束时 snapshot 1-3 条 trace 写入新表 `chamber_residue`（owner_pseudonym, chamber_template_id, last_npc_killed, last_loot_taken, last_death_location, expires_at = +72h）。下一位进入该 chamber 的玩家进场时 prefetch 该 chamber 的最近 5 条 residue，作为环境信息呈现（"💀 这里曾有人倒下"、"📦 某位幸存者带走了一个 medkit"）。**不允许暴露 username，全部用 owner_pseudonym**。
  - 文件：新建 `chamber_residue` 表 + migration、`src/lib/server/raids.js` postRaidSnapshot 钩子、`src/lib/server/chambers.js` getChamberResidue、game 页面进场前置查询
  - 理由：Hunt 2.7 "the world remembers" 是 2026 extraction 标杆，DTSV chamber 失忆是异步层的根性缺口，单靠探针抗不住"他人存在感"叙事压力。也是 v3 提议的 telemetry 的真正消费场景。

- **P1** — **Nemesis / 重复遭遇升级**：新建 `probe_encounter_pairs(attacker_id, owner_id, encounter_count, last_outcome, nemesis_since)`，同一对 (attacker, owner) 30 日内遭遇 ≥3 次 → 标记 nemesis_since = now。后续遭遇时遭遇 UI 显示 nemesis banner + 双方收到 "宿敌再次相遇" 通知。可选给 nemesis 对峙加特殊"决斗"分支（双方都 decode +1，输方掉 2 而非 1）。
  - 文件：新建 `probe_encounter_pairs` 表、`src/lib/server/probes.js` recordEncounterPair、UI banner、可选决斗分支
  - 理由：USPTO 9539518 / 9076292 Nemesis 模式把重复噪声变 emergent narrative。与 v3 P1 aggression score（降低重复）方向相反但不冲突：低侵略走隔离，高侵略走升级。

- **P1** — **Abuse-pattern 静默分流（hot pool）**：`player_aggression_score`（v3 P1）落地后，新增 30 日窗口 attack_rate > 0.85 且样本 ≥20 → 玩家进入 `hot_pool = true` 标记，`tryEncounterProbe` 抽取时把 hot_pool 玩家优先匹配同 hot_pool 玩家留的探针。**用户不可见此标记**（避免反向 exploit）。
  - 文件：`profiles.hot_pool BOOLEAN`、`src/lib/server/probes.js` 抽取权重、健康检查 spec 加 hot_pool_size 监测
  - 理由：USPTO 11400378 abuse 自动分流是异步多人合规底线。预防"少数高攻击率玩家集中骚扰新人探针 → 新人探针流入率崩溃"的雪球。

- **P1** — **scavenger probe SKU（低门槛子类）**：`cross_room_probes.kind ENUM('combat','scavenger')`。scavenger 不消耗 platform_part（消耗 5 fuel_pt 或 1 small consumable），遭遇时**只能放过 / 不能袭击**，放过给探针主人 1 条 "scavenger 报告"（chamber 当前 NPC 残余数 + 主要威胁类型），不掉残片。
  - 文件：`cross_room_probes` schema + `leaveProbe` kind 参数、`tryEncounterProbe` 分支、UI "留探针" 模态加两个选项卡
  - 理由：Marathon Rook runner shell 范式，扩大异步层入场玩家基数 → 降低长尾静默率。同时给 PvE 倾向玩家一个"参与异步但不冒被偷残片风险"的合法入口。

- **P2** — **遭遇 UI 把 owner_pseudonym 跟 P0 chamber_residue 串联**：遭遇时除显示 pseudonym，还附带"此人在 chamber X 留下的 2 条 residue"。让 attacker 在决定袭击 / 放过前能读到 owner 的近期行为画像（"上次死在 floor 3 BT 战，带走 1 个 fragment"），把决策从机械二选一升级为带 context 的判断。
  - 理由：把"间接通信"密度推到位需要多向量并存（pseudonym + residue + 探针本体）。P2 是因为依赖 P0 两条同时落地，建议在 Phase 21.2 一并完成。
