## 主题 D — 死亡惩罚与情感曲线(全新切面)

### 搜索结果摘要

- **来源 1(WebFetch 深读):[Game Design Deep Dive: Darkest Dungeon's Affliction System — Game Developer](https://www.gamedeveloper.com/design/game-design-deep-dive-i-darkest-dungeon-s-i-affliction-system)**
  - 设计师 Tyler Sigman / Chris Bourassa 原话:"The ability and skill to fight is only half of the equation. **What if a hero was unwilling to fight?**" → stress 是与 HP **独立**的第二条状态轴,建模"心理韧性 ≠ 身体血量"。
  - stress 满 100 触发 affliction check。**默认 75% 沦为 Affliction / 25% 升华为 Virtue** — 这个非对称比例刻意复刻"多数人压力下会崩"的现实研究。
  - 原话:"Having a hero pop Virtuous in the middle of a nasty fight can be a huge moment... **the heroic reversals are what memorable adventures are built on!**" → 一个惩罚系统**需要偶发的正向逆转**才令人难忘;全程只往下砸会变成纯折磨。
  - 设计意图明确是"剥夺 agency":"We want to put you in uncomfortable situations where you do not have complete control of your party。"

- **来源 2(WebFetch 深读):[Designing Shadow of Mordor's Nemesis System — Game Developer](https://www.gamedeveloper.com/design/designing-i-shadow-of-mordor-i-s-nemesis-system)**
  - 核心重构:玩家死亡不是终止态,而是**诞生一个具名敌人(杀你的那个 orc 升格为持久仇敌)**;Talion 作为"Gravewalker"能复活,为复仇叙事铺垫(灵感来自 Burnout 的"撞车不是失败而是反击机会")。
  - 设计师 Michael de Plater:游戏要主动"**记住**"玩家行为并在叙事里把玩家推到中心(类比 MGS Psycho Mantis)。**"revenge as a key motivational design tactic"** — 把死亡从终点重构成复仇钩子。
  - 关键:orc 只有几句短台词,玩家自己脑补出关系与历史 — "the core anchors are enough for the player to fill in the blanks"。
  - 设计师箴言:"Every time a player does something, never shut them off. **Build upon what they did。**"

- **来源 3(WebSearch 摘要):[Permadeath — Wikipedia](https://en.wikipedia.org/wiki/Permadeath) / Dwarf Fortress 设计观**
  - "failing is fun — **provided you don't have to repeat the same sequence of narrative events each time**。" → 永久死亡的乐趣来自**新颖的失败**,而不是重复同一段。这直接给死亡反馈 UI 上了一条约束:同一块"复盘屏"看 50 遍就死亡疲劳。
  - permadeath 提升留存的机制是"**responsibility / attachment**":角色可能永久失去 → 玩家更在意 → 沉浸与紧张上升。反推:DTSV 的入场 loadout 若**匿名一次性**,死亡就不疼。

### 玩家/设计共识 Top-3(本次新增,非经济角度)

1. **死亡不必二元**:DD 用第二条独立状态轴(stress)做出"还活着但已不一样"的中间态 — 情感纹理来自渐变而非开关。
2. **死亡需要偶发正向逆转**:75/25 的非对称是关键 — 全程下砸=折磨,稀有的"Virtue 时刻"才是记忆锚点。
3. **被杀 = 诞生关系,而非清零**:Nemesis 的全部价值在于"记住 + 复仇钩子 + 玩家脑补",且**只需要极少的具名锚点**就能生成叙事。

### DTSV 对照

| 设计杠杆 | DTSV 现状 | 缺口 |
|---|---|---|
| 第二状态轴(stress/condition) | 只有 HP 二元死亡,无持久心理/condition 层 | 🔴 无中间态,死亡情感纹理单薄 |
| 偶发正向逆转(Virtue) | 死亡全下行(丢本局 inventory + 无 class_pt) | 🔴 无任何稀有正向 swing |

| 死亡 recap"被记住" | DeathReviewModal(28-D)已展示 cause/存活/depth/残片 | 🟡 文案恒定,重复死亡看同屏 → 死亡疲劳风险 |
| 死亡推进 lore | PI 引导者 + 六纪元 lore 已有;death→lore 链路 28-D 点为 gap | 🔴 仍未系统化,Hades 抗挫核心缺位 |

### Actionable findings(建议改进)

- 💡 **[P1] 死亡 PvP → 宿敌复仇闭环接线**(本次最高杠杆,连接两个**已建**系统)。当 `player_death_log.cause_category='pvp'` 且 `defeated_by` 非空时,把这次"被终结"喂进 `probe_encounter_pairs` 的 nemesis 计数(或并行 `death_rival` 关系),使**被同一玩家击败**显著加权宿敌升级;下次遭遇该 owner 探针时,遭遇 UI 顶出"⚔ 你的终结者"复仇横幅。把 Nemesis 的"死亡→具名仇敌→复仇动机"落到 DTSV 已有数据上。文件:`src/lib/server/nemesis.js`(`recordEncounterPair` 加 `weight`/`source='pvp_death'` 入口)+ `deathLog.js`(写 death log 后回调 nemesis)+ Phase 21 遭遇 UI 横幅。**红线:匿名口径走 `buildOwnerPseudonym`,绝不渲染真实 id(沿用 28-E P0)**。

- 💡 **[P1] 死亡 recap 文案随上下文变体,防死亡疲劳**(additive 增强已建 DeathReviewModal)。Dwarf Fortress 铁律:重复同一失败屏=疲劳。让 DeathReviewModal 文案 branch on `cause_category × chamber_depth × 当前纪元`,每种组合配一条 PI 引导者旁白(死在 volatile 层 vs 进场即死 vs PvP 被终结 语气不同)。把"被记住"从静默遥测变成会变化的叙事。文件:`src/components/DeathReviewModal.jsx` + `src/lib/constants.js` 死亡旁白文案表(无 schema 改动,复用现有 3 字段)。

- 💡 **[P1] 死亡推进 lore 的元叙事节拍(Hades 抗挫核心,把 28-D 的 gap 落成机制)**。按**累计死亡次数**(`player_death_log` count by user)gate 一条 PI 引导者对白阶梯:第 N 次累计阵亡解锁下一段引导者 beat,使"死亡本身"成为 lore 揭示的 pacing key,**与点数/power 完全解耦**(死多了只解叙事,不给数值)。这正是 Hades"每次死回家有新对白"的等价物。文件:新建轻量 `pi_guide_death_beats`(threshold INT, era, dialogue) + `deathLog.js` 写入后查当前 death_count 命中阈值 → push 到 `player_notifications` 或下局 preRaidSetup 关怀对白(复用 28-D 已建 `raids.js` 对白系统)。

- 💡 **[P2] 非二元 condition 层(Darkest Dungeon stress 等价,谨慎、非数值惩罚)**。引入一条**跨 raid 持久 condition** 轴:高创伤死亡(深层 chamber 阵亡 / 高投资全损)累积"心理负荷",成功撤离衰减。**严禁做成战力 debuff(否则触发死亡螺旋,撞 27-v2 escalating-loss 反模式)** — 只表现为 PI 引导者语气转冷 / 残片旁白色调变化 / 可选的纯叙事状态卡。给死亡一个"还活着但已不一样"的中间态。建议先做**纯叙事版**(condition 不影响任何数值),数据上加 `player_state.trauma_load INT` 单列即可,UI/数值留后。

- 💡 **[P2] 偶发正向逆转(DD Virtue 75/25 非对称)**。在**濒死或死亡**时给一个**低概率(~20-25%)** 的正向 swing,但**绝不给点数/装备/掉率**(守经济红线):正向时掉一条**专属"逆境"lore 残片**或一句独特引导者赞许("你本该倒下,却没有")。稀有度是关键 — 太常见就贬值。把"全下行折磨"改成"绝大多数下行 + 罕见记忆锚点"。文件:`gameActions.js` 死亡分支 + `fragments.js`(逆境残片池)。

- 💡 **[P3] 给入场 loadout 一点身份(permadeath attachment)**。每次出勤自动命名一次"远征"(如"远征-海蓝-07")并在局内实时累计本局击杀/拾取残片数;死亡 recap 顶部用得上("本次远征 <名> 终结于 volatile 层")。匿名一次性 loadout → 微弱身份 → 死亡更疼,**零经济改动**。文件:gamevars `runLabel`/`runTally` + DeathReviewModal 顶栏。
