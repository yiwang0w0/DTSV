## 主题 B — 元进度 / 经济系统（catch-up + 可选 wipe + 通胀控制）

### 关键词
- `roguelite catch-up mechanic new player late game progression design 2026`
- `extraction shooter wipe season reset economy long term retention Tarkov Arc Raiders`
- `game economy sink design currency inflation control progression curve 2026`

### 关键发现

1. **Horizontal > Vertical 是 2026 共识** — "最持久的 roguelite 大多重 horizontal growth（新武器/新机制/新角色/规则变体），因为它驱动**实验**而不是 power creep"。垂直进度（更多 HP/伤害）容易把数值卷上天，让新人永远追不上。
   - 来源: [Roguelite Games With The Best Progression Systems](https://gamerant.com/roguelite-games-with-best-progression-systems/)

2. **Arc Raiders 已实装"可选 wipe"作为追赶机制（2025-12）** — bi-monthly（8 周）节奏，玩家 lv20 起可在 7 天报名窗口内自愿参与"Expedition Project"。**触发成本极高：需要数百材料 + 80 万 coin 等值物品**，所以不会被卷成强制。
   - 来源: [ARC Raiders Expedition: Solution to Progression Resets](https://screenrant.com/arc-raiders-extraction-shooters-progression-reset-problems/)

3. **Arc Raiders 持久 / 重置项分界（直接抄作业用）**：
   - **持久**：解锁的地图 / workshop / 蓝图 / codex / coins / raider tokens / cosmetics / 个人活动进度 / 补给车队进度（未完成的远征延期到下季）
   - **重置**：raider 等级 / 技能点 / 背包 / Cred 货币 / 排行榜 / 任务
   - 设计逻辑："横向积累（地图/蓝图/lore）持久，垂直数值（等级/库存）周期清洗"
   - 来源: [ARC Raiders Expedition Design](https://screenrant.com/arc-raiders-extraction-shooters-progression-reset-problems/)

4. **Expedition 奖励是"经济表现达标后转技能点"** — 每 100 万 coin 的库存 + 货币综合估值兑换 1 个新角色技能点，**上限 5 点**。设计要义：把"有钱"转换为"开局快 5 步"，避免一次性吐光所有富翁优势。
   - 来源: [Arc Raiders Optional Wipe Bonuses](https://biggo.com/news/202512062121_Arc_Raiders_Optional_Wipe_Rewards_Detailed)

5. **Expedition 永久奖励限于外观 + 仓库扩容（+12 槽位）** — 关键约束："**none of the changes will offer a combat advantage**"。这是用"prestige cosmetic + 仓库这种结构性资源"做长期粘性，不靠数值。
   - 来源: [ARC Raiders Expedition](https://screenrant.com/arc-raiders-extraction-shooters-progression-reset-problems/)

6. **经济失衡报警阈值：周库存涨幅 12%** — Machinations 给出的实测红线："当周货币库存增长 > 12% 时，市场就会失稳、物价开始通胀、内购失去价值"。这是健康检查可量化的核心指标。
   - 来源: [Game Economy Inflation — Machinations](https://machinations.io/articles/what-is-game-economy-inflation-how-to-foresee-it-and-how-to-overcome-it-in-your-game-design)

7. **优先用"弹性 sink"而不是"扁平 sink"** — Albion Online 的解法是"出现通胀就动态拉高维修/升级费用"（与玩家活动量挂钩）。比固定每日运营费高效，因为活跃玩家受到的抽水更大，自动平衡。
   - 来源: [Inflation in Video Game Economies](https://pulsegeek.com/articles/inflation-in-video-game-economies-causes-and-fixes/)

8. **Faucet 调控优先于"印新币"或"砍物价"** — 通胀时第一动作应该是**收紧产出口**（降掉率/降副本货币奖励），而不是发行新货币或暴力降价。后两者会触发玩家"我的资产被稀释"的恶感。
   - 来源: [Inflation in Video Game Economies](https://pulsegeek.com/articles/inflation-in-video-game-economies-causes-and-fixes/)

9. **元进度反模式 #2 实证："必须输 N 次开 X"会让玩家觉得难度被人为劣化** — Hades II Steam 讨论区原帖："wins feel more about accumulated currency than skill"。如果 DTSV 的 class_pt 保底"必须出 N 次才出 legendary"做得过死，会触发同样的反感。
   - 来源: [Hades II Discussion — I HATE roguelite around unlock to feel good](https://steamcommunity.com/app/1145350/discussions/0/4358999171576511867/)

10. **"补给车队"机制 = 跨赛季软续命** — Arc Raiders 允许"未完成的 Expedition 进度延期到下季"。这给中途断网/没时间打完的玩家一个软安全网，避免"我攒了一半但 deadline 错过就归零"的劝退点。
    - 来源: [ARC Raiders Expedition Design](https://screenrant.com/arc-raiders-extraction-shooters-progression-reset-problems/)

### 对照 DTSV

**已对齐**:
- **Phase 24b "extract 时把装备 DELETE 转点数"本质就是"每次撤离微 wipe"** — 与 Arc Raiders Expedition 节奏更密但思路一致：周期性清洗背包/装备，避免老玩家无限累积。
- **残片解码 / chamber 解锁 / 知识图谱**完全是 horizontal growth — 与 finding #1 best practice 对齐。
- **shop_exchange_rates 已规划加版本号**（05-27 P0）— 支持"按比例缩点数"软 wipe，符合 finding #2-#5 的"可选 wipe"路线。
- **profiles.stash_capacity 默认 40，按用户成长扩容** — 与 Expedition "+12 stash 槽"的"结构性奖励"思路一致。

**风险/缺口**:
- **DTSV 没有"自愿 wipe"路径**。Phase 24b 完成后老玩家点数会单调累积。建议在 Phase 24b SQL 里**预留 expedition 表雏形**（即使不立刻启动），避免半年后回头改账户表。
- **没有 catch-up mechanic 显式设计**。Phase 24c 职业 10% legendary + class_pt 保底是数值追赶，但**横向追赶（地图/残片解码量/职业池）缺位**。新人加入 6 个月后，老玩家 F01-F15 全解码、35 chamber 全访问，新人面对"已被解锁的"内容是无感知的（不知道老玩家已经见过）。
- **没有 faucet/sink 量化监控**。raid_stats 有 `fragments_extracted` 但**没有 points_credited / points_spent / stash_value_delta**。Phase 26 healthcheck 没法计算 finding #6 的 12% 阈值。
- **Phase 24c class_pt 软保底**如果做成"必出 legendary 间隔 = 10 次"的硬计数，会撞 finding #9 的反模式。需要做成"软保底 + 计数透明"。
- **Arc Raiders "5 点技能点上限"翻译到 DTSV**：如果引入软 wipe，老玩家累积的 high_equip_pt 换成的"新赛季初始优势"必须**封顶**，否则等价于资产滚雪球穿越赛季。

### Actionable findings

- **P0** — Phase 24b SQL 建表时**同时建空表** `seasonal_expeditions(season_id, opened_at, closed_at, departure_at, status)` + `player_expedition_opt_ins(user_id, season_id, opted_in_at, bonus_skill_points, persisted_items JSONB)`。即使本期不开赛季，提前定型可避免半年后破坏性改表。文件: `scripts/phase-24b-points-economy.sql`（待建）。

- **P0** — `raid_stats` 加 4 个 jsonb 字段：`points_credited / points_spent / stash_value_before / stash_value_after`。每场 raid 落点，Phase 26 healthcheck 才能跑"周库存增长率"指标，预警 finding #6 的 12% 通胀红线。文件: `src/lib/server/gameActions.js` (`extractPlayer` 末尾) + `scripts/healthcheck-spec.md` 加段。

- **P0** — **明确 DTSV 持久 vs 重置边界**（在 24b 启动前定，写进 Readme_Claude）：
  - **持久（与 Arc Raiders 对齐）**：残片解码 / chamber 模板访问历史 / class 池解锁 / cosmetic / 立绘 / 总出勤次数
  - **重置候选**（可选赛季）：4 类点数余额 / equipment_instances / player_stash 内容（**但保留 stash 容量上限**）
  - 写一份 `docs/economy-canon.md`（不在 Readme_GPT 里），后续 Phase 24b/26 的所有"重置范围"决策引用这个文档。

- **P1** — **catch-up mechanic 设计**：新玩家（出勤 < 20 次）享受 "discovery boost" — 残片掉率 ×1.5 / chamber 多样性权重补正（让新人优先碰到没见过的 template）。在 `pathGenerator.js` 加一个 `playerRaidCount` 参数，新人 raid 路径偏向"低 spawn_count" template。

- **P1** — **class_pt 软保底"透明化"**：UI 显示"距离下次必出 legendary 还剩 N 次出勤"，且**保底不是硬 10 次而是从第 6 次开始指数提升 drop_rate**（10% → 14% → 20% → ... → 100% on 第 10 次）。避免 finding #9 的反模式感。文件: `src/app/archive/page.js` ClassesTab + `src/lib/server/classes.js`（待建）。

- **P1** — **弹性 sink 雏形**：商店物价不固定，挂钩"近 24h 全服该商品兑换次数"。每多 100 次兑换，价格 +5%（封顶 +50%）。模仿 Albion Global Discount，让活跃玩家自动多抽水。文件: `src/app/admin/_tabs/ShopTab.jsx` + `shop_exchange_rates` 加 `dynamic_multiplier_window` 列。

- **P1** — **`unlocked_chamber_templates` 跨赛季持久**。即使未来开赛季 wipe，老玩家访问过的 chamber 模板**不重置**（横向积累）。新人则继承"全玩家社区已访问的模板集合"的 80% 作为起步池（避免新人面对一个"早就被发现"的世界还要从零探索）。

- **P2** — **赛季奖励"开局加速"模型**：未来 expedition 启动时，按 Arc Raiders 的"每 100 万 coin = 1 技能点（上限 5）"换算 DTSV：把上赛季 high_equip_pt + low_equip_pt 总和按汇率换成"新赛季起手装备额度"，**封顶 5 件 uncommon 装备 / 0 件 rare+**。绝对禁止跨赛季带 legendary。

- **P2** — **"补给车队"软续命**：玩家未完成的合同（contracts）可以延期 1 个赛季，不归零。降低赛季 deadline 焦虑。文件: `src/lib/server/contracts.js` 加 `seasonal_carryover` flag。
