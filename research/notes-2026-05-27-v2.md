## 主题 C — Lore / 叙事系统

### 关键词
- `environmental storytelling fragment lore game design 2026 best practices show don't tell`
- `hidden narrative discoverable lore design document codex collectibles player engagement`

### 关键发现

1. **环境叙事的本质是"玩家作为解读者"，不是被动观众** — 设计师摆放"事件最终结果"的物件让玩家自己反推故事过程。Dark Souls 的"每个破碎雕像、每个 item description"组合起来才拼出 fallen kingdom 的图景，玩家投资换取叙事产权。
   - 来源: [Reclaiming the Narrative — Wayline](https://www.wayline.io/blog/reclaiming-narrative-reviving-environmental-storytelling)

2. **七条具体反模式 — 文本过度依赖是头号杀手** — Wayline 列出环境叙事的核心 anti-pattern：
   > "Over-reliance on text" — use text sparingly to supplement the environment, not replace it.
   > "Environmental clutter" — focus on creating a few impactful environmental details.
   其他：缺乏部门内聚（解决方案：写 narrative vision document）/ 视觉隐喻过重 / 线性设计扼杀探索 / 重复音效 / 生硬谜题打断叙事 / 通用涂鸦破坏沉浸。
   - 来源: [Reclaiming the Narrative — Wayline](https://www.wayline.io/blog/reclaiming-narrative-reviving-environmental-storytelling)

3. **分层 lore 同时服务两类玩家** — Casual 玩家走主线不被卡，lore hunter 通过 codex 入口/隐藏物件深挖。秘密 codex 与契约/任务挂钩，玩家进度越深 codex 解锁越多，构成"探索 → 奖励 → 再探索"循环。
   - 来源: [Lee Rebel Writers — Hidden Collectibles](https://www.leerebelwriters.com/discovering-hidden-collectibles-that-expose-rich-lore-in-popular-games/)

4. **Outer Wilds 模式：碎片本身就是关卡** — 不靠 NPC 灌输，玩家通过废墟、加密信息、飞船日志拼出整个文明的命运。**这是 DTSV 残片三链的直系参考。**
   - 来源: [Reclaiming the Narrative — Wayline](https://www.wayline.io/blog/reclaiming-narrative-reviving-environmental-storytelling)

5. **What Remains of Edith Finch 模式：空间即角色** — 房子本身是主角，每个房间是 time capsule，物件成为情感锚点。对照 DTSV：函馆地图本身的命名/布局是否承担了"角色"功能，还是只是 raid arena？
   - 来源: [Reclaiming the Narrative — Wayline](https://www.wayline.io/blog/reclaiming-narrative-reviving-environmental-storytelling)

6. **lore 不是孤岛 — 必须与机制、关卡、对话紧绑** — 来自 Game Developer 的反神话：narrative design 不是"加一层文本"，而是和 mechanics/level/dialogue/cutscene 共同呼吸。这意味着 lore 部门和 system 部门脱节会立刻被玩家感觉到。
   - 来源: [Narrative design myth-busting — Game Developer](https://www.gamedeveloper.com/design/narrative-design-myths-2-it-s-not-just-lore)

### 对照 DTSV

**已对齐**:
- `F01-F15` 六纪元 + `loreInjections` 机制 = Dark Souls "item description" 模式，碎片本身承担叙事。
- `discoverFragment` 三链（拾取 → 解码 → 解锁）= Outer Wilds 风格的玩家拼图。
- `decode_level` 给 lore hunter 额外深度，casual 玩家不被强迫看完所有残片才能撤离。
- 残片是"内容解锁式"元进度（与 v1 主题 B 互证），不动数值平衡 — 这是双重 best practice。

**风险/缺口**:
- **缺乏明确的 narrative vision document**。`Readme_Claude` 是开发日志风格，没有独立文档定义"DTSV 想说什么 / 玩家在每个纪元应该感受到什么"。lore 文本和 system 行为（污染机制 / 撤离面板）有无语义一致性，目前靠 Claude 单点把关。
- **撤离面板可能"text-heavy"**（Phase 10.5 落地的结局横幅 + 撤离面板）— 需要核查是否过度依赖文字描述结局，缺少环境视觉（光照/粒子/字体动效）承载情感。这是 Wayline 反模式 #2 "over-reliance on text"。
- **地图作为"角色"未充分挖掘** — 35 张地图（constants.js MAP_LIST）目前主要是 raid arena。是否每张地图都有独立的"时间胶囊"感（Edith Finch 模式）？还是只是 weather / danger_level 差异？
- **残片三链对 casual 是否友好？** 没数据知道未解锁残片的玩家是否能完成核心 raid loop。需要 playtest 数据：F01-F15 中前 3 个有多大比例的玩家在 1 周内触达？

### Actionable findings

- **P0** — 建立 `docs/narrative-vision.md`（独立于 Readme_Claude），定义六纪元的核心情感主题 + 玩家在每个 chamber 路径应感受到什么。所有后续 lore 文本和系统命名（如 Ω-段、PI 引导者）必须能映射到这个 vision，避免 lore-system 脱节。文件: `docs/narrative-vision.md`（待建）。
- **P1** — 撤离面板（Phase 10.5）增加"环境承载情感"通路 — 远星函馆 FX shader 已经接入 Hero（Phase 10.1-10.3），同款 shader 应在 4 结局对应不同色调/粒子密度。检查 `src/components/EndingBanner.jsx`（Phase 10.5）是否已经分支化视觉。
- **P1** — `player_fragments` 加 healthcheck 看板：F01-F15 各残片的"触达率 / 解码深度分布"。若 F12-F15 残片只有 <5% 玩家触达，说明三链门槛过高，需要降阈或加引导。文件: `scripts/healthcheck-spec.md`（待建）+ `player_fragments`。
- **P2** — 35 张地图每张赋予一行"Edith Finch 式 capsule 描述"（map_config 加 `lore_capsule TEXT` 字段），即使玩家不刷该地图，从地图选单也能看到一段叙事钩子。低成本高密度的 lore 注入。

## 主题 D — 死亡惩罚 / 张力曲线

### 关键词
- `death penalty design extraction shooter loss aversion tension curve 2026`
- `risk reward curve roguelike death cost design escalating tension`

### 关键发现

1. **死亡代价应该分级 escalate，而不是 instant fail** — Cogmind 设计师 Kyzrati 明确反对"一击致命"，主张让玩家有"recover opportunities"。玩家在多次小错后才彻底失败，每个错误提供学习信号。
   - 来源: [Designing for Mastery in Roguelikes — Grid Sage](https://www.gridsagegames.com/blog/2025/08/designing-for-mastery-in-roguelikes-w-roguelike-radio/)

2. **可识别的因果 = 死亡有意义的前提** — Risk of Rain 2 的设计原则："clear cause-and-effect design means deaths rarely feel cheap"。玩家死后能立刻指出"我应该没贪那波 boss"，这是 80%+ 重玩率的心理基础（呼应 v1 A 主题 Arc Raiders 数据）。
   - 来源: [Roguelikes That Balance Difficulty — Gamerant](https://gamerant.com/roguelikes-with-perfect-difficulty-balance/)

3. **时间压力是天然的张力发生器（food clock / corruption）** — Risk of Rain 2 的"每分钟难度递增"和 Cogmind 的"占图过久触发腐蚀"是同一类设计：让玩家在贪婪 vs 撤离间持续权衡，时间本身就是 cost。
   - 来源: [Designing for Mastery — Grid Sage](https://www.gridsagegames.com/blog/2025/08/designing-for-mastery-in-roguelikes-w-roguelike-radio/)

4. **Dynamic dispatch — 玩家高调行为触发递增反应** — Cogmind 的 Unchained system (Beta 16)：极端玩家行为会生成跨多层追踪的 mini-boss。这给"贪婪/高调玩法"一个有机的代价，而不是数值惩罚。
   > "throw another new wrench into plans"
   - 来源: [Designing for Mastery — Grid Sage](https://www.gridsagegames.com/blog/2025/08/designing-for-mastery-in-roguelikes-w-roguelike-radio/)

5. **多层预警 — 让玩家"看见 cost 在逼近"** — Cogmind 对 Freighter 入侵采用"全图广播 + 可追踪路线 + 侦察组先遣"三层预警。这让有经验的玩家"capitalize on mastery"，而新人也有时间反应。**单次硬截止是反模式。**
   - 来源: [Designing for Mastery — Grid Sage](https://www.gridsagegames.com/blog/2025/08/designing-for-mastery-in-roguelikes-w-roguelike-radio/)

6. **Escape valve 是 mastery 设计的隐藏支柱** — Cogmind 提供"free item removal"让玩家可以裸装求生，避免 cascading bad luck 锁死。**任何死亡设计都需要一个"哪怕一切失败也能继续尝试"的兜底通路。**
   - 来源: [Designing for Mastery — Grid Sage](https://www.gridsagegames.com/blog/2025/08/designing-for-mastery-in-roguelikes-w-roguelike-radio/)

7. **整数完整度 (integrity loss) vs 一次性归零** — Cogmind 的"物品被攻击逐渐损坏"是 compound resource pressure，与 v1 B 主题 Phase 24b 的"extract 时 DELETE → 转点数"是两种 sink 哲学。前者是渐变张力，后者是阶跃归零。
   - 来源: [Designing for Mastery — Grid Sage](https://www.gridsagegames.com/blog/2025/08/designing-for-mastery-in-roguelikes-w-roguelike-radio/)

### 对照 DTSV

**已对齐**:
- `pollution meltdown` + `Ω-段` 倒计时 = food clock / corruption clock 同类，时间压力已有双层（个人 + 环境）。
- `player_death_log` 表已建立 — 提供"可识别因果"分析的数据基础。
- `failedRetreats` 字段 — 给玩家失败留下可追溯信号，符合"死亡有意义"前提。

**风险/缺口**:
- **Ω-段倒计时是否是"单次硬截止"？** 若 0s 一到就强制结算，违反"多层预警"原则。需要核查倒计时 UI 是否在 30s / 20s / 10s / 5s 给可见+音效层级警告。
- **缺少 dynamic dispatch 等价机制** — DTSV 的 NPC 生成基于 `npc_pool.maps[]` 静态映射，没有"玩家在 chamber 内连续高调击杀 → 引来更强响应"的递增反应。Phase 19 chamber 路径是否能挂这层？
- **没有 escape valve** — 装备一旦在 chamber 内全损（或入场前 stash 为空），玩家是否还有"裸装出勤 → 撤离即获少量点数"的兜底？Phase 24b "extract DELETE 转点数" 设计下，零装备入场是否合法？需要确认 PrepareModal 的最小入场门槛。
- **死亡日志维度不足** — `player_death_log` 当前是否记录 `cause_category`（被 NPC / 被污染 / 主动放弃）和 `survived_seconds`？没有这些维度无法做"死亡因果可识别度"分析。

### Actionable findings

- **P0** — `player_death_log` schema 检查 + 补字段：`cause_category ENUM`（npc_kill / pollution / omega_timeout / voluntary_quit / probe_encounter）+ `survived_seconds INT` + `chamber_depth INT`。这是 v1 A 主题 P2"死亡黏度"埋点的前置依赖。文件: 新建 migration `scripts/phase-22-*.sql`。
- **P0** — Ω-段倒计时分层预警审计：核查 `gamevars.omega_remaining` 在 UI 上是否有 30s/10s/5s/2s 多层提示（视觉 + 音效）。若只在 0s 触发结算，**这是反模式 #5**。文件: `src/app/game/[id]/page.js` 倒计时组件。
- **P1** — 设计 escape valve："零装备出勤" 路径 — 玩家 stash 完全为空时，允许免费入场 chamber，撤离时给极小但稳定的点数。防止 Phase 24b sink 设计反向锁死新玩家或破产玩家。文件: `src/components/PrepareModal.jsx`（待建）+ `scripts/phase-24b-*.sql`。
- **P1** — Dynamic dispatch 雏形：chamber 内连续击杀 N 个 NPC 后，触发 `cross_room_probes`（Phase 21）从相邻房间渗透。把异步 PvP（主题 E，待跑）和"高调行为代价"绑定，一举两得。文件: `src/lib/chamber.js`（或现有 chamber 模块）。
- **P2** — Integrity loss 实验：是否在 Phase 24b 之外，给装备加入"chamber 内被攻击逐损 atk/def"的渐变退化？作为"DELETE 转点数"的轻量补充。需要 playtest 评估是否过载，但理论上能补足"compound resource pressure"缺口。
