## 主题 D — 死亡惩罚 / 张力曲线（延伸）

### 关键词
- `extraction shooter death penalty insurance design 2026 Marathon Tarkov DMZ partial loot recovery`
- `roguelike consecutive death pity system Hades Returnal streak breaker 2026 frustration mitigation`
- `post death feedback loop replay system game design 2026 kill cam learning extraction`

### 关键发现

1. **"付费的死亡"放大损失感 — 投资可视化是张力的前置** — 2026 行业分析明确指出 "death feels more significant when you paid to access" 适用于所有"入场成本 > 0"的 raid 设计。DTSV 的 Phase 24b 「入场购买装备 / 兑换点数」本质上是"为这一局付了费"，意味着死亡心理代价显著超过单纯装备损耗。**反推：PrepareModal 必须把"本局总投资"显式标出**，让玩家在 commit 前就已知风险，避免事后归因偏差。
   - 来源: [From Tarkov to Arc Raiders — The Star (2026-04)](https://www.thestar.com.my/tech/tech-news/2026/04/06/from-tarkov-to-arc-raiders-the-evolving-landscape-of-extraction-shooters)

2. **Tarkov 风格保险 = "延迟返还 + 限品类"** — Tarkov 保险只覆盖 weapons/armor（不覆盖弹药/医疗），玩家死后由 NPC trader 经一段实时延迟（数小时）返还**未被对方撤走**的部分。这把损失从"全有/全无"分成"可承受 baseline + 高方差 swing"两层，既保留刺激又避免破产螺旋。注意：消耗品故意不保 → 给玩家"什么值得带"的心理决策权重。
   - 来源: [Insurance — Escape from Tarkov Wiki](https://escapefromtarkov.fandom.com/wiki/Insurance)（fetch 403，仅引用搜索摘要）

3. **EVE Vanguard 模型 — "raid 前主动 deposit" 替代被动保险** — EVE Vanguard 让玩家在入场前把 credits / chipsets 存入"终端"，存进去的部分**不会随死亡损失**。这是"主动选择 cost ceiling"的设计：玩家自己决定"本局最多敢输多少"，把风险阈值的设定权前移给玩家。比保险更直接、无延迟、无 RNG。
   - 来源: [From Tarkov to Arc Raiders — The Star (2026-04)](https://www.thestar.com.my/tech/tech-news/2026/04/06/from-tarkov-to-arc-raiders-the-evolving-landscape-of-extraction-shooters)

4. **Returnal-Hades 对比 — "首次伤害即归零" 是反模式** — Returnal 的 Adrenaline 一击清零受到广泛批评 "agonizing"；Hades 的 Thanatos keepsake 不会因受伤丢栈。**任何"连胜 / 完美撤离 / 无伤"buff 一旦被设计成"首次失误归零"，都会进入这个反模式**。Hades 的等价机制是"完成 encounter 不受伤 = 增量奖励"，但已获得的部分被保留。
   - 来源: [I want Saros to riff off a misunderstood Hades feature — GamesRadar](https://www.gamesradar.com/games/roguelike/i-want-saros-to-riff-off-a-misunderstood-hades-feature-to-become-a-very-different-roguelike-to-returnal/)

5. **Hades 死后剧情进度 = 抗挫核心，而非奖励货币** — Hades 真正让玩家愿意"再来一次"的不是 Mirror of Night 的数值升级，而是**"每次死回 House 都有新对话 / 新关系演化"**。即"死亡推进剧情"。Saros (2026) 继承这一点 — "permanent resources making every death valuable"。DTSV 已有六纪元 lore + PI 引导者，**死亡触发 lore / 引导者对白的链路尚未系统化**。
   - 来源: [How Hades deals with frustration — Medium](https://lorgoncewas.medium.com/how-hades-deals-with-frustration-702f96bee6c9)
   - 来源: [I want Saros to riff off a misunderstood Hades feature — GamesRadar](https://www.gamesradar.com/games/roguelike/i-want-saros-to-riff-off-a-misunderstood-hades-feature-to-become-a-very-different-roguelike-to-returnal/)

6. **Kill cam = 学习信号 + 因果可识别度承载体** — 多个 2026 玩家社区帖（Delta Force / Rust / CS2）反复强调 "killcam can be a good learning opportunity"；而 Delta Force operations 模式缺 killcam 被列为社区第一负反馈。**没有死亡复盘 = 死亡因果不可识别 = 玩家归因到"unfair"**。本质上 killcam 是"v1 D 主题 #2 — 可识别因果"的具体载体。
   - 来源: [We need a killcam in operations — Delta Force Steam Discussions](https://steamcommunity.com/app/2507950/discussions/0/592886010360137618/)
   - 来源: [Implementing Instant Replays (Killcam) — Devtricks](https://vorixo.github.io/devtricks/killcam/)

7. **Marathon 后期教训：死亡惩罚必须匹配 onboarding 友好度** — Marathon (Bungie) 2026 的 ResetEra 讨论将"Path Forward"列为：扁平化死亡惩罚 + 增加 partial-loss tier。**当 onboarding 摩擦高（入场要付费、要懂 gear、要会撤离）时，0/1 死亡惩罚会放大首挫败率**。DTSV 当前 PrepareModal 设计 + Phase 24b extract-DELETE 是高摩擦 + 0/1 损失的组合，**与 Marathon 后悔点完全重合**。
   - 来源: [Marathon's Path Forward — ResetEra Discussion](https://www.resetera.com/threads/discussion-marathons-path-forward-can-a-new-approach-save-the-extraction-shooter.1509976/)
   - 来源: [Best Extraction Shooters 2026 — Insider Gaming](https://insider-gaming.com/best-extraction-shooter-games-to-play/)

8. **2026 趋势 — Insurance / Deposit 已从"小众功能"变成"genre baseline"** — Tarkov / EVE Vanguard / Arc Raiders 都在 2026 同时迭代其"部分返还"系统；不提供任何返还机制的 extraction 新作 churn rate 显著更高。**对 DTSV 而言这意味着 Phase 24b 必须在"全 sink"和"部分返还"之间二选一，不能拖到 Phase 25+**。
   - 来源: [Best Extraction Shooters 2026 — Switchblade Gaming](https://www.switchbladegaming.com/extraction-games/best-shooters-2026/)
   - 来源: [Extraction shooter — Wikipedia](https://en.wikipedia.org/wiki/Extraction_shooter)

### 对照 DTSV

**已对齐**:
- `player_stash` 持久化 ≈ EVE Vanguard "raid 前 deposit" 等价物：玩家可以选择本局**不带**某件装备 → 它就不会损失。即"风险阈值设定权"已部分前置给玩家。
- `failedRetreats` 字段 — 连败计数已埋点，可作为 streak-breaker / pity 触发器的数据基础。
- `player_death_log`（27-v2 已提议补 `cause_category` + `survived_seconds`）— 死亡复盘 UI 的数据底座已规划。

**风险/缺口**:
- **没有保险 / 部分返还** — Phase 24b 当前是"extract DELETE → 全部转点数"，死亡 = 装备 100% 归零。这与 #2/#7/#8 的 2026 genre baseline 直接冲突。
- **PrepareModal 未显式展示"本局总投资"** — 缺 #1 的"为支付的死亡"心理前置，玩家事后才意识到投入有多大 → 易归因到"unfair"。
- **没有死亡复盘 / kill cam 等价物** — `player_death_log` 是数据层，UI 层缺一个让玩家"看见死因 / 看见时间线 / 看见 chamber 路径"的回放视图。违反 #6"因果可识别度"。
- **没有 streak-breaker / pity** — `failedRetreats` 仅是 counter，连续 N 次失败后没有任何系统反馈。违反 #4 的反模式 (Returnal 风格"无内置 mercy")。
- **死亡未挂 lore / 引导者对白链** — 与 #5 (Hades) 的核心抗挫机制对不上。DTSV 有 PI 引导者、有六纪元 lore、有 `discoverFragment` 三链，但**死亡事件没有作为 lore / 对白触发器**。
- **可能存在 Returnal-style 反模式** — 任何"撤离连胜累积 bonus" / "无伤穿越 chamber 加分" / "PI 信任度首伤归零"类设计如果以"首次失误清零"实现，需要立刻审计。**目前 codebase 还未实现，但 Phase 25+ 设计时必须避开**。

### Actionable findings (优先级 P0/P1/P2)

- **P0 — 死亡复盘 UI (Phase 22 follow-up)** — 利用 27-v2 已提议的 `player_death_log.cause_category + survived_seconds + chamber_depth`，在 `src/app/game/[id]/page.js` 死亡分支加一个 "📜 死亡复盘" 弹窗，至少展示：① 死因分类（NPC/污染/Ω-段/被探针击杀/主动放弃）② 存活 N 秒 ③ chamber 路径深度 ④ 本局已获取但被销毁的 fragment 列表。**这是 #6 因果可识别度的 UI 承载体，缺它则 Phase 22 数据白埋。** 文件: `src/app/game/[id]/page.js` + 新建 `src/components/DeathRecapModal.jsx`。

- **P0 — Phase 24b 必须内置 "部分返还" tier，不能全 sink** — 在 `shop_exchange_rates` (27 P0 已规划) 同期建表时，加 `equipment_instances.insurance_tier ENUM('none','basic','premium')` + `insurance_premium_pt INT`。PrepareModal 入场前可花点数购买 basic (30% 返还概率) / premium (60% 返还概率)。死亡时按概率随机决定是否归还 stash。**这是 #2/#7/#8 的 genre baseline 对齐，拖到 Phase 25+ 会被新玩家流失数据反推回来**。文件: `scripts/phase-24b-*.sql` + `src/components/PrepareModal.jsx`（待建）+ `src/lib/server/raids.js` 死亡分支。

- **P0 — Streak-breaker / 连败 pity 机制** — `failedRetreats >= 3` 触发下一局自动 buff：① 免费 basic 保险 ② chamber 入场 NPC 密度 -20% ③ PI 引导者对白 "你看起来需要喘口气"（触发 lore 关怀分支）。**这是 #4 反模式的反向兜底，防止 tilt cascade 把中等技术玩家清出去**。注意：buff 不应叠加经济收益，只降难度 — 否则会变成"故意送死刷 buff"。文件: `src/lib/server/raids.js` (preRaidSetup) + `src/lib/constants.js` (pity 阈值)。

- **P1 — PrepareModal 显式 "本局总投资" 摘要条** — 装备购买 + 入场费 + 兑换点数损耗汇总成一个 "💸 本局承担风险：XX 点 + Y 件装备 (估值 Z 点)"。玩家点 "确认入场" 前必须看到。**这是 #1 的心理前置 — 让风险归因发生在 commit 之前**。文件: `src/components/PrepareModal.jsx`。

- **P1 — 死亡 → lore / 引导者对白触发链** — `player_death_log` 写入时同步检查触发条件：① 首次死于污染 → 解锁 fragment F09（污染源相关）② `failedRetreats == 5` → PI 引导者投递特殊对白进入 `player_notifications` ③ `failedRetreats == 10` → 解锁"耐心者"成就 + 六纪元过渡 lore 一段。**这是 #5 Hades 模型在 DTSV 的本地化实现 — 让死亡推进叙事而不只是清零经济**。文件: `src/lib/server/raids.js` 死亡分支 + 新建 `src/lib/server/deathTriggers.js`。

- **P2 — 反模式审计 (Phase 25+ 设计前置)** — 在 `docs/anti-patterns.md`（新建）中明确禁止：① 任何"连胜 buff 首伤归零"类设计 ② 任何"完美撤离 streak" 0/1 累计逻辑 ③ 任何"PI 信任度 / 残片解码进度"被单次死亡完全清零的字段。所有 Phase 25+ PR 必须 review 这条。**这是 #4 的预防性护栏，不实现是 0 成本，未来踩坑成本 >> 文档化成本**。
