## 主题 B — 元进度甜区（节奏 + 自适应难度 + 数值 vs 技能）

### 关键词
- `Hades God Mode adaptive difficulty meta progression design retention`
- `Slay the Spire unlock pacing card pool progression player retention design`
- `roguelike permanent upgrades trivialize skill too easy meta progression debate`

### 关键发现

1. **"每局是一章，不是一次重置" 是元进度的核心心理框架** — Hades 2 平均 35-40h 通真结局、约 133h 全完成，"数字看着吓人但实际不劝退，因为每局是一章而非 reset"。死亡传递双信号："你犯了错 + 你仍有进展"。这是判断元进度是否健康的定性标尺。
   - 来源: [Roguelike vs Roguelite: StS2 vs Hades 2 — Switchblade](https://www.switchbladegaming.com/strategy-games/roguelike-vs-roguelite-explained/)

2. **两条相反路线都成立，取决于"靠什么留人"** — Slay the Spire 2 把元进度**砍到最小**（Timeline/Epoch 前置且极简，之后每局完全平等），靠 build/RNG/难度阶梯留人；Hades 2 用 **25 张渐进解锁 Arcana 卡**（Grasp 上限随 Psyche 从 10 涨到 29）跨局扩展，靠"章节感"留人。没有唯一甜区，但**必须明确自己靠哪条**。
   - 来源: [Switchblade](https://www.switchbladegaming.com/strategy-games/roguelike-vs-roguelite-explained/)

3. **Hades God Mode = 渐进自平衡减负，而非一次性 buff** — 开启后受伤 -20%，每死一次 +2%，**上限 80%**；中途开启不追溯既往死亡。设计精髓：玩家一路死、一路推进，直到防御够通关，然后游戏请你调高难度，再回到边死边进——**永远不会永久失去挑战**。
   - 来源: [Hades' God Mode is an Incredible Choice — Phenixx](https://web.phenixxgaming.com/2021/02/15/hades-god-mode-is-an-incredible-choice-in-game-design/)

4. **God Mode 是 opt-in 且不锁任何内容** — "不多打伤害、房间不多掉物、最重要的是不会因此错过任何剧情"，也不锁成就。减负的政治正确性来自"不剥夺成就感 + 不惩罚选择减负的人"。三次死于 Bone Hydra 后开 God Mode 渐进通关，**仍感觉是真成就而非作弊**。
   - 来源: [Phenixx](https://web.phenixxgaming.com/2021/02/15/hades-god-mode-is-an-incredible-choice-in-game-design/)

5. **"democratize" 留存证据：Hades 把数百万会在第一周弃坑纯 roguelike 的玩家留了下来** — 纯 roguelike 流失风险集中在**第一周**。元进度的首要价值不是后期深度，而是**渡过第一周的劝退峡谷**。
   - 来源: [Switchblade](https://www.switchbladegaming.com/strategy-games/roguelike-vs-roguelite-explained/)

6. **垂直永久升级 trivialize 技能（社区强共识）** — "永久加 HP/伤害 + 保证拿到最好物品会彻底 trivialize 游戏"；批评者认为那不是在玩游戏而是"刷到够强为止，无论怎么玩都能通关，不需要学习/调整/策略"。
   - 来源: [Do you like meta progression — ResetEra](https://www.resetera.com/threads/do-you-like-meta-progression-in-your-roguelikes-roguelites.1341955/)

7. **可接受的永久升级 = "建立基线"而非"无限增长"** — 折中派："只要不是无限叠加、只是确立一个基线 power level，就是 roguelike 应该有的"。关键词是 **floor（地板/保底）≠ stockpile（可无限囤积的跳关券）**。
   - 来源: [ResetEra](https://www.resetera.com/threads/do-you-like-meta-progression-in-your-roguelikes-roguelites.1341955/)

8. **解决"太简单"的标准答案是 Heat/Ascension 式自愿加难** — "Hades 用 Heat 系统对冲进度，玩家觉得太简单可以自己调难"。StS 的 Ascension 1-20 同理：完成解锁更高难度 + 新卡/遗物。强者**自愿再挑战换更好奖励**是元进度的"上行阀门"。
   - 来源: [ResetEra](https://www.resetera.com/threads/do-you-like-meta-progression-in-your-roguelikes-roguelites.1341955/) / [Switchblade](https://www.switchbladegaming.com/strategy-games/roguelike-vs-roguelite-explained/)

9. **横向解锁也有副作用：卡池稀释** — StS2 社区抱怨"卡池随解锁扩大 → 抽到特定 synergy 卡的概率下降"。横向 growth 不是免费午餐：池子越大，**找到关键件**越难，需要加权抽取兜底。
   - 来源: [Switchblade](https://www.switchbladegaming.com/strategy-games/roguelike-vs-roguelite-explained/)

10. **"必须输 N 次才解锁好东西"是被点名的反模式** — 多个社区讨论指向：当保底/解锁被做成"人为劣化前 N 次"，玩家会觉得难度被假摔，胜利"靠攒货币不靠技术"。保底必须**被体验为玩家自己的累积兑现**，而非"游戏放弃了把奖励塞给你"。
   - 来源: [ResetEra](https://www.resetera.com/threads/do-you-like-meta-progression-in-your-roguelikes-roguelites.1341955/) / [Roguebook meta-progression 讨论](https://steamcommunity.com/app/1076200/discussions/0/3070873501568676154/)

### Actionable findings

- **P1** — **Streak-breaker 从"一次性二元触发"升级为 Hades God Mode 式渐进自平衡**：`failedRetreats` 越多减负越强（如 NPC 密度按连败次数线性递减 -10%/次、封顶 -40%），**一旦成功撤离即衰减归零**，永远不永久 trivialize；并改为 **opt-in 可见**（出勤前显示"引导减负已生效 LvN"而非静默），呼应 God Mode "不锁内容 + 不剥夺成就感"。文件: `src/lib/server/raids.js` `computeStreakBreaker`（已存在二元版）+ `src/lib/constants.js` `STREAK_BREAKER`。红线不变：只降难度不加经济收益。

- **P1** — **新增"高危出勤"自愿上行难度阀门（Heat/Ascension 等价）**：出勤前可选 modifier（+污染加速 / +NPC 密度 / -撤离窗口 / Ω-段提前），换取 **fragment 掉率 + 点数倍率**。给数值饱和老玩家"再挑战换奖励"的出口，对冲 finding #8 的"太简单"终点。与 Streak-breaker（下行）构成完整双向自适应。文件: `src/components/PrepareModal.jsx`（24b）选择器 + gamevars `heatLevel` + `pollution.js` / `pathGenerator.js` 读 heat 缩放 + `gameActions.js` extract 奖励乘子。

- **P1** — **Phase 24c legendary 必须是 horizontal build-enabler 而非纯数值 stat-stick**：在职业/装备引擎落地前定下设计约束——legendary 赋予**新机制/独特 perk/玩法变体**（横向，驱动实验），而非更大的 atk/def/hp 数字（纵向，trivialize 技能）。审计 `equipment_series`/`equipment_tiers` 现有 legendary 条目是否为纯数值堆叠；class_pt 保底兑现的 legendary 同此约束。配套：class_pt 设计成 **floor（保底地板）不是 stockpile（可无限囤的跳关券）**——余额封顶，到顶即触发不再累积（finding #7）。文件: `src/app/admin/_tabs/EquipmentTab.jsx` 审计 + `docs/economy-canon.md` 加"legendary = 横向"条款 + Phase 24c `classes` perks 白名单复核。

- **P2** — **撤离后 meta-progress 回顾屏，把"每局是一章"做实**：Phase 24b "extract DELETE 装备转点数"是每局微 wipe，若不可视化横向进展会被读成"损失"。结算屏显式展示"本局推进: 解码 +X 残片 / chamber 探索 +Y 模板 / 知识图谱 +Z 节点 / 出勤累计 N 次"，让装备清空读作"章节推进"而非"reset"（finding #1）。与 05-29-A 的 runGoal/本局评级（局内目标）互补——此处是**局外 meta 进展**。文件: 撤离结算组件 + `GameClientPage.jsx`。

- **P2** — **池子稀释兜底：in-progress 链加权抽取**：fragment/chamber 池随 phase 扩大后抽到关键件概率下降（finding #9）。扩展 05-28-C 的新手 boost 思路到**全玩家**：若持有某残片 partial（如 F06 decode_level 1-2），提升其后继（F07）发现权重；chamber 路径生成偏向玩家未访问模板。文件: `src/lib/server/fragments.js` `discoverFragment` weightFn + `pathGenerator.js`。

- **P2** — **God-Mode 式 opt-in"引导出勤模式"（事前铺垫，非事后兜底）**：Streak-breaker 是连败 3 次后才触发的反应式减负，但 finding #5 指出劝退峡谷在**第一周**。补一个出勤 < N 次可主动开启的引导模式（渐进减负 + 不锁 lore/成就/残片），渡过新手墙，与 Streak-breaker（反应式）形成"事前 + 事后"双层。文件: `PrepareModal.jsx` + `profiles` 出勤计数读取 + `raids.js`。
