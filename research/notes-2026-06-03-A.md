### 玩家抱怨 Top-5（社区高频）

1. **信息密度过载**（Marathon 案例）— 合约 / 班配 / Codex / 多队列 / 任务层级一次性砸给新人,UI 难解析,挫败感"在玩法亮点显现前就劝退"
2. **死亡看不到敌人**（Marathon、Tarkov 通病）— "突然死掉不知道被谁打"撕裂社区,玩家不是输给操作而是输给信息不对称
3. **Wipe / 反向进度**(Tarkov)— 把 wipe 称作"伪装成维护的惩罚"; Hardcore Wipe 上来禁掉 9/11 张地图 + 飞市关闭 + 修理费翻倍,口碑当天崩
4. **PvP vs 休闲撕裂**（Arena Breakout / Marathon 全员）— 50% Tarkov 玩家想要纯 PvE; "在打 NPC 时被人偷"是萌新流失第一因
5. **失败不解释**（Marathon）— souls-like 哲学但没有 souls 的反馈密度,玩家死了"得不到为什么死的信息",纯被惩罚感

### 普遍称赞的"减负"机制

- **PvE/PvP-Lite 阶梯**(Marathon Season 2、Vaultbreakers 新模式)— 让萌新先玩 PvE,熟练后再进 PvP
- **结构化任务/合约**(Marathon Contracts、ARC Raiders)— 给一局明确目标,不再"裸地图无方向"
- **难度降梯**(Bungie 已部署: 减少 EMP 手雷 / 加资源 / 降 AI 难度 / 加导航)— 上线后改 onboarding,不固执"硬核哲学"
- **代际共存**(ARC Raiders)— 老带新同一 lobby 都有事干,而不是新人"陪练"

### Actionable findings（按 P0/P1 优先级）

1. **[P0] 加入"萌新保护"raid 标签**（首 3 局或前 24h）— 强制 PvE only / 探针遭遇率从 8% → 0% / 撤离失败返还 50% 点数。靠 `rooms.gametype` 新增 `tutorial` 枚举 + 服务端 join 时按 `profiles.created_at` 判定。**痛点对应**: 萌新流失第一因 + Bungie 已被迫这样改。
2. **[P0] Death post-mortem 页面**（复用 `player_death_log`）— 死亡返回大厅前显示一页：「你死于 NPC=X(lvl=hard) / 探针抢走 Y 残片 / 最后 inventory 价值 Z 点」。**痛点对应**: Marathon 最大社区怨气 = "不知道为什么死"。改动小（表已存在），UI 加一个 modal。
3. **[P0] Loadout preset**（仅入场购买）— 在 catalog 页支持「保存当前购买组合为 preset_1/2/3」，下次一键填入。**痛点对应**: 入场摩擦 + 老玩家重复操作疲劳。SQL 加一张 `player_loadouts(player_id, slot, items_json)` 即可。
4. **[P1] 信息密度分层**— 首次进入大厅时只暴露「房间列表 + catalog」，把 lore / class_pt / 探针解释折叠到「教学手册」二级页。**痛点对应**: Marathon 翻车直接原因。改动：`src/app/rooms/page.js` + `localStorage('seen_tutorial')` 旗标。
5. **[P1] 撤离失败"软底"机制**— 死亡时按本局获得点数的 X%（建议 10-15%）返还 high_equip_pt（不是 class_pt），缓解"裸打几小时全没"的尾段挫败。**痛点对应**: Tarkov "伪装成惩罚"指控。注意：保留 class_pt 不奖死亡的硬核张力。
6. **[P1] In-game codex 化 lore**— F01-F15 不要全堆 README，做成大厅"档案库"按解锁条件渐进暴露（参考 Hades codex）。**痛点对应**: 信息密度 + lore 容忍度。本主题不深入，留给 Theme C。
7. **[P2] 探针遭遇可读化**— 8% 抢残片时给被抢方一条 toast "🛰 探针 player=X 在 map=Y 抢走了你的残片 F-12"，让异步 PvP 有"留痕"而不是"凭空消失"。**痛点对应**: 失败不解释。**复用 Theme E 留物机制**，先做最薄一层。
