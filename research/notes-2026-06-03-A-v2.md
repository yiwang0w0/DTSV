## 主题 A — 三个未被今日 A note 覆盖的新角度

### 搜索结果摘要

- **[Why Do Most Extraction Shooters Fail? — GAMES.GG](https://games.gg/news/why-most-studios-struggle-to-make-a-successful-extraction-shooter/)** — 核心论点: "loss 必须 matter,每个决策要有真实后果"; 反例 CoD DMZ "死了只损失一把枪和几分钟" → stakes 几近于零 → 玩家觉得**无聊**(与"惩罚过重"相反的另一端失败)。
- **[Marathon Rook System Explained — carrylord.com](https://carrylord.com/marathon/rook-system-explained/)** — Rook 直接绕开 "death spiral": **零负重出生(无装备可丢)+ 拾取即归己 + 晚 10-15 分钟入场 + PvE 敌人无视 Rook + 仅单人**;明确针对 "month 3-8 流失窗口" 设计 fallback 进度。
- **[Players Warm Up / PvE Co-op retention — LevelUpTalk & ResetEra 讨论串](https://leveluptalk.com/news/extraction-shooter-genre-2023/)** — 加 PvE/Co-op 模式**不蚕食** PvP 玩家池,反而救回"第一个月后就退坑的休闲玩家";Tarkov 数据 **50% 受众想要 no-sweat 玩法**(非仅新手期,而是长期偏好)。

### 关键概念: "death spiral"(齿轮式负债螺旋)

> 原文: "你输掉一场 → 丢掉装备 → 现在只能带便宜残缺的配装,去同样危险的地图,对上保住好装备的玩家。" 挣扎玩家越陷越深,最终弃坑。研究称这是 extraction 流失的**头号原因(超过单纯难度)**。

**DTSV 对照(重要)**: DTSV 的 4 类点数 + catalog 入场购买(Phase 24b)是 **re-buy 模型**,结构上已破除"持久装备 death spiral" —— 死亡丢的是本局 inventory,不是永久变穷的装备链。**但 re-buy 模型有一个未被现有 finding 覆盖的失败边: 点数破产**。若玩家把可入场点数打到低于最低门槛(裸打几局全失 + 没有撤离收入),就会重现"只能带最便宜配装反复送"的 spiral —— 只是货币从"装备"换成"点数"。25l NewbieProtection / 28-D Streak-breaker / 今日 A note soft-floor 都是**死亡返还**(事后补),没有一个是**入场地板**(事前兜底)。

### Actionable findings(均为今日 A note 之外的新条目)

1. **[P1] 点数破产软底 / 入场地板(bankruptcy floor)** — 与所有现有"死亡返还"减负正交。当玩家任一可入场路径的点数全部低于最低入场门槛时,发放一笔**受限 `low_equip_pt`**(仅够 basic 入场,标记不可兑换/不可转换,防刷)。这是 re-buy 模型的兜底,堵住"货币换成点数后的 death spiral"。文件: `gameActions.js` joinRoom 入场校验前 + `constants.js` `BANKRUPTCY_FLOOR` 块(ENABLED 预埋)。红线(economy-canon §6.1): 救济点数受限且不计入 `v_weekly_stash_inflation` faucet 预算,class_pt 永不发放。
2. **[P1] 永久纯-PvE 房型(区别于 tutorial raid)** — Tarkov 50% 长期想要 no-sweat;DTSV 异步架构分裂成本低(本就不是同屏 PvP)。`rooms.gametype` 加永久 `pve_only` 枚举: 探针遭遇率 0%、保留搜寻/撤离/lore/点数经济,但产出点数打折(防 PvE 房成最优 farm 路径)。与 06-03-A 的限时 tutorial raid 互补: 一个是萌新过渡,一个是休闲玩家永久家。文件: `roomState.js` gametype 校验 + `probes.js` tryEncounterProbe 读 gametype 短路 + 入场 UI 标签。
3. **[P1] 死亡惩罚"双向校准"护栏(防滑向 DMZ 无聊端)** — GAMES.GG 明确: 惩罚过低(DMZ)和过重(Tarkov)是**两端都失败**。DTSV 减负 finding 已堆 ≥6 条,缺一个"loss 仍 matter"的量化护栏。建议 healthcheck 加 **M_death EV 指标**: 计算"成功撤离 EV − 阵亡 EV"差值,叠加所有减负机制(25l + 28-D + 25h 保险 + soft-floor + 本条破产地板)后该差值若跌破阈值(死亡几乎无损) → critical 告警。把"减负不能减到死亡无意义"写进 `docs/economy-canon.md`。这是对整条减负 finding 链的安全带。
