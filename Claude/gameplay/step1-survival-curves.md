## 1. ①掉血曲线

**d = 4 HP / 次搜索,定值,无方差,不随时间递增。**

- **为什么定值不加方差**:整套阈值线索的锚点是「**还能撑几拍**」(§4)。掉血一旦有方差,玩家**算不出余量**,阈值线索就从"信息通道"退化成"随机噪音"。且 Kanata 的意图经我翻译、🧭 采纳的形状是「**掉血是确定的**·药的保底是确定的·只有余量薄厚不确定」——**不确定性全部放在药那一侧**,这是刻意的分工。
- **为什么不递增(伤势累积)**:递增会压缩 N,直接吃掉 M 的余量(§3 已经只有 1.9×);且让"还能撑几拍"变成非线性,玩家更难判断。**留作后段(step2+)的强度杠杆**,step1 不用。
- **hp 基线**:100(`createPlayerState`)⟹ 无药时 **25 拍见底**。
- **扩容件(+15 maxHp)= +3.75 拍**。在这条曲线下它是**实打实的续命**(不再是 boss 曲线里那个抽象的 +30hp 分量),值得作为 step1 的重要拾取。

## 2. ②药品投放曲线

| 来源 | 物品 | 量 | 作用 |
|---|---|---|---|
| **周期保底** | 修补剂(heal30)| **每 16 搜 1 瓶** | **护住最坏运气**(唯一能护的机制·§3)|
| **权重掉落** | 修补剂(heal30)| **6% / 搜** | 抬中位·造波动(张力来源)|
| 合成 | 修补剂/大补剂 | 按配方 | 玩家主动兑换 |

- **大补剂(heal60)不进 step1 基础掉落表** —— 留给合成与后段。理由:上表两项已经过 harness 实测定标(§3 的 N 与 §5 的档位命中率都是按"仅修补剂"算的),塞进大补剂会让实测数偏移;要加须重跑。
- **收支**:`heal/搜 = 30/16 + 0.06×30 = 1.875 + 1.8 = 3.675` vs `drain 4` ⟹ **净 −0.325/搜**。
  正是我推荐、🧭 认同的「**净收支恰好为负一点点**」:有一口钟在走、卡得越久越薄,但正常推进(20-30 搜)碰不到危险。

## 3. ⚠ 载重前提:**必须是周期保底,不能是"每关一次"**

现 `event_deck.guaranteed` 是**每关一次**;而 step1 的卡关场景是**在同一关里无限搜**。两种机制下 N 差一倍:

| 保底机制 | N 最坏 | N 中位 | vs M=21 |
|---|---|---|---|
| **(A) 周期保底**(每 16 搜)| **40** | 108 | **1.9×** ✓ |
| (B) 每关一次(现机制)| **25~32** | 40~47 | **1.2~1.5×** ✗ 太薄 |

**且权重掉落救不了最坏情况**(harness 实测·d=4·无保底):

| p(权重掉药率)| N 最坏 | N 中位 |
|---|---|---|
| 0.06 | **25** | 40 |
| 0.08 | **25** | 48 |
| 0.10 | **25** | 70 |

⟹ **p 从 6% 拉到 10%,最坏 N 纹丝不动(25)**,只有中位在涨。**因为最坏情况的定义就是"连续不掉"——概率性投放对它无效,只有保底能护。** 这与我在 seq1 用 guaranteed 兜解锁链是同一条原理。

**⟹ 给 🔧 的机制请求**:step1 需要「**每 N 次合格搜索必掉 1 瓶**」的周期保底(计数器随关卡重置与否需定)。**没有它,M<N 的余量掉到 1.2-1.5×,最坏运气的玩家会在诱饵刚讲到最直白那一档时死掉** —— 那正是 🧭 最初担心的"卡住退化成慢性死亡",只不过根因不是时钟耦合,而是**保底机制的粒度**。

## 4. 阈值锚点(替代 📖 N7 §3.1 的百分比占位)

```
有效剩余拍数 beats = (当前 hp + 药瓶数 × 30) / d
档1 ≤ 20 拍   档2 ≤ 12 拍   档3 ≤ 4 拍   恢复 = 回升一档
```

- **为什么带药瓶数**:能区分「40 血 + 3 瓶 = 安全」vs「40 血 + 0 瓶 = 要命」——**血量百分比分不出这两个**,而这两种处境该说的话完全不同。
- **runtime 可精确算**(不需预测未来掉药),且是「余量薄厚」的字面实现。
- 📖 的四档措辞**一字不用改**;档3「撑不住几下了」在新锚点下是**字面真话**(≤4 拍 = 真的只剩几下)。

## 5. 实测:正常游玩的紧迫感

harness 校准(d=4 · G=16 · p=0.06 · 前 30 搜内至少触发一次的概率):

| 档 | 触发率 | 读作 |
|---|---|---|
| 档1(发涩)| **91%** | 几乎每局都尝到 |
| 档2(慢下来·在响)| **56%** | 过半的局真紧张过 |
| 档3(撑不住几下了)| **18%** | 偶尔真吓一跳 |

**且正常推进不死**:最坏 1% 也要到第 40 搜才死,而 step1 约 20-30 搜完成。
⟹ 同时满足 Kanata 的两条:「**不打算让玩家死**」+「**始终感觉薄**」。

> 📌 首稿教训(自曝):我第一版给 d=3/每12搜保底,N=144 看着很安全 —— 但 📖 会签时套它的 hp 档位发现**正常玩家一次都听不到线索**。我起初以为是锚点问题,改成拍数锚点后实测**仍 0% 触发** ⟹ 根因是**曲线太安全**,"求生"整个是装饰性的。收紧到 d=4 才让那口钟真的走起来。**"安全"不等于"对"。**

## 5.1 L(step1 长度)敏感度 —— L 由"想要什么紧迫感"倒推(🧭 要求)

d=4 · G=16 · p=0.06,前 L 搜内各档触发率 + 死亡率:

| L | 档1 | 档2 | 档3 | **死亡率** | 读作 |
|---|---|---|---|---|---|
| 20 | 88% | 39% | 0% | **0%** | 太短:档3 永不响,没有"真吓一跳" |
| **30** | **92%** | **56%** | **17%** | **0%** | **推荐**:三档齐全 · 零死亡 |
| 50 | 94% | 65% | 31% | **25%** ⚠ | **越线**:四分之一玩家死 ⇒ 违 Kanata「不打算让玩家死」|

- **⟹ L 的硬上限 ≈ 40 搜**(50 已经 25% 死亡)。**推荐 L = 30**。
- L 一旦定案(依赖 📖 的 seq1-2 改造),回本表取对应行即可,不必返工。

**掉血方差(🧭 倾向"要但要小")= 采纳 ±1**(均匀 {3,4,5},期望仍 4):
| | L=30 档1 | 档2 | 档3 | 死亡率 |
|---|---|---|---|---|
| 定值 ±0 | 92% | **56%** | 17% | 0% |
| 方差 ±1 | 91% | **44%** | 17% | 0% |
- ⚠ **方差不是免费的**:它让档2 触发率从 56% 掉到 44%(方差让一部分局"运气好、掉得慢",反而更少探到中档)。
- 结论:**采纳 ±1**(达到"防精确数拍"的目的,期望不变),**代价是中档张力略降**;~~若想把 44% 补回 56%,把保底 G 从 16 收到 15 即可~~ ⚠ **这半句已被实测证伪,别照做** —— G 越小档2 触发率**越低**(收 G 是往反方向走),真凶是档2 窗口太窄,见 **§5.6**。

## 5.2 ⚠ 动态诱饵档(补 🧭 指出的静态不等式洞)+ 我加的一条

**🧭 的洞成立**:我的 N 是**从满血算起**的;而卡住可发生在任何血量。玩家 35 血 0 药卡住时实际只剩 ~9 拍,而诱饵档3 要到第 21 拍 ⟹ **他这一局跑不赢**。

**🧭 裁定的修法(我落)**:
```
tier_by_margin(beats):  ≤4 → 档3 ;  ≤12 → 档2 ;  ≤20 → 档1 ;  else 无
tier_by_exposure(n):    n≥5 → 档3 ;  n=3-4 → 档2 ;  n=1-2 → 档1
诱饵档 = max( tier_by_exposure , tier_by_margin )      // 只加速,不降级
```
仅对**承重 key**(move_btn / hp_bar)生效。

**⚠ 我加的一条(不加则这条修法仍会漏)**:光换档不够,**还要强制发**。
因为诱饵的**发射间隔**仍是每 M 拍一条(承重 5→3→2)。玩家余量掉到 ≤4 拍时只剩 4 次搜索,而下一次发射可能要等 5 拍 ⟹ **他到死都没看到那句档3**。
⟹ **余量跨档时必须边沿强制发一条(绕过 M 间隔)**,与 📖 N7 §2.2 自己立的「**跨档边沿必发**」同一条原理(它对阈值线索已经这么做了,这里只是把同一原理用到承重 key 的诱饵上)。
**⟹ 完整规则 = 档位取 max + 余量跨档边沿强制发。** 这样保证才真从"统计上跑得赢"变成"他真快死时一定跑得赢"。

### 5.2.1 📖 会签结果:承重 key 诱饵**按触发因分两组**(`b7c0f10`)

📖 核过后确认三档**扛不住被提前跳档**:档2「**这一段翻遍了**」/ 档3「**再翻也还是这些**」都对**搜索次数做了事实断言**,才翻 5 拍就说 = 假陈述。已分两组:

| 档 | 曝光驱动(翻很久还没走)| **余量驱动**(没翻几下但快没了)|
|---|---|---|
| 1 | 出口还开着。这一段没别的事了。 | 同 |
| 2 | 这一段翻遍了。出口一直在那儿。 | **出口还开着。这一段耗不起了。** |
| 3 | 再翻也还是这些。出口，一直开着。 | **出口一直开着。你耗在这儿了。** |

**⚠ 实现约束(📖 提 · 写进给 🔧 的规格)**:余量组**刻意不复述濒死**——≤4 拍时 hp 档3「撑不住几下了。」**同拍齐发**,两条都喊"你要死了"是浪费一拍。**余量组的职责是把出口指成出路,不是再报一次血。** ⟹ 实现时**两条都要发、不得互相抑制、也不得合并**(它们是互补的两个信息:一条报身体、一条指出路)。

⟹ **完整规则(终版)**:
```
档位 = max(tier_by_exposure, tier_by_margin)
文案组 = 触发因(曝光 → 曝光组 / 余量 → 余量组)
余量跨档 → 边沿强制发(绕过 M 间隔)
```

## 5.3 恢复档的两因(📖 发现的边界 · 我给实现口径)

📖 指出:`beats` 公式里**捡到一瓶药也会让档位回升,但身体没好** —— 此时发「响声轻了些。」是**假陈述**。它已把恢复档拆成两因,并问我能否给出区分信号。

**答:能,零成本。** 算 `beats` 时 hp 与药瓶数都在手上,取前后差即可:
```
cause = (hp 升)      → 'healed'   → 「响声轻了些。」
        (药瓶数升 且 hp 未升) → 'stocked'  → 「手里多了一瓶。撑得久一点了。」
        (两者皆升)   → 'healed'  (身体确实好了,优先报身体)
```
⟹ 恢复事件下发时**带 `cause` 字段**(给 🔧 的实现口径)。📖 两条文案都能用,不必退到中性写法。

## 5.4 扩容件 = **时间件**,且必须稀有(🧭 定性 + 我定量)

- 🧭 的语义订正很对:+15 maxHp 在本锚点下 = **+3.75 拍**,它买的是**时间**,不是"更耐打"。**📖 写它时该写"多撑几步"而不是"更硬"。**
- **必须稀有**:时间是这条曲线唯一的货币,给多了整口钟就停了。
- **定量**:**不进 step1 基础掉落表**,只走**合成**(管段×1 + 芯子×1)。两种材料都要靠权重掉落攒 ⟹ 天然稀有,且是玩家**主动用两次搜索换 3.75 拍**的决策,而不是白捡。若日后要放进掉落表,建议 ≤1%/搜。

## 5.5 `loadout_panel` 该换余量框架 —— 且 B4 有一件可以救回来

📖 问:N3 的 `loadout_panel` nar_line「这一件算在身上了。**比刚进来时结实了一点**。」是**耐打框架**;若扩容成为主要/唯一升级路径就该改成余量框架。

**答:该改,而且理由比"扩容变主要"更强 —— 在 step1 里它本来就是唯一碰得到那口钟的升级。**
- step1 的主循环是**搜索→掉血→找药**,`atk/def` 只影响战斗,**对掉血时钟毫无作用**;而 `maxHp` 直接买拍数。
- 加上加力/加防**当前还是哑的**(§6.1,待 🔧)⟹ step1 里**唯一真实的升级就是扩容件**。
- ⟹ 「结实/耐打」在 step1 是**错误的仪表**(同"血量百分比是错误的仪表"一个道理):它描述的是抗打击,而玩家实际买到的是**时间**。建议改**余量框架**(📖 的「比刚进来时多点底」方向对)。

**⚠ 但有个前提要 🧭 定**:`loadout_panel` 是 **B4 三件之一,随 seq4/seq5 冻结了**,它现在根本不触发。
⟹ **我提一个 B4 的救回方案(交 🧭 裁)**:B4 原本挂在「seq4 crafting 兑现」那一刻,那个挂靠点随旧结构没了 —— **但 step1 有一个天然等价的瞬间:玩家第一次把管段+芯子合成出扩容件**。那正是"**搜刮变时间**"的兑现拍,和 B4 设计意图(后段披露绑准备度兑现)完全同构。
⟹ 建议 **`loadout_panel` 重锚到 step1 首次合成**,文案走余量框架。这样 B4 三件里至少**救回一件**,且它落在新结构真正有兑现感的那一拍上。`prep_readout`/`convergence_preview` 仍随 boss 冻结。

## 5.6 ⚠ G 是错的杠杆(🧭 指令方向相反)· 真凶是档2 窗口太窄

> ⚠ **本节的具体数字是旧口径**(仅搜索扣血)。**两个结论仍然有效**:①**G 的方向**(G 越小 = 档2 触发率越低)—— 新口径下同向(G=12→56% · G=10→48%,§5.13);②**档2 阈 ≤12** —— 已批准且现行(harness `T2=12`)。
> **失效的只有**:本节表内的百分比、以及「G 保持 16」这个定案值(新口径推荐 **G=10**,见 §5.13/§5.16)。

🧭 裁「方差 ±1 + G 从 16 收到 15 补回中档张力」。**实测方向相反**:

| G(方差±1)| L=30 档2 |
|---|---|
| 14 | 26% |
| 15 | 33% |
| **16** | **44%** |
| 18 | 47% |
| 20 | 47%(但 L=50 死亡率升到 30%)|

**G 越小 = 保底越勤 = 药越多 = 余量越厚 = 越少探到档2。** 收 G 是往反方向走;而放大 G 只能换回 3 点,还抬死亡率。**G 买不回这 11 点。**

**真凶(诊断出来了)**:档2 的**可观测窗口太窄**。0 药时 档2(≤10 拍)= `hp ≤ 40`,而玩家 `hp < 35` 就喝药 ⟹ 窗口只有 **5 HP ≈ 1 次搜索宽**;方差一抖就**跳过去了**。**不是曲线变安全,是这一档"测不到"。**

**正解 = 放宽档2 阈,不动曲线**:

| 档2阈 | 0 药时 hp | 窗口 | L=30 档2 | 死亡率 |
|---|---|---|---|---|
| ≤10 拍 | ≤40 | 5 HP | 43% | 0% |
| **≤12 拍** | **≤48** | **13 HP** | **59%** ✓ | 0-1% |
| ≤13 拍 | ≤52 | 17 HP | 62% | 0% |

⟹ **定案:方差 ±1 保留 · G 保持 16 · 档2 阈 ≤10 → ≤12 拍**。档2 回到 **59%**(超过原 55-57% 目标),档1 90% / 档3 16% / 死亡 0-1% 全部不动。
**通用教训**:阈值边界与"玩家自动用药阈"贴太近时,那一档会因为窗口窄而**测不出来**——调档位比调曲线便宜得多。
> 📖 注:档2 现在在 `hp≤48`(而非 40)触发,比原设计**略早**。文案「动作慢下来了。接缝在响。」在 48 血说仍然成立。

## 5.7 L=30 的真实时长(第二口钟要的数)

⚠ **harness 只数拍不数秒**,下面是按 🎨 已公布的编舞时长**估算**,**权威 per-beat 数在 🎨 手上**:
- 单次搜索节拍 ≈ 填充 1000ms + 迁移 900ms(doc 10 §2.4)+ 读一行 nar(2-4s)+ 决策(1-3s)≈ **5-9 秒**
- L=30 搜 ≈ **3-4.5 分钟**;+ 用药动作(实测均 5-8 次 × ~3s)≈ 20-25s;+ step0 开场与解锁级联阅读 ≈ 1-2 分钟
- ⟹ **step1 全程 ≈ 5-8 分钟**(单次坐下轻松打完)

⟹ 对死区(第二口钟)的含义:**step1 在一个日循环内完成毫无压力**,L=30 不会被死区截断。**但这只在"玩家不卡关"时成立** —— 卡住的玩家可以搜 100+ 拍(15+ 分钟),那才是会撞上死区的人。

## 5.16 🔴🔴 结构级发现:step1 有**两个制度**,选哪个不是调参是定性(修正我自己 §5.13 的推荐理由)

⟹ **搜索经济负责"惊险但活得下来",死区负责"必须回去"**,各司一职。这比"3% 可接受"硬得多。
